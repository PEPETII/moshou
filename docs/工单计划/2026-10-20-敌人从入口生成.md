# 敌人应从入口生成，而不是开战瞬间铺在路径中段

## 任务目标

点「开战」之后，敌人从入口（路程 `s ≈ 0`，入口格外的画外一格）逐个生成，再沿路径走进来。
开战当帧不得把一批敌人直接摆到路径中段。

## 当前问题 / 背景

玩家反馈：点「开战」后一瞬间，路径上就出现了一批敌人，而不是从入口走进来。

定位结果：`BattleDirector.begin()` 里的 `prefill()` 会在开战当帧生成 12 只敌人，
再按 `s = prefillStart × 72 + i × prefillSpacing`（1.5 格起、每 80px 一只）改写里程：

```
开战瞬间实测：12 只，s = 115 / 194 / 275 / 354 …（最远已过拐角进入下半段）
```

即：敌人不是"走"进来的，而是被直接摆到了路径中段。这一段是工单 04 为"让塔第一眼就有目标"
加的预铺，与玩家期望的"从入口出怪"冲突。

对照：普通刷怪路径 `Enemy.reset → s = random × startSpread`（0~20px），
`PathTrack` 的入口已向画外延伸一格（`extendEntry`），所以从 `s≈0` 生成的敌人天然是从画外走进来的。

## 涉及文件

- `js/core/spawner.js`：删除 `prefill()` 与 `begin()` 里的调用
- `js/config/glyph-battle.js`：删除 `SPAWN.prefillCount / prefillStart / prefillSpacing`
- `js/core/waves.js`：注释同步；开战时收掉开场演出（见下）
- `tests/test-path-track.js`：把"预铺 12 只"的断言改为"开战当帧为空、随后从入口生成"
- `tests/test-spawn-entry.js`（新增）：生成时机、生成位置、开战收演出三条契约
- `package.json`：新增 `test:spawn` 并串入 `npm test`

## 实施步骤

1. `BattleDirector.begin` 只保留计时与计数重置，不再调用 `prefill`；删除 `prefill` 方法。
2. 删除 `SPAWN` 里三项预铺配置，并在注释里写明"所有敌人都从入口生成，不在路径中段预铺"。
3. `Game.prototype.beginBattle` 先 `inkTrailAnimation.stop()` 再开战：开场演出只属于开战前，
   否则玩家快速点开战时，未盖章的塔卡会保持 `opacity: 0` 且 `pointer-events: none`（实测 11/12 张不可点）。
4. 更新 `test-path-track` 的预铺断言；新增 `test-spawn-entry`：
   - 未开战 10 秒：0 次刷怪、坚守计时不动；
   - 开战当帧：0 只；0.5 秒后全部敌人 `s ≤ startSpread`，且调度器没有调用 `syncPosition` 改写里程；
   - `beginBattle` 会收掉演出，塔卡恢复。
5. 无头浏览器截图对比开战瞬间、0.6 秒、2 秒三个时刻。

## 风险与注意事项

- **开局第一眼不再有目标**：首只敌人在开战后 `1 / rate` 秒出现（潮 0.15s、常 0.29s、稀 0.63s），
  到达中段塔位需要几秒；这是"从入口走进来"的必然代价。
- 塔防与征服共用 `BattleDirector`，两模式同时生效；征服的环形路径入口同样在 `s = 0`。
- 预铺配置被删除后，任何仍读 `CONFIG.SPAWN.prefillCount` 的代码都会拿到 `undefined`，
  必须同步清理测试与文档，避免"循环 0 次静默不报错"。
- 不改敌人速度、密度、坚守时长等数值，平衡口径不变。

## 验收标准

1. 点「开战」当帧 `game.enemies.length === 0`，路径上没有突然出现的一批敌人。
2. 开战后 0.6 秒：敌人出现在入口画外附近（世界坐标 `x ≈ -30 ~ 0`）；2 秒后队列在入口格内沿路前进。
3. 所有敌人都从 `s ≈ 0` 起步，没有任何敌人凭空出现在路径中段。
4. 开战瞬间 12 张塔卡全部可见、可拖放。
5. `npm test` 全绿（含 `test:spawn`、`test:path`、行数检查）。
6. 留开战瞬间的修复前后对照截图。
