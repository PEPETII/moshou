# Phase 1 工单：入口与样式结构治理

## 任务目标

降低 `index.html` 与 `css/style.css` 的复杂度，使页面入口、页面结构、组件样式和视觉效果各自有明确归属。

## 前置条件

必须先完成 Phase 0，并拥有：
- 当前行数表；
- DOM 依赖表；
- CSS/JS 依赖表；
- smoke test 基线。

## 当前问题

当前 `index.html` 同时承担页面结构、资源加载和内联样式；`css/style.css` 也集中承载大量不同职责。继续增加菜单、HUD、征服模式 UI 或新弹窗时，维护成本会快速增长。

## 目标结构

```text
css/
├─ base/
│  ├─ tokens.css
│  ├─ reset.css
│  └─ layout.css
├─ components/
│  ├─ buttons.css
│  ├─ modal.css
│  └─ hud.css
├─ screens/
│  ├─ menu.css
│  ├─ game.css
│  └─ conquest.css
└─ effects/
   └─ ink.css
```

`index.html` 继续保留唯一页面入口。

## 实施步骤

### 1. 提取 index.html 内联样式

先按“原样迁移”原则：
- 不改选择器；
- 不改颜色；
- 不改尺寸；
- 不改 DOM；
- 不做视觉优化。

提取后先验证，再进行 CSS 分类。

### 2. 拆分 style.css

按职责迁移，而不是按文件大小平均切。

推荐顺序：
1. tokens/reset；
2. 页面 layout；
3. buttons/modal/HUD；
4. 主菜单；
5. 游戏画面相关；
6. conquest；
7. 水墨和动画效果。

每移动一组样式都进行一次视觉回归。

### 3. 控制 CSS 依赖顺序

在 `index.html` 明确从基础到具体加载：

```text
tokens → reset → layout → components → screens → effects
```

禁止依赖偶然覆盖。

### 4. 清理重复规则

只有在确认 computed style 不变时才允许合并重复规则。

本工单不进行设计改版。

### 5. 缩减 index.html 职责

最终应主要保留：
- meta；
- 字体/样式引用；
- 页面结构；
- Canvas；
- 必要模板节点；
- JS 资源引用。

不要为了减少 HTML 行数而把静态 DOM 全部改为 JS 动态生成。

## 重点回归

- 主菜单布局；
- 游戏 HUD；
- 模态框；
- 塔详情；
- 关卡选择；
- 征服模式；
- 移动端/窄屏已有行为；
- 字体加载失败时的降级；
- 水墨效果层级和 z-index。

## 风险

- CSS 拆分后加载顺序改变可能造成覆盖关系变化。
- 相同选择器可能分散在多个位置。
- 内联样式优先级高，迁出后可能暴露旧冲突。
- JS 可能依赖 class 名称或通过 style 检查状态。

## 验收标准

- [ ] `index.html` 不再包含大段内联 CSS。
- [ ] 样式按职责分类。
- [ ] 不改 DOM ID/class 契约。
- [ ] 不发生视觉回归。
- [ ] 页面功能无行为变化。
- [ ] 新增 CSS 文件均满足 600 行规则。
- [ ] README 中结构说明同步更新。
- [ ] 生成本阶段完成报告。
