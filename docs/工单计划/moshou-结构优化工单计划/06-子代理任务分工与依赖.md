# 结构优化子代理任务分工与依赖

## 1. 任务定位

本文件是 `00-项目结构优化总工单.md` 的执行编排，不替代 Phase 0～4 工单。目标是把结构优化拆成可验证、可回滚、写入边界不重叠的子代理任务。

任务拓扑：

```text
真实仓库与工单
  → Phase 0 并行审计
  → Phase 0 基线整合门禁
  → Phase 1 HTML/CSS
  → Phase 2 JavaScript（按 config → tower → ui → game → enemy → conquest/data 串行）
  → Phase 3 测试/工具/文档
  → Phase 4 扩展架构准备
  → 每阶段测试、完成报告与回滚点
```

本轮默认不做：玩法和数值调整、视觉改版、ES Modules 全量迁移、构建工具引入、分支/提交/推送/部署。

- **职责**：完成 Phase 0 工单的正式审计和基线文档。
- **输入**：`01-结构审计与依赖基线.md`；当前 `index.html`、`css/**/*.css`、`js/**/*.js`、根目录测试/工具、`package.json`、`README.md`、`AGENTS.md`、现有架构和测试报告。
- **输出**：
  - `docs/architecture/current-structure.md`
  - `docs/architecture/script-dependency-map.md`
  - `docs/architecture/refactor-boundaries.md`
  - `docs/test-results/structure-refactor-baseline.md`
  - `docs/完成报告/2026-09-16-结构审计与依赖基线.md`
- **资源**：PowerShell、`rg` 或等价文件扫描、Node.js、已有 Playwright 依赖；不需要新增依赖。
- **依赖**：无；但它是后续写入阶段的硬门禁。
- **写入边界**：仅上述 5 个文档产物；不改业务代码、配置、入口脚本顺序或文件位置。
- **验收证据**：完整文件/行数表、真实 script 顺序、关键全局提供/依赖表、责任边界表；`node test-balance.js` 和 `node test-fusion-recipes.js` 的退出码；可执行的浏览器 smoke 结果或未执行原因。

### P0-B：HTML/CSS 依赖审计

- **职责**：为 Phase 1 提供独立的入口、DOM、样式和视觉回归风险清单。
- **输入**：`index.html`、`css/style.css`、所有直接操作 DOM/class/style 的 JS、Phase 1 工单。
- **输出**：返回主代理的只读审计报告；不直接创建正式架构文档，避免与 P0-A 发生写入冲突。
- **资源**：文本搜索、浏览器 DOM/CSS 检查能力（若环境可用）。
- **依赖**：无，可与 P0-A/P0-C/P0-D 并行。
- **重点**：内联 `<style>`、行内 style、DOM ID/class 契约、computed style 和 z-index 风险、CSS 职责分组、迁移批次。
- **验收证据**：每条关键结论附源文件和行号；明确已确认、推断和未验证；给出 Phase 1 的最小回滚点。

### P0-C：JavaScript 边界审计

- **资源**：文本搜索、行数统计、现有测试脚本；不需要新增依赖。

- **输入**：P0-A 的 5 个文档产物、P0-B～P0-D 的审计报告、当前仓库状态。
- **输出**：确认 Phase 0 是否通过；必要时只修正文档事实，不改代码；列出 Phase 1 的明确输入和未决风险。

- **依赖**：P0-A～P0-D 全部返回。
- **验收标准**：没有仅凭旧报告的关键结论；测试失败保留原始错误；工作区无业务代码变化；所有后续代理能按文件和行号定位依据。

## 4. 依赖和并行规则

1. **可并行组**：P0-A、P0-B、P0-C、P0-D 只读审计/基线工作可并行；P0-A 是唯一允许写入 Phase 0 正式产物的代理。
2. **Phase 0 门禁**：P0-E 未确认前，不得进行大规模移动、拆分或入口改写。
3. **Phase 1 与 Phase 2**：必须串行，先完成并验证 P1；P2 内部按表中顺序串行，避免 `index.html` 和普通 `<script>` 装配冲突。
4. **Phase 3**：等待 P1/P2 稳定后一次迁移，之后对新路径重新跑所有测试；不能只依据旧路径通过。
5. **Phase 4**：P4-A/P4-B 可并行只读设计；P4-C 统一集成。任何涉及公共接口、存档或模式生命周期的代码写入都必须单独记录回滚点。
6. **共享文件锁**：同一时间只能有一个代理写 `index.html`、`README.md`、`AGENTS.md`、`package.json` 或入口脚本加载清单；其他代理只能只读。

## 5. 全体子代理通用交付格式

每个代理最终必须报告：

- 结果：已完成、未完成、阻塞项；
- 修改/新增文件及写入边界；只读任务明确“未修改文件”；
- 关键实现或审计结论，附真实文件路径和行号；
- 验证命令、退出码、测试/浏览器结果；
- 与 Phase 0 基线相比的变化；
- 推断与未验证项、验证方法和残余风险；
- 回滚方式和下一任务的明确输入。

代理不得把“文件已移动”“构建成功”表述为“功能已验证”，不得吞掉错误、禁用测试、硬编码结果或借机修复范围外问题。
