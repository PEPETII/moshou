# Phase 3 工单：测试、工具与文档治理

## 任务目标

让测试、开发辅助脚本和项目文档从“散落文件”升级为长期可维护的工程资产，并为后续结构变化提供稳定验证入口。

## 当前问题

根目录目前仍存在测试和辅助脚本；`docs/` 中设计、审计、运行时架构、商店材料和历史测试结果混在较浅层级。项目已有 Playwright 依赖，但测试入口尚未统一。

## 建议目标结构

```text
tests/
├─ balance/
│  └─ test-balance.js
├─ fusion/
│  └─ test-fusion-recipes.js
├─ smoke/
└─ e2e/

scripts/
└─ generate-posters.js

docs/
├─ architecture/
├─ design/
├─ audits/
├─ roadmap/
├─ publishing/
├─ test-results/
├─ 工单计划/
└─ 完成报告/
```

## 实施步骤

### 1. 迁移根目录测试脚本

迁移前先检查：
- 是否依赖相对路径；
- 是否被 README/AGENTS/其他文档引用；
- 是否被 npm script 引用。

迁移后同步修正引用。

### 2. 迁移工具脚本

`generate-posters.js` → `scripts/`。

不修改其业务行为，只修正必要相对路径。

### 3. 建立 package.json 标准入口

在不引入构建工具的前提下，可增加：

```json
{
  "scripts": {
    "test:balance": "...",
    "test:fusion": "...",
    "test:smoke": "...",
    "test:e2e": "..."
  }
}
```

仅加入真实可运行命令，不创建空壳命令。

### 4. 建立结构 smoke test

优先覆盖最容易在重构中破坏的能力：
- 页面打开；
- JS 无加载错误；
- 关键全局对象存在；
- 主菜单按钮可用；
- 能进入关卡；
- 能返回主菜单；
- 征服模式入口可用。

### 5. 归类 docs

先建立分类映射表，再逐项迁移。

推荐：
- GDD、tower/ui/full-balance spec → `docs/design/`
- architecture-runtime、dependency map → `docs/architecture/`
- quality audit、code review、fix log → `docs/audits/`
- store listing → `docs/publishing/`
- 未来版本规划 → `docs/roadmap/`

`docs/工单计划/`、`docs/完成报告/`、`docs/test-results/` 保持现有强制用途。

### 6. 修复文档引用

迁移后全仓搜索：
- `.md)`；
- `docs/`;
- 旧文件路径；
- README/AGENTS 中的引用。

禁止留下失效链接。

### 7. 更新 README

README 的项目结构必须和真实目录一致。

不要在 README 中维护过细的每个内部文件说明；详细架构链接到 `docs/architecture/`。

## 注意事项

- Git 移动文件尽量保持可追踪历史。
- 不在文档整理阶段改游戏逻辑。
- `AGENTS.md` 内测试命令必须同步新路径。
- 若历史文档内容已经过时，不直接改写历史结论；可标记“历史报告”并新增当前架构文档。

## 验收标准

- [ ] 根目录无散落测试脚本。
- [ ] 根目录无仅供开发使用的海报生成脚本。
- [ ] package.json 提供真实可执行的测试入口。
- [ ] docs 分类明确。
- [ ] README 与真实结构一致。
- [ ] AGENTS.md 测试命令正确。
- [ ] 所有 Markdown 内链通过检查。
- [ ] 所有测试在新路径下仍能运行。
- [ ] 重构测试结果写入 `docs/test-results/`。
