# 音效优化与全局 BGM

## 任务目标

1. 优化现有水墨音效：按炮塔系别区分攻击音、加入音高随机、补全缺失场景的音效、加压限器防爆音、提供独立的音效/音乐开关与音量。
2. 新增全局背景音乐（BGM）：纯 Web Audio 程序化合成（古筝拨弦 + 竹笛 + 波鼓），覆盖主菜单、战斗准备、波次进行、胜负收尾，并按主题与战斗强度变化。

## 当前问题 / 背景

审查 `js/audio.js`（235 行）得到：

- 只有 `place / attack / death / fusion / wave / core` 六个音效，所有炮塔共用一个攻击音，击杀音不分敌人大小，每次音高完全相同。
- 无声场景：菜单与选关点击、升级、出售、墨水不足/放置失败提示、胜负弹窗、波次结束。
- 没有压限器，音量固定 0.6，只有开/关；开关只在战斗 HUD 内，主菜单与设置里没有。
- 页面切后台时游戏暂停，但音频上下文不暂停；没有"首次手势后解锁音频"的全局监听。
- 没有 BGM。

## 实施步骤

**P1 音效**

1. 拆分：`audio.js` 保留核心；新增 `audio-cues.js` 注册音效；总线改为 `sfxBus / bgmBus → master → DynamicsCompressor → destination`。
2. 攻击音按炮塔系别分 6 类（火、水冰、风木毒、金属、雷光、土暗），每类独立冷却，并加入 ±4% 音高随机与同时发声数上限。
3. 击杀音按敌人体型分小/大/首领三档。
4. 新增音效：界面点击、升级、出售、拒绝（提示框 warning 触发）、波次结束、胜利、失败。
5. 设置页加音效/音乐开关与两个音量滑块；战斗与征服 HUD 加音乐开关；设置写入 `localStorage`，不可用时只在本页生效。

**P2 BGM**

6. 实现预调度节拍器（`setInterval` + Web Audio 时钟前瞻 0.25s）；五声音阶旋律随机游走，带动机复用，避免循环疲劳。
7. 声部：古筝（Karplus-Strong 缓冲，按音高缓存）、竹笛（正弦 + 气声 + 颤音）、波鼓、低频长音；合成混响作为发送总线。
8. 场景：菜单 / 准备 / 战斗 / 结算；导演器每 250ms 读取界面与战斗状态选择场景；胜负音效触发时 BGM 压低。
9. 首次点击/触摸后解锁；页面切后台挂起上下文，回前台恢复；音乐关闭时停止调度器。

**P3 打磨**

10. 按主题（初墨、风林、火山、玄冰、终焉）切换调式根音与速度；战斗强度（场上敌人数与波次进度）影响速度、鼓点密度和旋律密度。

**收尾**

11. `tests/test-audio.js` 使用假的 `AudioContext` 校验：模块加载、音效注册、冷却、设置持久化、BGM 调度器产生音符且不抛错、不支持 Web Audio 时静默。
12. 运行 `npm test`；用浏览器实际加载检查无报错、横屏手机尺寸下 HUD 不挤出屏幕。
13. 更新 README 与脚本依赖图，写完成报告。

## 风险与注意事项

- 作者无法听到声音：只能保证技术正确（不爆音、不断音、能出声、可开关），音色与旋律是否顺耳需用户试听反馈后微调。
- 浏览器自动播放策略：必须在用户手势后创建/恢复上下文；iOS Safari 需要 `touchend`/`click` 手势。
- 手机性能：同时发声数设上限；BGM 只用一个卷积混响；音乐关闭时调度器停止。
- 仍是普通脚本加载，不引入构建工具、外部音频文件或网络依赖；每个文件不超过 600 行。
- 保留工作区与本任务无关的已有改动。

## 验收标准

- 6 类炮塔攻击音可区分，击杀音有三档，新增 7 个场景音效在对应事件触发。
- 音效与音乐可分别开关并调节音量，设置跨刷新保存；设置页、战斗 HUD、征服 HUD 均可操作。
- 菜单、战斗准备、波次进行、胜负收尾有不同 BGM 状态；首次手势前不出声，之后自动开始；切后台暂停、回前台恢复。
- 不支持 Web Audio 或存储不可用时游戏流程不受影响。
- `npm test` 全部通过，新增代码文件均不超过 600 行；完成报告记录实际验证范围与限制。
