# 工单：网格仅在炮塔待放置状态显示

- 日期：2026-10-18
- 状态：已完成（完成报告：`docs/完成报告/2026-10-18-网格仅放置态显示.md`）
- 类型：UI / 渲染行为调整

## 任务目标

把战场网格从"常驻背景"改为"放置辅助提示"：

1. 玩家进入炮塔待放置状态时显示网格，用来说明可落子的格子。
2. 放置完成、取消放置或未进入放置状态时，网格立即隐藏。
3. 显隐切换必须与状态切换同帧生效，且不改变其他画面元素的绘制顺序与观感。

## 当前问题 / 背景

- 主模式：`js/runtime.js` 的 `StaticCanvasLayer._ensure()` 在生成静态缓存时无条件调用 `game.drawGrid()`，网格被烘进缓存层，因此整局都显示。
- 征服模式：`js/modes/conquest/rendering.js` 的 `draw()` 每帧无条件调用 `drawGrid()`。
- 现有代码中"炮塔待放置"的唯一状态源是 `ui.placementDrag.active`（塔卡 pointerdown 进入，pointerup / pointercancel / lostpointercapture 退出，触摸端经 `input-card-gesture.js` 同样落到 `beginPlacementDrag`）。征服模式没有新塔放置流程，其"落位选点"状态为拖拽移动/融合现有塔的 `isDragging`。
- 网格被绘制在路径墨廊**之下**（缓存顺序：地形 → 网格 → 路径 → 核心）。若改为每帧叠在静态层之上绘制，网格会压在墨廊上，属于画面元素显示异常，因此必须保持原有 z 序。

## 涉及文件

- `js/core/rendering.js`：新增放置态判定与 `drawGrid()` 守卫。
- `js/runtime.js`：`StaticCanvasLayer` 增加网格显隐同步与缓存失效。
- `js/modes/conquest/rendering.js`：`ConquestGame.drawGrid()` 增加放置态守卫。
- `tests/test-grid-visibility.js`（新增）：验证显隐判定与绘制次数。
- `package.json`：把新测试挂进 `npm test`。

## 实施步骤

1. 在 `Game.prototype` 上增加 `isPlacementActive()` / `shouldShowGrid()`，口径直接复用 `ui.placementDrag.active`，不引入第二套状态。
2. `Game.prototype.drawGrid()` 首行加守卫：非放置态直接返回。
3. `StaticCanvasLayer` 记录缓存中是否含网格（`_gridVisible`），在 `draw()` 前比对当前状态；状态变化即 `dirty = true`，使缓存在同帧重建，网格随状态即时出现/消失，且 z 序不变。
4. 征服模式：初版按 `isDragging` 守卫，实测空场棋盘失去唯一分格依据、退化为淡色平板，故回退为网格常驻，仅保留注释说明（详见完成报告"关键判断"）。
5. 新增测试：未放置时 `drawGrid()` 不产生任何描边；放置中产生预期数量的网格线；`pointerup`/`pointercancel` 后恢复隐藏；`StaticCanvasLayer` 状态切换会置脏。
6. 回归 `npm test`。

## 风险与注意事项

- 缓存重建发生在状态切换当帧：地形与墨廊均为已缓存 canvas 的 `drawImage` 合成，成本可控；不在每帧重建。
- 若后续新增其他"待放置"入口（如点击选定后点地落子），必须仍写入 `ui.placementDrag.active`，否则网格不会出现。
- 融合拖拽（拖动已有塔）不视为"新塔待放置"，主模式不显示网格，沿用既有落点描边预览。
- 征服模式无新塔放置，网格是其棋盘分格的唯一依据（空场没有其他分格视觉），因此保持常驻，不随拖拽显隐；已加测试锁定该行为。
