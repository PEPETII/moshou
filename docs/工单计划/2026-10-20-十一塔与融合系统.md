# 工单：新增八座单字塔、三座合字塔与融合系统，重做土、木（2026-10-20）

## 一、任务目标

在现行字形弹道玩法上：

1. 新增 8 座单字塔：金、风、炮、雷、冰、弓、山、剑，进入商店与征服召唤池、炮塔志；
2. 重做土、木两塔的普攻与大招，使其与火的「直线爆发」明显区分（土＝范围压制与减速，木＝持续生长与蔓延）；
3. 重建融合系统：两座素材塔合成一座合字塔（炎、林、焚），映射集中在 `CONFIG.FUSION`；
4. 图鉴新增「合字图鉴」页，展示解锁状态、素材塔、合成公式与说明。

## 二、当前问题 / 背景

- 现役只有火、水、土、木四塔（`CONFIG.ACTIVE_TOWERS`）。土、木与火同为「掷出整字→落地炸开」的抛物大招，打法与火重合。
- 32 座下架塔的配置与旧攻击链已在 [删除下架炮塔残留](2026-10-20-删除下架炮塔残留.md) 中删除（工作区尚未提交）。旧金风炮雷冰弓山剑的实现走旧攻击链，已无法复用；本次一律按字形结构**重建**，只回收两项仍有效的基础设施：
  - 路径塔阻挡：`Enemy.checkBlocking` + `RuntimeIndexes.blockingTowerByCell` + `Tower.takeDamage`（山字塔用）；
  - `onPath` 放置校验（`js/core/towers.js`）。
- 融合系统（`js/config/fusion.js` 等）已于 2026-10-19 整套删除，本次按字形结构重写，不恢复旧代码。

## 三、决策（已与用户确认）

- 合字全部可见（图鉴不设锁）；图鉴「解锁状态」统一显示「已开放」，另记本机是否亲手合成过。
- 本阶段不做数值平衡（D12 延续），只保证每塔可用、可辨识。
- 配方：炎 = 火 + 火；林 = 木 + 木；焚 = 林 + 火。
- 一次完成四个阶段。
- 火塔大招原名「焚」与合字塔「焚」重名，图鉴与说明中火塔大招改称「燎」，招式实现不变。

## 四、设计表

### 单字塔

| 塔 | 键 | 普攻 | 大招 | 独特点 |
|---|---|---|---|---|
| 金 | `gold` | 金轮：两横轮流化作回旋刃，去程、回程各结算一次 | 金钟：整字罩下，范围伤害并「破甲」（受伤加深） | 回旋弹道 + 易伤 |
| 风 | `wind` | 风刃：撇化作扇形横扫，扇内全部受伤并被吹退 | 旋：落点生成旋风，把周围敌人沿路吸向中心并持续伤害 | 扇形 + 聚怪 |
| 炮 | `cannon` | 炮弹：抛射打最远处敌人，落地溅射；近身有盲区 | 连珠：五发炮弹沿路依次落下（地毯轰炸） | 超远射程 + 最小射程 |
| 雷 | `thunder` | 电弧：瞬发连锁闪电，湿身目标加伤且不衰减 | 霹雳：天雷轮番劈落多名敌人，小范围伤害并眩晕 | 瞬发连锁 + 水雷联动 |
| 冰 | `ice` | 冰凌：竖钩化冰凌，叠「寒」减速，叠满冻结 | 冻：寒潮从塔身扩散，冻结射程内全部敌人 | 叠层减速→冻结 |
| 弓 | `bow` | 穿云：超远单发，优先射血量最高者，对重敌加伤 | 箭雨：射程内一段路持续落箭 | 优先高血 + 反重甲 |
| 山 | `mountain` | 峰刺：三竖化作石刺，从最前三名敌人脚下拱出 | 崩：回满生命并沿路双向震荡，击退眩晕 | 唯一路径塔，有生命，阻挡来敌 |
| 剑 | `sword` | 剑气：短射程高频斩击最近敌人，带暴击 | 剑落：竖钩化巨剑沿路向入口飞斩，途经者各中一剑 | 近战高频 + 沿路飞剑 |

### 土、木重做

| 塔 | 普攻 | 大招 |
|---|---|---|
| 土 | 夯土：下横砸地，以塔为心震荡一圈，伤害并「泥泞」减速（无弹道） | 壁垒：落点升起「土」字壁垒，区域内重度减速并持续碾压，到时崩塌造成伤害与眩晕 |
| 木 | 播种：撇笔落到最前敌人前方路上，长成木苗，持续刺伤经过者并轻微减速（每塔上限若干） | 蔓生：藤蔓从落点沿路双向生长蔓延，缠住其上敌人（减速 + 持续伤害） |

### 合字塔（属性独立配置，不由素材叠加推导）

| 塔 | 键 | 公式 | 普攻 | 大招 |
|---|---|---|---|---|
| 炎 | `yan` | 火 + 火 | 炎柱：瞬发火柱贯穿直线，叠两层灼烧 | 双爆：两枚火字先后砸向两处敌群 |
| 林 | `lin` | 木 + 木 | 双生：一次种两株木苗，木苗初触定身 | 成林：射程内全部敌人被定身，林地持续伤害；其中被击杀者原地再生木苗 |
| 焚 | `fen` | 林 + 火 | 焚木：抛出燃木，落地成短时火场 | 燎原：大火从落点沿路双向蔓延；燃烧中被击杀的敌人爆燃波及周围 |

合字塔字形由素材字的笔画按部件位置组合生成（炎＝上下两火，林＝左右两木，焚＝上林下火），不手写坐标。

### 融合规则

- 选中一座塔，信息面板列出它能参与的配方；另一份素材须在**相邻 8 格**内。
- 校验：全局合成冷却（`CONFIG.FUSION.cooldown` 秒）、墨水（配方 `cost`）、相邻素材存在、结果塔可占用被选塔所在格（路径塔/非路径塔与格子类型一致）。
- 结算：消耗两座素材塔与墨水，合字塔落在被选塔所在格，另一格腾空；已发出的弹道照常收尾。
- 塔防与征服共用同一逻辑。

## 七、风险与注意事项

- **火、水不改**：`fire.js`、`water.js` 与其参数一字不动；全局大招间隔、顿帧、震屏机制不动。
- **注册表兼容**：`GlyphTower.impl` 对未知类型须安全返回，不能让旧测试桩（`probe` 等）崩溃。
- **山字塔阻挡**：沿用旧阻挡链，需确认里程制下 `pathIndex` 正确同步；山被打掉时须走 `removeTower` 并重建索引。征服模式召唤出的山不放路径上（`onPath` 置否），只用招式。
- **敌人状态**：减速与湿身叠乘并设上限，避免敌人被永久冻住；冰冻走 `glyphStun`，尊重 `immuneControl`。
- **性能**：上限 260 敌人。所有范围查询走 `GlyphWorld.enemiesInRange`；沿路蔓延类招式按路段采样，不逐敌扫全路径。
- **行数**：每个文件 ≤ 600 行；`test-glyph-battle.js` 已 546 行，新断言放新测试文件。
- **底栏 12 张卡**：确认底栏可横向滚动，不挤压。

## 八、验收标准

- `CONFIG.ACTIVE_TOWERS` 为 12 座单字塔；`CONFIG.TOWERS` 共 15 条；`CONFIG.FUSION.recipes` 3 条。

- 每塔能放置、普攻、自动大招，绘制不抛错；山字塔能挡住敌人并被打掉。
- 融合在冷却、墨不足、无相邻素材时给出原因且不执行；条件满足时消耗素材与墨水、生成合字塔。

- `npm run check:line-count`、`npm test`、`npm run test:balance`、`npm run test:glyph` 全部通过。
