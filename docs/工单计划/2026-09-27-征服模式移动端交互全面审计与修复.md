# 工单：征服模式移动端交互全面审计与修复

- **日期**：2026-09-27
- **类型**：移动端交互审计与缺陷修复
- **优先级**：P0
- **范围**：征服模式的移动端操作与交互，不改动数值与玩法规则

## 1. 任务目标

以移动端触摸玩家为目标，全面检查征服模式从进入关卡到战斗操作、炮塔信息、移动/融合、召唤/波次、图鉴、胜负弹窗和返回流程的交互设计，找出仍残留的桌面端假设，并用最小范围修复使关键流程符合触屏预期。

## 2. 当前问题/背景

工作区已有一版征服模式触屏适配改动，本工单先把该改动视为待验证基线，不直接采信已有报告。重点复核：实际 DOM/CSS 尺寸与缩放坐标、动态模态按钮、触摸状态清理、多点/取消路径、覆盖层可达性，以及移动端触控目标尺寸。

工作区在任务开始前已有大量未提交改动，涉及全站样式、征服模式和文档；本任务只叠加必要变更，不覆盖或整理无关改动。

## 3. 涉及文件

- `js/modes/conquest/*`
- `js/conquestGame.js`（仅在确认重复实现会影响运行路径时处理）
- `js/bootstrap/page-markup.js`
- `js/bootstrap/device-profile.js`
- `js/bootstrap/viewport.js`
- `js/ui/*`（仅检查共用弹窗、提示和触摸输入调用链）
- `css/style/*`、`css/inline/*`（仅征服模式及移动端覆盖规则）
- `index.html`
- 必要的征服模式验证脚本或测试

## 4. 实施步骤

1. 记录现有工作区状态、测试基线和适用项目规则。
2. 以真实调用链审查触摸事件、坐标换算、模式切换、弹窗/覆盖层和可点击尺寸。
3. 在可用浏览器或最小 DOM 复现中验证关键移动端路径，区分已确认、推断和未验证项。
4. 对直接影响征服模式移动端可用性的缺陷做最小补丁，保持桌面鼠标路径与数值规则不变。
5. 运行行数检查、语法检查、受影响测试，并记录已有失败与本次结果。
6. 创建完成报告，列出证据、残余风险和未验证的真机事项。

## 5. 风险与注意事项

- 不修改炮塔、敌人、波次、融合配方等数值。
- 不覆盖工作区已有未提交改动，不做无关格式化、重构或依赖升级。
- 触摸事件必须避免与合成鼠标事件重复执行，并保证 `touchcancel`、多指和模态/关卡结束路径清理状态。
- 任何覆盖层按钮的动态改动都要检查与共用 `#modal-btn` 监听器的兼容性。
- 项目代码文件保持不超过 600 行；如需新增验证文件，避免把它混入运行时入口。

## 6. 验收标准

1. 移动端可进入征服关卡，当前模式的侧栏、画布和按钮均在可视区域内，坐标命中与缩放一致。
2. 可用手指点击查看炮塔信息、点击空白关闭、点击升级/出售/召唤/波次/图鉴/菜单。
3. 可拖动普通炮塔，实时看到落点/可行性反馈；融合有明确确认和取消路径；非法操作有可读反馈。
4. 多点触控、系统取消、关卡结束和返回菜单不会残留拖拽状态、遮罩或事件监听器。
5. 桌面鼠标链路保持可用，数值与玩法规则未改变。
6. 通过与本次影响范围匹配的自动化检查，并在完成报告中明确浏览器/真机验证边界。
