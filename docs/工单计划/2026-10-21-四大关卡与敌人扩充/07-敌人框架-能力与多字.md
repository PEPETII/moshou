# 07 敌人框架：能力组件与多字分段

- **所属模块**：敌人实体（`js/enemy.js`、`js/entities/enemy/`）、敌人配置、图鉴「妖异录」
- **依赖**：无。08、09、10、12 都建立在这份工单之上。

## 1. 目标

1. 给敌人加上**能力组件**：每种能力是一个独立的小模块，敌人配置里声明自己有哪些能力、参数是多少，`Enemy` 每帧调度。
2. 给敌人加上**多字分段**：双字、三字、四字敌人每个字单独计血；某个字被打碎，挂在这个字上的能力就失效。
3. 定义**体量**（`mass`）和**字数**（`glyphCount`）两个字段，供控场规则（12）使用。
4. 妖异录能展示新敌人：多字敌人逐字列出能力。

## 2. 当前问题和背景

- 敌人的特殊行为散落在 `combat.js` / `misc.js` 里，用 `config.split`、`config.invisible` 这类布尔开关控制，大多是旧玩法遗留下来的，而且计时用的是 `Date.now()`。
- 敌人只有一个 `hp`；重敌只靠 `weight > 1` 来区分。

## 3. 具体规格

### 3.1 配置格式

单字敌人：

```js
bone: {
  char: '骨', hp: 45, speedPx: 44, size: 30, weight: 1, damage: 1, reward: 5,
  tier: 'minor',                          // minor 小怪 / heavy 重敌 / elite 双字 / greater 三字 / boss 四字
  abilities: [ { id: 'reassemble', delay: 1.5, hpRatio: 0.4, breakKinds: ['fire', 'thunder', 'yan', 'fen'] } ],
},
```

多字敌人（字的顺序就是受伤的顺序）：

```js
yaksha: {
  name: '夜叉', speedPx: 52, size: 34, weight: 3, damage: 3, reward: 30, tier: 'elite',
  segments: [
    { char: '夜', hp: 120, abilities: [ { id: 'stealth', revealRadius: 110 } ] },
    { char: '叉', hp: 160, abilities: [ { id: 'dash', every: 5, distance: 80 } ] },
  ],
  abilities: [],                          // 不属于任何一个字的能力（整只敌人都有）
},
```

- `hp` 由各段血量相加推导出来，不用手写。
- 关卡的 `hpMul`（01）乘在每一段的血量上。

### 3.2 派生字段（在 `Enemy` 构造时计算）

| 字段 | 计算 |
|---|---|
| `glyphCount` | 单字为 1，否则为 `segments.length` |
| `mass` | 优先读配置；没有就按分档：`minor` 1、`heavy` 3、`elite` 4、`greater` 6、`boss` `Infinity` |
| `isBoss` | `tier === 'boss'` |
| `segIndex` | 当前在受伤的段（从 0 开始） |
| `segHp[]`、`segMaxHp[]` | 每一段的当前血量和最大血量 |

### 3.3 能力框架（`js/entities/enemy/abilities/`）

```
abilities/registry.js   EnemyAbilities.IMPLS = { reassemble, blink, web, ... } 与调度
abilities/minor-a.js    初墨、墨泽主题的单字能力
abilities/minor-b.js    铁砚、焚卷主题的单字能力
abilities/elite.js      双字、三字的能力
abilities/boss.js       四字首领的能力（超过 600 行时再按首领拆）
```

每种能力实现以下接口（不需要的钩子可以不写）：

```js
{
  init(e, p)               // p 是配置里的参数；能力状态放在 e.ab[id]
  update(e, p, dt, game)   // 每帧调用；冷却统一按 dt * e.abilityTimeScale 递减
  onHit(e, p, amount, opts)          // 返回修正后的伤害（硬甲、缩壳之类）
  onLethal(e, p, opts)     // 受到致命伤时调用；返回 true 表示拦下这次死亡（复聚、复生）
  onSegmentBreak(e, p, index)        // 有字被打碎
  draw(ctx, e, p)          // 额外的绘制（光环、隐身虚影等）
}
```

调度规则：

- **能力冻结**：敌人处于 `carried`（被潮卷着）、`stun > 0`、被冻结这些状态时，不调用 `update`。冷却照样计时，但不触发主动效果。
- **碎字失效**：段上的能力只在 `segIndex ≤ 该段下标` 时生效，也就是这个字还没碎。
- **伤害管线**：`Enemy.hit(amount, opts)` 先依次调用所有有效能力的 `onHit` 修正伤害，再乘上增伤（受 12 的上限约束），最后扣在当前段上，溢出部分顺延到下一段。
- **死亡**：所有段都碎完（单字敌人就是 `hp ≤ 0`）时，先依次调用 `onLethal`，任意一个返回 `true` 就不死。
- `opts.kind`（伤害来源的塔类型，`GlyphWorld.damage` 已经传了）要记到 `e.lastHitKind` 上，「复聚」这类能力需要用。

### 3.4 召唤接口

`game.spawnGlyphEnemy(type, { pathIndex, s, summoned: true })`

- 召唤物出生在召唤者的 `s - 10 ~ s - 40` 范围内（取不到就从 0 起），走召唤者所在的路径。
- 召唤物 `reward = CONFIG.SUMMON_REWARD`（初值 1），不受关卡 `hpMul` 影响。
- 召唤也要遵守 `ENEMY_CAP`：场上数量到上限时，这次召唤直接跳过，冷却照常计算。

### 3.5 显形 / 不可选中

部分能力会让敌人**不能被单体攻击锁定**，统一用一个字段 `e.untargetable = true`（每帧由能力设置）。

- `GlyphTower.frontTarget`、弓的「最高血量」选目标、剑的「最近」选目标、金轮、冰凌、雷的首跳，全部过滤掉 `untargetable` 的敌人。
- **范围类效果照常命中**：焦土、震荡、壁垒、木苗、藤蔓、旋风、箭雨、炮弹溅射、寒潮、雷的后续跳跃。
- 被范围伤害命中的敌人进入显形状态 `revealT = CONFIG.REVEAL_ON_AOE`（初值 1.5 秒），显形期间可以被锁定。
- 绘制：不可选中时画成 35% 透明度的虚影。

### 3.6 多字敌人的绘制（`js/entities/enemy/segments.js`）

- 每个字按 `size` 横向排开，字间距 0.9 倍字号，沿行进方向从前往后排列：第一个字（最先受伤的那个）走在最前面。
- 碎掉的字：在原位置画一团碎墨（透明度 0.4），然后淡出；剩下的字往前合拢，0.3 秒动画。
- 血条：每个字下面一小段血条；首领不画头顶血条，改用 01 的首领血条。
- 每个字的碰撞半径（`enemiesInRange` 用到的）按整只敌人的包围盒算：中心取各字中点，半径 = 字数 × 字号 × 0.5。这样范围技能不会因为敌人变长而打不中。

### 3.7 妖异录

- `CONFIG.CODEX.enemies` 补齐 20 种新敌人的文案：`role` 一句话定位，`traits` 列出能力条目。多字敌人按字逐条写：「夜 · 夜行：……」。
- `ACTIVE_ENEMIES` 改成 23 个 key，按出场顺序排列（顺序见 11 的总表）。
- 妖异录卡片显示字数徽记：「单」「双」「三」「四」。首领卡片用朱砂边框。

`js/enemy.js`、`js/entities/enemy/misc.js`（构造）、`combat.js`（受伤）、`lifecycle.js`（死亡）、`rendering.js`、`js/glyph/glyph-tower.js`（选目标过滤）、`js/glyph/adapter.js`，以及每座塔选目标的地方（`bow.js`、`sword.js`、`gold.js`、`ice.js`、`thunder.js` 等）、`js/config/codex.js`、`js/ui/encyclopedia.js`。新增 `js/entities/enemy/abilities/*.js`、`js/entities/enemy/segments.js`。

## 5. 实施步骤

1. 构造函数解析 `segments`、`tier`、`mass`，计算出派生字段。
2. 编写能力注册表和调度，先接一个空能力验证流程。
3. 改造伤害管线：`onHit`、分段扣血、溢出顺延、`onLethal`。
4. 实现 `untargetable` 过滤：把各塔选目标的逻辑收拢到一个函数 `GlyphKit.targetable(pool)`，避免每座塔各写一套。
5. 实现多字敌人的绘制和碎字动画。
6. 实现召唤接口。
7. 扩充妖异录。

## 6. 风险与注意

- 旧的布尔能力开关（`split`、`invisible` 这类）**不要**和新能力框架混用；新敌人只用 `abilities`。
- 伤害数字、连斩、击杀着色这些逻辑都挂在「死亡」事件上。多字敌人碎一个字**不算**击杀，可以弹一个较小的碎字飘字和一次轻微震屏（`addShake(3)`）。
- 性能：能力调度每帧要遍历全部敌人。只有配置了能力的敌人才调用 `update`，没有能力的尸、鬼、巨直接跳过。

## 7. 验收标准

- [ ] 一只三字敌人受到正好等于第一段血量的伤害时，第一段碎掉、第二段满血。
- [ ] 一次溢出伤害可以连续打碎两段。
- [ ] 能力只在自己所在的字没碎时生效。
- [ ] 被潮卷着、被眩晕的敌人不会触发主动能力。
- [ ] `untargetable` 的敌人不会被单体攻击锁定，但会被焦土、震荡这类范围效果命中，并且命中后显形 1.5 秒。
- [ ] 召唤物出生在召唤者附近，并且受 `ENEMY_CAP` 限制。
- [ ] 尸、鬼、巨的行为、数值和改动前完全一致（`test:glyph`、`test:damage` 通过）。
