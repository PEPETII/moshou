# 01 关卡框架、刷怪编排、首领胜负与全部解锁

- **所属模块**：关卡数据（`js/levelsData.js`、`js/levelManager.js`、`js/data/levels/`）、刷怪（`js/core/spawner.js`）、对局流程（`js/core/flow.js`、新增 `js/core/boss.js`）、选关 UI（`js/ui/level-scroll.js`）
- **依赖**：无（首领的具体能力在 10，本工单只搭流程，用一个测试用的占位首领验证）

## 1. 目标

1. 关卡数据可以声明：本关出哪些敌人、各占多少比例、什么时间出精英、要不要出首领。
2. 刷怪器 `BattleDirector` 改为**数据驱动**，不再写死尸、鬼、巨的比例。
3. 关底实现「坚守 + 斩首」的组合胜负判定。
4. 4 个主题、20 关全部解锁。

## 2. 当前问题

- `BattleDirector.update` 写死了 `corpseRatio`（尸、鬼比例）和 `giantEvery`（多久出一只巨），每一关出的怪都一样。
- `LevelManager._initThemes` 和 `levelsData.js` 的 `THEMES` 都只有主题 1；`getLevelsByTheme` 固定按每主题 10 关去查。
- 胜利条件只有 `holdLeft <= 0 && coreHp > 0`，没有首领的概念。
- `isThemeUnlocked` 依赖 `unlockRequirement` 判断能不能进。

## 3. 具体规格

### 3.1 关卡数据新增字段（`LEVELS_DATA[id]`）

```js
"1-5": {
  id: "1-5", name: "夜行", theme: 1, difficulty: 5,
  startInk: 450, coreHp: 20, holdSeconds: 180,
  path: polylineCells([...]),        // 也可以是二维数组：多条路径
  core: { x: 25, y: 4 },
  // ↓ 新字段
  hpMul: 1.12,                       // 本关小怪、精英的血量倍率（首领不吃这个倍率，见 10）
  roster: [                          // 普通刷怪池；权重越大越常出
    { type: 'corpse', weight: 50 },
    { type: 'ghost',  weight: 25 },
    { type: 'bone',   weight: 15, from: 20 },   // from / to：只在开战后第 from～to 秒出现
    { type: 'fox',    weight: 10, from: 40 },
  ],
  heavy: [                           // 重敌按固定间隔出，替代旧的 giantEvery
    { type: 'giant', every: { sparse: 14, normal: 9, flood: 6 }, first: 4 },
  ],
  elites: [                          // 精英按时间点出现，与敌潮档位无关
    { type: 'yaksha', at: 60 },
    { type: 'yaksha', at: 120, path: 1 },     // path：多路径关卡里指定走哪一条，缺省为随机
  ],
  boss: { type: 'baiguiyexing', at: 100, path: 0 },  // 只有第 5 关有
  surges: [ { at: 90, dur: 8, rateMul: 1.6 } ],      // 可选：某段时间刷怪更密，可以没有
}
```

- `roster` 缺省时，回退到旧逻辑（`corpseRatio` + `giantEvery`），保证征服模式和旧数据照常运行。
- 每一档敌潮的刷怪速率（`DENSITY[*].rate`）照旧，从 `roster` 里按权重抽取怪物类型。
- 新字段 `heavy[].every` 可以给数字（三档相同），也可以给按档位区分的对象。

### 3.2 刷怪器重构（`js/core/spawner.js`）

- 新增 `pickRosterType(level, elapsed)`：只在 `from ≤ elapsed < to` 的条目里按权重抽取。
- 精英、首领按 `at` 触发，每个只触发一次；用 `game.spawnedElites` 记录已经出过的下标。
- **首领出场的缓冲期**：首领出场后的 `CONFIG.BOSS.entryCalmSeconds`（初值 10 秒）内，普通刷怪速率乘 `entryCalmRateMul`（初值 0.5）。
- 新增 `spawnGlyphEnemy(type, { pathIndex, s })`，额外参数可选：`pathIndex` 指定路径，`s` 指定初始里程（召唤用，见 07）。
- 开战后经过的时间记在 `game.elapsed` 上，由刷怪器累加，暂停时不走。
- 文件超过 600 行时，把 `roster` 抽取、精英调度拆到 `js/core/spawn-schedule.js`。

### 3.3 关底胜负（新增 `js/core/boss.js`、`js/config/boss-battle.js`）

```js
CONFIG.BOSS = {
  entryCalmSeconds: 10, entryCalmRateMul: 0.5,
  killEarlyHoldMul: 0.5,      // 首领在计时结束前被击杀：剩余坚守时间立即减半
  coreHitRatio: 0.5,          // 首领第一次到达核心：扣除核心上限的 50%（向上取整）
  maxCoreHits: 1,             // 首领到达核心的次数超过这个值就直接判负
  duelSpawnStop: true,        // 进入决战后停止普通刷怪
};
```

| 情况 | 结果 |
|---|---|
| 计时结束，首领已死，核心血量 > 0 | **胜利** |
| 计时结束，首领还活着 | 进入「**决战**」：停止普通刷怪（召唤物照出），倒计时文字变成「斩首」；之后首领死亡且核心血量 > 0 即胜 |
| 计时结束前首领被击杀 | 剩余坚守时间 × `killEarlyHoldMul`，计时继续；横幅提示「首级已斩」 |
| 首领第 1 次到达核心 | 扣除 `ceil(maxCoreHp × coreHitRatio)` 点核心血量，首领带着**当前血量**回到入口重新走（其余状态清空），横幅提示「首领破阵 · 卷土重来」 |
| 首领第 2 次到达核心 | 直接失败，失败原因写「首领破阵」 |
| 核心血量归零 | 失败（原有规则） |

- 首领的 `damage` 字段不再用来扣核心血量；到达核心时由 `boss.js` 接管处理。
- 在 `Enemy` 的到达核心逻辑（`js/entities/enemy/lifecycle.js`）里，如果 `this.isBoss` 为真，就转交 `BossFlow.onReachCore(game, enemy)` 处理。
- 胜负判定从 `BattleDirector.update` 的 `holdLeft <= 0` 分支里拆出来，统一调用 `BossFlow.checkVictory(game)`；没有首领的关卡行为和现在完全一样。

### 3.4 首领相关 UI（`js/ui/boss-bar.js`）

- 首领出场时，在画布顶部中间显示首领血条：四个字依次排开，每个字下面是这个字自己的血条；碎掉的字用朱砂斜线划掉，并变灰。
- 首领出场横幅：在现有横幅样式基础上显示首领名，持续 1.6 秒；开启「减少动态效果」时只显示文字，不做动画。
- 首领不在镜头范围内时，在视口边缘显示一个朱砂箭头，点击后镜头移到首领位置（调用 `camera.js` 现有的定位接口；没有的话就补一个 `focusWorldX`）。
- 倒计时文字的三种状态：`mm:ss` → 首领被击杀后显示「mm:ss · 首级已斩」→ 进入决战后显示「斩首」。

### 3.5 主题与关卡注册

- `THEMES` 和 `LevelManager._initThemes` 改成**从同一个数据源读取**（推荐只保留 `levelsData.js` 的 `THEMES`，`LevelManager` 直接读它），避免两处配置不一致。
- `getLevelsByTheme` 不再固定按 10 关查找，改为按 `LEVELS_DATA` 里实际存在的、`theme` 字段匹配的关卡，按关卡序号排序。
- 4 个主题：

| id | name | icon | desc |
|---|---|---|---|
| 1 | 初墨 | 墨 | 荒村夜路，初识妖异 |
| 2 | 墨泽 | 泽 | 水乡烟雨，潜影难寻 |
| 3 | 铁砚 | 砚 | 关隘重甲，步步为营 |
| 4 | 焚卷 | 焚 | 卷焚劫起，万妖归位 |

### 3.6 全部解锁（E7）

- `LevelManager.isThemeUnlocked`、关卡卡片的解锁判断一律返回 `true`；`unlockRequirement` 字段保留但不再参与判断。
- 征服模式：`conquestProgress.js` 的 `unlockedThemes` 视为所有主题都已解锁（读档时直接补全，不弹提示）。
- 通关记录（`moshou_completed_levels`）照常写入，选关界面的「已守 x / y」照常显示。
- 选关界面里，「未解锁」的样式、遮罩和锁图标全部去掉。

## 5. 实施步骤

1. 统一 `THEMES` 数据源，改写 `getLevelsByTheme`。
2. 刷怪器支持 `roster`、`heavy`、`elites`、`boss`、`surges`，并保留没有 `roster` 时的旧逻辑回退。
3. 编写 `boss.js` 和 `boss-battle.js`，把胜负判定改为调用 `checkVictory`。
4. 编写首领血条、横幅、屏外指示箭头。
5. 去掉所有解锁判断。
6. 用一个**测试用的占位首领**跑通完整流程：随便拿四个字，每字 300 血、没有能力。

## 6. 风险与注意

- **`LevelManager` 有字段白名单**：`levelManager.js` 约第 200～217 行的归一化函数只返回固定的那几个字段。`hpMul`、`roster`、`heavy`、`elites`、`boss`、`surges` 必须加进返回对象里，否则会被**静默丢弃**。05 要用的不可建造格（岩石）走现有的 `specialTerrain` 字段（`_computePlacementGrid` 已经会把它从可建造格里排除），不需要另加新字段。
- **征服模式**和刷怪器共用 `BattleDirector`。征服关卡没有 `roster`，必须走旧逻辑回退；`test:conquest-touch`、`test:spawn` 必须继续通过。
- 首领回到入口重新走时，要清空 `carried`、`stun` 等状态，并重建敌人索引（`runtimeIndexes.rebuildEnemies`）。
- 计时器用 `dt` 累加，保证暂停时不走。

## 7. 验收标准

- [ ] 没有 `roster` 的关卡（征服 1-1、1-2）刷怪行为和改动前一致。
- [ ] 配置了 `roster` 的关卡，敌人类型比例偏差 ≤ ±5%（统计 1000 次抽取）。
- [ ] 精英、首领在 `at` 秒（误差 ±0.1 秒）准时出现，并且只出一次。
- [ ] 表 3.3 的六种情况各写一个自动化断言（见 13）。
- [ ] 选关界面显示 4 个主题，20 关都可以直接进入；已通关的关卡有标记。
- [ ] 首领血条按字分段显示，碎掉的字有划线标记。
