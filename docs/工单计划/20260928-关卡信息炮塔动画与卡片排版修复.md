# 关卡信息、炮塔动画与卡片排版修复

## 任务目标

- 移除关卡选择区的附加说明，同时保留关卡编号、名称和进入按钮。
- 统一炮塔攻击动画与渲染使用的时间基准，修复水字塔等文字炮塔持续快速抖动，并降低攻击位移的振荡幅度与频率。
- 复用现有前两字/剩余字符拆分，让三字和四字炮塔在现有卡片中分别显示为 2+1、2+2。

## 当前问题/背景

- `Tower.prototype.draw` 和战斗渲染调用使用 `performance.now()`，`triggerAttackAnimation` 却以 `Date.now()` 记录起始时刻。二者时钟基准不同，计算出的攻击进度会成为巨大负数，`isAttacking` 无法按时结束；水、冰、风等绘制函数又对该进度乘以多个 π 周期，产生快速、持续的位置变化。
- `createTowerSelects()` 已把长度不少于 3 的名称拆成前两个字符和剩余字符，但 CSS 仅为两个指定塔种把内层 `span` 设为块级，其他多字塔仍在同一行。
- 关卡说明节点由动态脚本写入，CSS 还为它保留第二行；删除节点时需同步删除写入逻辑和布局占位。

## 实施步骤

1. 删除关卡附加说明的 DOM、文本派生赋值及相关 CSS 行布局，并调整选择栏高度/按钮行定位。
2. 沿更新调用传递同一单调时钟，并复用统一的攻击动画进度计算；将不合理的多周期位移改为低幅度、平滑的单次脉冲。
3. 在现有多字拆分分支标记多字卡片，添加通用分行规则；缩小多字字形并控制行高与字距，维持卡片尺寸、价格显示及单/双字样式。
4. 运行相关自动化检查并在桌面、移动视口检查关卡信息、炮塔动态与卡片布局；创建完成报告。

## 风险与注意事项

- 攻击动画时钟也用于融合塔；其重写的 `draw` 必须一起使用同一时钟，避免只修复基础塔后引入时钟错位。
- 仅改变绘制表现和关卡说明布局，不改塔属性、费用、攻击间隔、弹道、攻击逻辑或拖拽事件。
- 多字样式只作用于长度不少于 3 的卡片，不覆盖单字、双字样式；不扩展到其他无关 CSS/JS。
- 保留工作区现有泼墨生命周期相关未提交改动，不修改、不覆盖其计划、报告及测试。

## 验收标准

- 关卡选择区不再生成或写入附加说明，关卡编号、关卡名称和进入按钮仍可用且无空白说明行。
- 水、火、土、风、冰等存在多周期位移的文字塔不再持续快速抖动；攻击动画平滑归零，不使用逐帧随机偏移。
- 单字、双字塔卡视觉保持；三字为 2+1，四字为 2+2；桌面和移动视口无裁切、重叠或溢出，价格保持可见。
- 炮塔属性、花费、攻击及拖拽放置行为不变；相关检查通过，完成报告记录已确认、推断和未验证事项。
