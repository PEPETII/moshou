# 工单 01：删除融合系统与多字塔

- 总览：[00-总览](00-总览.md)（对应决策 D1、D2）
- 依赖：无（建议先完成总览里的前置提交）

## 任务目标

彻底移除融合玩法，以及所有两字及以上的炮塔。完成后游戏里不再有任何「拖拽融合」「融合预览」「融合图鉴」的入口和代码路径，现有单字塔的行为不受影响。

## 当前问题/背景

- `js/config/fusion.js` 里登记了 45 个融合配方：二合一、三合一，以及单字产物，如炎、淼、焱、鑫等；还有 `FUSION_EVOLUTION_RECIPES` 和 `FUSION_BALANCE`。
- 两座基础多字塔：`xinZhongYan`（心中炎）、`ruFengSiZhen`（如风似真），定义在 `js/config/domain-02.js`，并在关卡 `unlocks` 里解锁。
- `CONFIG.TOWERS.fusion`（字「融合」，cost 0）是一个占位类型。
- 融合逻辑散落在塔防和征服两种模式、输入、界面、音效、图鉴、测试和脚本里。

## 实施步骤

1. 全仓库搜索 `fusion|Fusion|融合|xinZhongYan|ruFengSiZhen|心中炎|如风似真`，列出清单，写进完成报告。
2. 先删配置和系统文件，再按「入口 → 调用方 → 界面 → 样式 → 测试 → 脚本」的顺序清理引用。
3. 把关卡数据 `js/data/levels/*.js` 的 `unlocks` 里的 `xinZhongYan`、`ruFengSiZhen` 删掉。关卡本身在 02 里精简，这里先保证不报错。
4. 存档兼容：读取 `localStorage` 进度时，过滤掉已不存在的塔类型（完整做法见 02）。
5. 用 `npx serve` 打开游戏，分别进入塔防和征服各打一关：拖塔叠到另一座塔上应该弹回，不弹融合确认；控制台零报错。
6. 跑 `npm test`（融合测试已移除），失败的用例按第 2 步继续清理。

## 风险与注意事项

- `FusionTower` 可能继承自 `Tower`，并被渲染或特效模块用 `instanceof` 判断；删除前先全局搜索 `FusionTower`、`isFusion`、`fusionType`。
- `CONFIG.TOWERS.fusion` 删除后，图鉴或卡片栏如果遍历 `CONFIG.TOWERS`，不要被空值打断。
- 有些弹窗场景是融合和其他功能共用的（如 `InkUI.setModalScene`），只删 `fusion` 这个场景，不要误删整个弹窗机制。
- 字「蛊」既是寄生塔 `parasite`，又是融合产物 `poison+poison`。只删融合产物。

- 两种模式都能正常开局和放塔，塔叠放时不触发任何融合逻辑。
- `npm test` 通过，`npm run check:line-count` 通过。
