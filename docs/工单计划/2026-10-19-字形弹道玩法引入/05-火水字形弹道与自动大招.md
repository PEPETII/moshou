# 工单 05：火、水的字形弹道与自动大招

- 总览：[00-总览](00-总览.md)（对应决策 D3、D4、D8，假设 A2）
- 依赖：03（网格和镜头分层）、04（路程系统和新敌人字段）

## 任务目标

把原型里火、水两座塔的完整表现和机制移植进正式游戏，两种模式都要支持：

- 塔身用笔画数据绘制；用掉的笔画按笔顺写回，写回的过程就是冷却；
- 火：普攻「火星」（左点、右点轮流，追踪、灼烧、暴击），大招「焚」（整字掷出，落地爆炸，留下火字焦土）；
- 水：普攻「水箭」（竖钩拉长，贯穿、击退、打湿减速），大招「潮」（三笔化浪，沿路倒卷，卷入后落下并眩晕）；
- 圆相蓄力环；蓄满后**自动释放**，没有手动入口；
- 表现形式只有字形弹道，**不移植**原型的 `plain` 对照模式。

## 当前问题/背景

- 正式游戏的火、水塔走通用的 `Tower` 攻击、投射物、渲染管线：`js/tower.js`、`js/entities/towers/combat.js`、`projectiles.js`、`rendering-basic.js`、`rendering-advanced.js`、`effects.js`。塔身用字体画字。
- 原型实现（`demo/字形弹道原型-火与水/js/`）：`brush.js`（毛笔渲染）、`towers.js`（笔画消耗、写回、蓄力、绘制、调度）、`fire.js`、`water.js`。它们依赖全局的 `World`、`FX`、`COLORS`、`TOWER_CFG`，而且**假设每种塔只有一座、位置固定**。
- 正式游戏里玩家可以放多座火、多座水，位置任意，也可以出售。

## 涉及文件

**新建（原型移植，每个文件 ≤ 600 行）**
- `js/config/glyphs.js`：`CONFIG.GLYPHS = { fire, water }`，照搬原型的笔画数据
- `js/glyph/brush.js`：照搬原型的 `Brush`
- `js/glyph/glyph-tower.js`：原型 `Towers` 的通用部分，改造成「挂在单座塔实例上」的组件（见步骤 2）
- `js/glyph/fire.js`、`js/glyph/water.js`：招式实现
- `js/glyph/adapter.js`（可选）：给原型代码提供 `World` 风格的接口，内部转调正式游戏的敌人列表、`PathTrack` 和伤害入口，尽量减少对原型代码的改动

**修改**
- `js/config/domain-02.js`：`fire`、`water` 加上原型 `TOWER_CFG` 里的全部招式参数，像素量乘 `GLYPH_SCALE`；`size: 68`；`cost` 保留 120 / 100；删除 `x`、`y`（由放置位置决定）
- `js/tower.js`：`type` 为 `fire` / `water` 时，`update` 和 `draw` 委托给字形组件，**不再**走旧的攻击和投射物管线
- `js/core/rendering.js`、`js/modes/conquest/rendering.js`：按原型的绘制顺序把字形层插进世界层：地面效果（焚后火字）→ 敌人 → 塔 → 弹道与大招 → 粒子、碎字 → 伤害数字
- `js/game.js`、`js/conquestGame.js`：维护一个全局的字形弹道列表 `glyphShots`（对应原型的 `Towers.shots`），每帧推进并绘制；塔被出售时，**已经发出的弹道继续完成**，只是不再写回笔画
- `index.html`：按依赖顺序插入新脚本，放在配置之后、`tower.js` 之前（`brush` → `glyph-tower` → `fire` / `water`）
- `js/ui/encyclopedia.js`：火、水的说明改成新的招式描述（普攻和大招各一句）

## 实施步骤

1. **配置与数据**：把笔画数据和招式参数搬进配置。参数分三类：时间、伤害、概率类照搬；像素类（`range`、`sparkSpeed`、`bombArc`、`bombRadius`、`markRadius`、`jetWidth`、`jetKnock`、`waveSpeed`）乘 `GLYPH_SCALE`；**`chargePerSec`、`chargePerHit` 照搬**。
2. **按实例改造**：原型的 `Towers.list` 每种塔只有一座；正式游戏里每个 `Tower` 实例各自持有 `strokes[]`、`charge`、`timer`、`nextDot`、`recoil`、`readyPulse`。`Towers.make` 的逻辑放到 `Tower` 构造函数里，按类型初始化。新塔放下时 `charge = 0.35`（和原型一致），并播放一次「写出整字」的动画（所有笔画 `prog` 从 0 开始，按笔顺写出）。
3. **普攻**：照搬 `FireTower.update` / `WaterTower.update` 的逻辑，只有对应笔画写满时才能发射。目标选择用「射程内最靠近终点的敌人」（`frontTarget`，按里程 `s` 最大）。征服模式是环形路径，`s` 会循环，「最靠近终点」改成「射程内 `s` 最大」即可。
4. **大招只自动释放**：
   - 射程内有敌人且 `charge ≥ 1` 时，自动调用 `cast`；`cast` 返回 `false`（没有合适落点）就等下一帧；
   - **全局大招间隔** `ULT_GLOBAL_GAP = 0.6` 秒（配置化）：任意两次大招之间至少隔这么久，避免多座塔同时爆发，导致画面过载、顿帧叠加（原型文档第 6 节的建议）；
   - 删除原型里的点塔释放、`Q` / `W` 快捷键，以及「点塔 · 焚 / 潮」提示文字；点击塔仍然打开出售面板（02 的行为）。
5. **焚（火）**：落点搜索改用 `PathTrack` 按 16px（× `GLYPH_SCALE`）采样，只在**这座塔**射程 1.15 倍以内、距入口 150px（× `GLYPH_SCALE`）以后的路段里选。巨的权重为 4。落地后的伤害、焦土、焦痕照原型实现。
6. **潮（水）**：浪头是一个里程值，从射程内最靠前的敌人前方 40px 处涌起，向来路倒卷。
   - 塔防：倒卷下限为 `80 × GLYPH_SCALE`，不把敌人推出画面；
   - 征服（环形）：倒卷下限为 `max(0, s0 - 推回距离)`，不跨过 0 点绕回；
   - 一只敌人同一时间只能被一道浪卷入（`carried` 不为空就跳过），避免多座水塔反复卷同一批敌人，把它们永久卡死（原型 4.2 第 3、4 条）。
7. **水箭充能上限**：每发水箭最多按 3 个命中计算充能（原型 4.2 第 3 条），保留。
8. **伤害与击杀**：所有伤害走正式的伤害入口，保证奖励墨、击杀音效、统计照常触发；击杀产生的墨渍、碎字等反馈在 06 里接入，本工单只预留调用点（`GlyphFX.kill(enemy, kind)`），可以先写成空函数。
9. **渲染**：塔身用 `Brush.drawGlyph` 绘制；写回中的笔画用元素色，满蓄时整字变元素色并发光（`shadowBlur` 只用在满蓄塔和飞行中的火字上，控制性能）。圆相蓄力环画在塔身外圈。射程虚线圈**只在选中塔或拖卡放置预览时显示**；原型一直显示，但正式游戏里塔多了画面会乱。
10. **放置预览**：拖卡片时，在目标格子上画半透明的火字或水字，以及射程圈。
11. **自测**：
    - 单座火、单座水分别验证四招都能触发，表现和原型截图一致（`demo/…/screenshots/01～05`）；
    - 放 3 火 3 水，「潮」档跑 60 秒：大招不会同帧扎堆，敌人不会被永久卡住，控制台零报错；
    - 出售正在蓄力或正在放大招的塔，不报错，残留弹道自然结束；
    - 镜头滚到最右边时，弹道、焦土、浪头的位置都正确。

## 风险与注意事项

- 原型代码直接读全局 `World.enemies`、`World.pointAt`、`TOWER_CFG`。正式项目里**不要**新建同名全局变量覆盖它们，通过 `adapter.js` 注入依赖，或者改成参数传入。
- 原型的 `inRange` 用 `filter` 全量扫描；塔多、敌人多时开销大，要复用 04 的空间索引。
- 旧管线（`projectiles.js` 等）中，火、水的专属分支可以删掉；**共用部分不要动**（下架塔仍然引用）。
- 字形塔在 `devicePixelRatio = 2` 下要清晰，不能只按逻辑像素绘制。
- `js/tower.js`（345 行）加上委托逻辑后，要注意不超过 600 行；如有需要，把字形相关逻辑全部放进 `js/glyph/*`。
- 按决策不做数值平衡；但如果出现「水箭推退 + 减速把敌人冻结在原地」这类**机制性死锁**，要按原型 4.2 的经验修复，这不算调平衡。

## 验收标准

- 火、水的普攻和大招表现都和原型一致，笔画消耗和写回清晰可见。
- 大招只能自动释放，全局间隔生效，没有任何手动释放入口。
- 多座同类塔并存时不报错，不会永久卡死敌人。
- 两种模式都可用；镜头在任何位置时，弹道坐标都正确。
- `npm test` 通过；已写完成报告，附 4 张截图：火星、焚、水箭、潮。
