# 工单 04：敌人改按路程移动，刷怪改为连续刷怪

- 总览：[00-总览](00-总览.md)（对应决策 D7、D11，假设 A3、A4、A5、A7、A10）
- 依赖：03

## 任务目标

1. 敌人的位置改用**路径里程 `s`** 表示，和原型的 `World` 一致，为水箭击退、「潮」倒卷提供基础。
2. 关卡的固定波次改成原型式的**连续刷怪**，开局前由玩家选择「稀 / 常 / 潮」，默认「潮」。
3. 终局改为**限时坚守**：塔防守住核心，征服把场上存活数压在危险线以下。
4. 敌人收缩为原型的三种（尸、鬼、巨），使用原型数值。

## 当前问题/背景

- 正式游戏的敌人用 `pathIndex` 加像素坐标逐点前进（`js/entities/enemy/misc.js:336-380`），速度单位是「格/秒」（`speed × CELL_SIZE`）。击退只能回退 `pathIndex`，拐角处不自然。
- 原型的做法（`demo/字形弹道原型-火与水/js/world.js`）：把路径预处理成线段表 `segs`；敌人存里程 `s`，每帧用 `pointAt(s)` 换算坐标，再沿法线加一个随机偏移 `lane`。击退就是减小 `s`；被「潮」卷入的敌人把 `s` 锁在浪头后面。
- 刷怪：塔防用 `startWave` / `spawnNextEnemy` / `checkWaveComplete`（`js/core/waves.js`），由「波次」按钮（`#start-wave`）触发。征服同理（`js/modes/conquest/waves.js`，`#conquest-wave-btn`），失败条件是存活数 ≥ `maxAliveEnemies`。
- `Game.MAX_SPAWN_COUNT = 500`、`js/objectPool.js` 对象池，需要确认它们和新上限之间的关系。
- 正式敌人数值的量级（尸 hp 5、巨尸 hp 34）和原型（尸 40、巨 300）不同，原样使用会让原型伤害一击清屏。

## 实施步骤

1. **路程系统**：实现 `PathTrack`。格子路径经 `gridToPixel` 转成点列，合并共线点后生成线段表。塔防路径的入口点向画外延伸半格，让敌人从画外走进来。
2. **速度换算**：`speed_格每秒 = 原型 px/s × GLYPH_SCALE / CELL_SIZE`。比如尸：46 × 0.74 / 72 ≈ 0.47。如果引擎已改为直接用 px/s，就按 `原型值 × GLYPH_SCALE` 计算。两种写法任选其一，但要在配置注释里写明单位。
3. **敌人改造**：
   - 生成时 `s = rnd(0, 20)`，`lane = rnd(-9, 9) × GLYPH_SCALE`；
   - 每帧：如果不在被卷入状态（`!carried`），眩晕中就减少 `stun`，否则 `s += speed × (wet > 0 ? 1 - wetSlow : 1) × dt`；
   - 坐标 = `track.pointAt(s)` + 法线 × `lane`；鬼（`float`）照原型做上下浮动；
   - 灼烧、湿身的计时和伤害合并显示逻辑按原型搬过来，伤害统一走正式的 `takeDamage`（或 `damage`）入口，保证击杀奖励、音效、统计照常触发；
   - `pushVx`、`flash` 等表现字段一起搬过来。
4. **连续刷怪**（照搬原型 `World.update` 的刷怪部分）：
   - `spawnAcc += dt × DENSITY[档位].rate`，每累计满 1 就刷一只：70% 尸、30% 鬼；
   - `giantTimer` 倒计时归零就刷一只巨，开局第一只在 4 秒后；
   - 场上数量 ≥ `ENEMY_CAP` 时暂停刷怪，**不计为失败**；
   - 开局在路径上预先铺 12 只敌人（原型是 22 只；地图更长，可以按比例调整），让塔第一眼就有目标。
5. **敌潮选择弹窗**：选关后、开局前弹出，三个按钮「稀 / 常 / 潮」，附各自的刷怪速率说明。**每次默认选中「潮」**，确认后才开始计时。暂停和继续时不再弹出。
6. **终局**：
   - 塔防：`holdTimer` 倒计时到 0 且核心血量 > 0，判定胜利；核心血量 ≤ 0，判定失败。漏怪按敌人的 `damage` 扣血（尸、鬼 1，巨 3，初值）。
   - 征服：坚守倒计时到 0，判定胜利；存活数 ≥ `CONQUEST_DANGER_LIMIT`，判定失败。
   - 胜利后，沿用原来的结算弹窗、关卡解锁和星级逻辑。星级原本按核心血量比例计算，保留即可。
7. **清理波次相关代码**：删除 `wave`、`maxWave`、`spawnQueue`、`checkWaveComplete` 的引用；HUD 上的「第 n 波」改成坚守倒计时。音效中如果有「波次开始」提示，改在开局时播放一次。
8. **分裂、召唤类敌人**（`split`、`necromancer` 等）已经不出场，它们的 `spawnEnemyAt(pathIndex…)` 调用要么改成传 `s`，要么确认不会被触发；选一种，在报告里写明。
9. **自测**：
   - 三档密度的刷怪速率肉眼可辨，满上限后停止刷怪；
   - 敌人在拐角处平滑转向，`lane` 偏移让队伍不排成一条线；
   - 塔防漏怪会扣血，坚守倒计时到 0 判胜；征服里敌人绕圈，存活数超过 200 判败；
   - 手动把一只敌人的 `s` 减小 100（控制台操作），它会沿路后退，拐角处不穿墙。

## 风险与注意事项

- 下架塔的攻击逻辑（减速、击退、冰冻等）直接改 `pathIndex` 或 `x`/`y`，改成里程制后它们会失效或出错。它们已经不出场，可以不修，但不要让共用代码因为字段缺失而崩溃。
- 对象池复用敌人时，必须重置所有新字段（`s`、`carried`、`burnStacks`、`wet`、`stun`），否则会出现「出生即眩晕」之类的残留状态。
- 260 只敌人，每帧都对所有塔做 `inRange` 全量扫描，开销会比较大。原型直接用 `filter`；正式项目已有 `RuntimeIndexes`（`js/runtime.js`），优先用它做空间分桶。
- `tests/test-frame-independence.js`、`tests/test-status-and-limits.js` 会受移动方式改变的影响，在本工单内同步修好。
- 原型「潮」档的经验数据是「40 秒击杀 248、漏 0」，但那是在 960 宽的地图上。新地图更长、塔更小，开局可能被压制。**按决策不做数值平衡**，只在报告里记下实测的击杀数和漏怪数，供以后调整参考。
