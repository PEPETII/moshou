- 日期：2026-10-19

## 2. 实施时采用的默认假设（用户未指定，可直接按此执行，并在完成报告里注明）

| # | 假设 | 理由 |
|---|---|---|
| A1 | `CELL_SIZE = 72`，`GRID_ROWS = 6`（6 × 72 = 432）；塔防 `GRID_COLS = 26`（世界宽 1872px），征服 `COLS = 22`（世界宽 1584px）。视口仍为 960×432。 | 原型文档写明笔画要 ≥72px 才清楚；72 正好整除 432。列数只是初值，集中写在配置里。 |
| A2 | 塔身尺寸 `size = 68`（原型 92，约缩为 0.74 倍）。射程、弹速、爆炸半径等**像素量**统一乘 `GLYPH_SCALE = 0.74`；时间、伤害类参数照原型。 | 满足「适度降低塔的大小」，同时保持手感比例。 |
| A3 | 胜负规则改为**限时坚守**：坚守 `holdSeconds = 150` 秒且核心血量 > 0 即胜利；核心血量归零即失败。漏怪按敌人 `damage` 扣核心血量。 | 连续刷怪没有「最后一波」，需要新的终局条件。 |
| A4 | 敌人只用原型的三种：尸、鬼、巨，属性取原型数值，速度从 px/s 换算成新网格下的速度（同样乘 `GLYPH_SCALE`）。击杀奖励墨的初值：尸 4、鬼 4、巨 25。 | 正式游戏的敌人血量（尸 5、巨尸 34）和原型（40 / 300）不是一个量级；保留原数值，原型的伤害就会秒杀一切。 |
| A5 | 场上怪物上限 `ENEMY_CAP = 260`；三档密度沿用原型：稀 1.6 / 常 3.4 / 潮 6.5 个每秒，巨每 14 / 9 / 5 秒刷一个。 | 满足 D7 的「拉高上限」；具体数值以手机实测帧率为准，可以下调。 |
| A6 | 打击反馈的开关持久化到 `localStorage` 键 `moshou_hit_feedback`（`'on'`/`'off'`，缺省为 `'on'`）。设置页里的「墨迹动效」关闭，或系统开启「减少动态效果」时，即使反馈开着，**也不震屏**。 | 和现有的 `ink-motion` 设置保持一致。 |
| A7 | 敌潮档位**每次开局都默认选「潮」**，不记住上一次的选择。 | 按 D7 的字面要求实现。 |
| A8 | 主菜单的「自定」入口**暂时隐藏**，代码不删。 | 自定塔、自定关卡依赖旧塔体系和旧网格，不在本次实验范围内。 |
| A10 | 征服模式的路径是沿边框的**环形回路**，敌人走不到核心，失败条件是「场上存活数 ≥ `maxAliveEnemies`（现为 50）」。这条规则保留，阈值改成 `conquestDangerLimit = 200`；胜利条件与 A3 相同，坚守 150 秒。在征服模式里，A5 的 `ENEMY_CAP` 只作为性能上限。 | 连续刷怪加上原阈值 50，「潮」档开局约 8 秒就会失败。 |
| A9 | 征服模式保留「召唤」：召唤池只有火、水。去掉融合以后，「内圈满了先融合」的提示改为「先出售腾出位置」。 | 召唤是征服模式的核心入口，不宜一起删掉。 |

如果实施中发现某条假设明显不可行，在对应完成报告里说明改了什么、为什么改。

## 4. 原型 → 正式项目的模块映射（建议）

原型用的是全局对象加 IIFE，和正式项目的脚本组织方式一致，可以直接移植，**不得引入构建工具**。

| 原型文件 | 正式项目落点（新建） | 说明 |
|---|---|---|
| `js/data.js` 的 `GLYPHS` | `js/config/glyphs.js` | 笔画数据，注册到 `CONFIG.GLYPHS` |
| `js/data.js` 的 `TOWER_CFG` / `DENSITY` / `ENEMY_TYPES` / `COMBO_MARKS` | 并入 `js/config/domain-02.js`（火、水）和新文件 `js/config/glyph-battle.js` | 数值要集中配置，禁止散落 |
| `js/brush.js` | `js/glyph/brush.js` | 基本照搬 |
| `js/fx.js` | `js/glyph/fx.js` | 照搬，再接入设置开关、动效开关和倍速 |
| `js/towers.js` | `js/glyph/towers.js` | 通用笔画消耗、写回、蓄力，接到正式的 `Tower` 实体上 |
| `js/fire.js` / `js/water.js` | `js/glyph/fire.js` / `js/glyph/water.js` | 招式实现 |
| `js/world.js` | 拆进 `js/entities/enemy/*` 和新文件 `js/core/path-track.js` | 路程系统、伤害结算接入正式的 `Enemy` |
| `js/app.js` | 不搬 | 主循环和输入以正式项目为准；顿帧逻辑接进 `game.js` 的主循环 |

每个文件不超过 600 行；新脚本要按依赖顺序加进 `index.html`（以及 `scripts/build-h5-zip.py` 的打包清单，如果它枚举了脚本）。

## 5. 全局验收标准

1. 主菜单 →「塔防」/「征服」→ 选关 → 选敌潮（默认「潮」）→ 开局，整个流程能跑通，控制台零报错。
2. 每种模式各有 2 关，都能打到胜利或失败，并正确结算。
3. 商店（卡片栏）里只有「火」「水」，能花墨放置、能出售，没有升级入口。
4. 火：火星会追踪并叠灼烧；火的大招「焚」整字掷出、落地炸开、留下火字焦土。水：水箭会贯穿、击退、打湿；水的大招「潮」沿路倒卷、眩晕。大招只会自动释放。
5. 网格每格 72px，地图比视口宽；鼠标滚轮、键盘、拖拽、屏幕边缘都能左右滚动镜头，手机横屏也能操作。
6. 设置页有「打击反馈」开关，默认开，刷新后仍记得上次的选择。
7. 全仓库搜索不到融合系统的残留（`fusionSystem`、`FUSION_TOWERS`、`fuseTowers`、`btn-fusion` 等）。
8. `npm test` 全部通过（测试集按 07 调整）；`npm run check:line-count` 通过。
9. 手机横屏、「潮」档、怪物数量到上限时，帧率不低于 45fps；达不到就下调 `ENEMY_CAP`，并写进完成报告。
