- 日期：2026-10-19
- 范围：塔防、征服两种模式的**战斗中界面**
- 现状截图：[现状-塔防-1-1.jpg](assets/2026-10-19-战斗界面水墨视觉统一/现状-塔防-1-1.jpg)

## 1. 任务目标

把顶部 HUD、中部地图、底部塔栏（征服模式是左侧侧栏和地图）统一成一幅水墨画面：

1. 共用宣纸底纹，栏与地图之间以墨晕过渡，没有生硬的分割线和色块边界；
2. 按钮和数值面板做成淡墨底、飞白笔触边框，选中态用朱砂印章；数字清晰可读；
3. 地图路径分出深浅墨线和淡彩晕染，有远近层次；左下等大块空白处用山石和留白点缀，但不遮挡路径和可交互区域；
4. 色调以墨黑为主，辅以青灰（水）、朱红（火）、淡赭（尸）；
5. 各信息的相对位置不变，只调整间距和对齐；
6. 各分辨率下都可读，**点击区域不变**。

## 3. 当前问题/背景（已核对代码）

**三块割裂的原因**
- 顶栏和底栏是 DOM：`js/bootstrap/page-markup.js:268-320`（`#top-bar`、`#game-area`、`#bottom-bar`），征服模式在 `:322-367`（`#conquest-side-panel`、`#conquest-game-container`）。
- 栏是纯色底 `var(--ink-paper)`，直接用 1px 线分隔：`css/ink-ui/battle.css:9-16`（`border-bottom`）、`:49-56`（`border-top`）、`:253-258`（征服侧栏 `border-right`）。
- 地图的宣纸是画布里画的：`js/mapBackground.js:95-135` 的 `paintPaper`（纤维、茶渍），**结尾按世界尺寸加了一圈暗角**（`:129-134`）。地图因此像一张贴在纸上的深边卡片。
- 镜头左右边缘提示：`js/core/camera.js:252-283` 的 `drawHints`，用的是纯黑渐变，加上位置条（墨灰轨道、朱红滑块）。
- 画布左上角的关卡名用 `14px Microsoft YaHei` 绘制（`js/core/rendering.js:354-365`），字体和整体风格不一致。

**扁平的原因**
- 顶栏和征服侧栏按钮：`battle.css:135-160`，透明底，只有一条 1px 底线，并用了 `!important`。
- 塔卡：`battle.css:57-121`，透明底，只有底线；选中态是右上角一个 19px 的「选」字小框（`:92-103`）。
- 数值用 `Ma Shan Zheng` 22px 书写（`battle.css:23-26`），书法数字辨识度一般。

**空旷的原因**
- 地图装饰只有远山（`paintMountains`，沿底边、透明度 0.03～0.055）和随机苔点（`paintMoss`，半径 1～3px）；面积大的空白区域没有任何构图元素。
- 征服模式每帧画纯色底和 `inkRenderer.drawDistantMountains`（`js/modes/conquest/rendering.js:79-100`），没有使用 `MapBackground` 的缓存地形；网格常显（`drawGrid`，`:132`）。

**样式层叠**：`css/style.css` → `css/inline.css` → `css/ink-ui.css`（依次 `foundation`、`pages`、`battle`、`audio`、`mobile`）。`battle.css` 和 `part-0x.css` 里有大量 `!important` 和触屏特化规则；`mobile.css` 负责手机端最小字号（`--fs-min`，依赖 `--ui-scale`）。

## 4. 设计规范

### 4.1 色彩（单一来源）

CSS 变量放在 `css/ink-ui/foundation.css` 的 `:root`；画布侧的同名色值放在 `CONFIG.COLORS`（`js/config/domain-03.js:310` 起）。两边都要加注释「与另一处保持一致」。

| 变量 | 值（初值，可微调） | 用途 |
|---|---|---|
| `--ink-paper` | `#f4efe4`（不变） | 宣纸底，三块区域共用 |
| `--ink-strong` | `#1c1a17`（不变） | 主墨：文字、数值、深墨线 |
| `--ink-soft` / `--ink-faint` | 不变 | 标签、次要文字 |
| `--ink-wash` | `rgba(28,26,23,0.06)` | 淡墨底（按钮、面板） |
| `--ink-wash-strong` | `rgba(28,26,23,0.11)` | 悬停态 |
| `--tint-water` | `#5f7884`（青灰） | 水塔卡点缀、水相关数值、路径淡彩 |
| `--tint-fire` | `--ink-seal` `#b4473a`（朱红） | 火塔卡点缀、选中印章、核心 |
| `--tint-ochre` | `#a88a62`（淡赭） | 「尸」计数、敌潮相关提示、敌人脚下的晕影 |

彩色只做点缀，总面积不超过画面的 10%。正文和数值一律用墨色。

### 4.2 纹理资产（新建，纯 SVG 数据 URI，与分辨率无关）

新建 `css/ink-ui/ink-texture.css`，只定义变量，不写选择器规则：

- `--tex-paper`：`feTurbulence` 生成的纤维噪点，叠加在 `--ink-paper` 上，颗粒密度和 `paintPaper` 接近；
- `--tex-wash-edge`：一条不规则的横向墨晕带（上实下虚），用作栏与地图交界处的晕染；征服侧栏用竖向版本 `--tex-wash-edge-v`；
- `--tex-brush-frame`：飞白笔触边框，四边粗细不均、带枯笔断口，用作 `mask-image` 或 `border-image`；
- `--tex-seal`：朱砂印章外框，略有缺口和斑驳。

### 4.3 组件规范

| 组件 | 规范 |
|---|---|

| 顶栏 `#top-bar`、底栏 `#bottom-bar`、征服侧栏 | 透明底，去掉 1px 分隔线；交界处用 `::after` / `::before` 贴 `--tex-wash-edge` 墨晕带：高 10～14px，透明度 ≤ 0.18，`pointer-events: none`。墨晕带画在栏自己的盒子内，不能盖到画布上。 |
| 数值组（墨 / 守时 / 尸 / 守） | 标签用书法字（`Ma Shan Zheng`，墨淡）。数值改用 `ZCOOL XiaoWei` 加 `font-variant-numeric: tabular-nums`，避免数字跳动时宽度抖动，字号不小于现在。每组下方加一笔淡墨横皴（`::after`，飞白），代替底线。「尸」的标签用 `--tint-ochre`。 |

| 塔卡 `.tower-select` | 淡墨底方纸加飞白边框；「火」字用墨写，下方墨价用 `ZCOOL XiaoWei`。火卡左下点一抹朱红晕，水卡点一抹青灰晕（伪元素，面积小）。**选中态**：整张卡外围盖一方朱砂印框（`--tex-seal`，旋转 -4°），并在原「选」字位置换成一枚小朱印。**墨不够**（`.locked`）：卡面变淡、印「墨乏」。卡片尺寸保持 62×70 不变。 |

### 4.4 地图层次（只改绘制，不改数据）

**分层**（从远到近，都在缓存里）：

1. **宣纸**：`paintPaper`，**去掉按世界尺寸绘制的暗角**（改由 DOM 统一绘制，见 4.3）。
2. **远景**：远山改为 2～3 层叠加。最远一层用青灰淡彩（透明度 0.03～0.05），近一层用淡墨；高度不超过画布的 18%，只出现在底边和不靠路径的区域。
3. **中景点缀（新增，解决空白）**：见下面的布局算法，内容是山石皴擦、几笔兰草或枯枝、一方留白题字区（例如一枚很淡的闲章）。
4. **路径墨廊**：
   - 外晕：现有的大半径模糊淡墨，叠一层极淡的青灰（路像被水汽洇过）；
   - 路面：现有三层淡墨保留，按路段**远近**分深浅：入口段较淡，越靠近核心或出口越浓，沿路径里程线性插值，透明度差别控制在 ±30% 以内；
   - 边线：两侧各一条细墨线，粗细有起伏，并有飞白断口（替代现在的「飞白边」）；
   - 行进箭标：保留，颜色改为墨色 40%。
5. **网格**：只在放置状态出现（现有行为）；线色用 `--ink-grid`，交叉点加一个小墨点，增加「格」感。
6. **入口、核心**：「入口」字样改用书法字体，旁边加一方淡墨小印；核心沿用现有绘制，仅统一配色。

**空白装饰布局算法**（`MapBackground` 内新函数，例如 `paintScenery`）：

- 输入：路径格子、世界列数和行数、`cell`；
- 计算「禁区」：所有路径格，以及路径格周围 1 格（切比雪夫距离 ≤ 1）；另外，世界左右边缘各 0.5 格不放装饰，避免和镜头提示叠在一起；
- 在禁区之外，找出面积 ≥ 3×2 格的空白矩形块（贪心，从最大的开始），**每块放一组**点缀，整张地图最多 4 组；
- 每组的元素尺寸按块大小缩放，主体放在块内靠下的 2/3，留出上方空白（「留白」）；
- 透明度：主体 ≤ 0.16，皴擦细节 ≤ 0.10。这些格子仍然可以放塔：塔、网格、放置预览都画在装饰之上；放置状态下网格清晰可见（验收时要截图核对）；
- 用固定随机种子（按关卡 ID 派生），同一关每次进入画面一致；
- 结果进入 `terrainCanvas` 的缓存，缓存键加上「装饰版本号」。

## 8. 风险与注意事项

- **`!important` 冲突**：`battle.css` 和 `style/part-0x.css` 的旧规则大量使用 `!important`。在新文件里叠加更高优先级很容易漏掉触屏分支（`html[data-input="touch"]`），应当删掉旧规则，而不是继续叠。
- **缩放下的纹理**：整个战场在 `#scale-container` 的 `transform: scale()` 之下，SVG 纹理和 `mask-image` 会随之缩放，与分辨率无关；**不要用 PNG 纹理**，否则高分屏上会糊。
- **墨晕带越界**：墨晕带必须留在栏的盒子内，不能叠在画布上，否则会盖住第 0 行和第 5 行的格子。
- **画布和 DOM 的纸纹不完全连续**：画布里的宣纸随镜头移动，DOM 纸纹是固定的。靠「同底色 + 颗粒密度相近 + 交界墨晕」消除接缝，不追求像素级连续。另一个方案是画布不画纸、透出 DOM 纸纹，但那样滚动镜头时，路径会像在玻璃上滑动，所以不采用。
- **征服模式改用缓存地形**：要确认 `RenderScale` 倍率变化时，缓存键会随之更新（`terrainCanvas` 的键已包含 `scale`）。
- **装饰与可读性**：「潮」档敌人密集时，背景装饰太浓会干扰辨识，透明度上限要严格遵守（4.4）。
- **文件行数**：`mapBackground.js` 必须先拆分再加功能；`battle.css`（401 行）删除旧规则后行数会下降，新规则放进 `scene.css`。

## 9. 验收标准

1. 三种分辨率的截图里，顶栏、地图、底栏（以及征服侧栏）之间没有可见的直线分隔和色块边界，看起来是同一张宣纸。
