# 工单：数值修复二 —— A2 路径阻挡塔每帧拆除 + A4 阵光环帧率相关

日期：2026-10-17　来源：审计报告 A2、A4（用户已确认继续）

## 任务目标
1. A2：被阻挡的敌人对路径塔的伤害改为按时间间隔结算（新增 `CONFIG.GAMEPLAY.blockAttackInterval`，初值 800ms），与帧率无关。
2. A4：阵(formation)的 dot 光环改为按 dt 累计，伤害归零时走 `die()`，与帧率无关。

## 当前问题/背景
- `Enemy.checkBlocking` 每帧调用 `tower.takeDamage(this.damage)`：壁(42HP)被 1 伤敌人 0.7s 拆除（60fps），144fps 下 0.29s。
- `Tower.updateAura` 的 dot 为 `hp -= auraValue/60`：伤害与帧率成正比，且不调用 `die()`，负血敌人继续走到核心。

## 涉及文件
- `js/config/domain-03.js`（GAMEPLAY 新增常量）
- `js/entities/enemy/combat.js`（checkBlocking）、`js/enemy.js` 与 `js/entities/enemy/misc.js`（两份 update 调用点）
- `js/entities/towers/effects.js`（updateAura）、`js/tower.js` 与 `js/entities/towers/misc.js`（update 调用点）
- 回归测试：扩展 `tests/test-damage-resolution.js`

## 实施步骤
1. 配置新增 `blockAttackInterval: 800`。
2. `checkBlocking(deltaTime)` 用累加器 `_blockAccum`；换目标/脱离阻挡时清零。
3. `updateAura(deltaTime)` 的 dot 用 `auraValue × dt/1000`，`hp<=0` 调 `die()`。
4. 测试：30/60/144fps 下拆除时间与 dot 伤害一致；负血敌人被击杀并给奖励。
5. 重跑审计微观脚本与 49 关模拟，记录基线变化。

## 风险与注意事项
- 路径塔会比现在耐久得多（壁 vs corpse 约 34s），整体难度下降；本工单只改机制与新增常量，不调塔数值。
- 敌人 `update` 与 `Tower.update` 各有两份副本，必须同步。
- 单文件 ≤600 行。

## 验收标准
- 同一场景不同帧率下拆除时间差 <5%、dot 伤害差 <5%。
- dot 致死的敌人 `dead=true` 且获得奖励，不再走到核心。
- `npm test`（除既有 balance 未通过项外）通过。
