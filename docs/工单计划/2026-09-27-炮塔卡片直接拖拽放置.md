# 工单：炮塔卡片直接拖拽放置

- **日期**：2026-09-27
- **类型**：交互改造
- **优先级**：P1

## 1. 任务目标

将主游戏炮塔放置改为“从底部卡片按下并拖入战场，松手建造”。鼠标、触控笔和触屏统一使用 Pointer Events；卡片单击不进入待放置状态。保留已有炮塔的信息查看与拖拽融合行为。

## 2. 当前问题与背景

- `js/ui/menu.js` 当前用卡片 `click` 设置 `selectedTowerType`。
- `js/ui/input.js` 的 Canvas `click` 及 `js/ui/input-touch.js` 的 `touchend` 都支持基于 `selectedTowerType` 建造，形成两套放置入口。
- `js/core/towers.js` 已提供放置限制、失败原因和扣墨逻辑；`js/core/rendering.js` 已绘制合法格、非法格和攻击范围。
- 已有炮塔融合使用独立的 `draggingTower`，本任务不复用或改变该状态机。
- 修改前基线：`npm test` 退出码为 0；其中余额脚本输出部分既有平衡阈值未达标，本任务不涉及数值。

## 3. 涉及文件

- `js/ui.js`
- `js/ui/menu.js`
- `js/ui/input.js`
- `js/ui/input-touch.js`
- `js/core/rendering.js`
- 新增主游戏炮塔放置交互回归测试，并接入 `package.json` 的 `npm test`
- `docs/完成报告/` 下新增对应完成报告

## 4. 实施步骤

1. 为新炮塔拖放建立独立 `placementDrag` 状态，按 `pointerId` 捕获指针且不借用 `draggingTower`。
2. 将卡片点击选中改成 Pointer Events 拖放；拖动时更新网格坐标、合法性预览及触点上方的半透明炮塔幽灵。
3. 让 Pointer `up` 仅在战场内调用显式类型参数的 `tryPlaceTowerAt(gx, gy, type)`；场外松手取消，结束后清空拖放状态并抑制合成 Canvas 点击。
4. 移除鼠标与触屏 Canvas 点击建造分支；Canvas 点击只查看炮塔或清空信息面板。
5. 复用现有 `getPlacementBlockReason`、`canPlaceTower`、`placeTower` 与融合拖拽逻辑。
6. 新增覆盖放置边界和融合状态隔离的自动化测试，运行相关测试及项目验证命令。

## 5. 风险与注意事项

- 触摸底栏保留既有 `pan-x` 横向滚动；纵向拖放被浏览器取消时必须清理状态。
- Pointer `cancel`、场外释放和墨水实时变化都必须清理状态且不能扣墨。
- 山字塔仍只能放路径格；普通塔仍只能放 `_placementGridSet` 中的合法格。
- 代码文件保持在 600 行以内，不改变任何炮塔数值，不重写融合逻辑。

## 6. 验收标准

1. 鼠标与触屏都能从卡片拖到合法格并立即建造、扣墨；卡片单击不建造、不保留选择态。
2. 拖动时合法格为绿色并显示攻击范围，非法格为红色；触屏幽灵预览高于手指约 40–60 CSS px。
3. 松手在场外不建造、不扣墨；占用格、非法格和墨水不足显示现有原因。
4. 山字塔只允许路径格，普通塔只允许合法放置区域。
5. 放置结束后状态清空，后续 Canvas click 不触发额外选择或建造。
6. 已有炮塔的融合拖拽仍走 `draggingTower` 且行为不变。
7. 相关测试通过；完整验证如有既有失败需区分并记录；修改文件均不超过 600 行。
