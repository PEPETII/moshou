# 工单：字形弹道交互原型（火 / 川 / 山 + 弓范例）

- 日期：2026-10-17
- 类型：设计验证型原型（不改动正式玩法代码）
- 状态：进行中

## 1. 任务目标

新建一套**独立的、可直接双击打开**的 HTML 交互原型，用「火、川、山」三座炮塔（另附「弓」作为原始范例）演示「字形即弹道」这一攻击方式改造：

> 字是炮塔，笔画是动作，笔顺是时序，字形是弹道，笔锋是命中反馈。

原型目的是**决策验证**，不是正式功能：确认「玩家能否只凭字形预判攻击方式、轨迹与命中逻辑」，以及手感、节奏、可读性是否达到预期。

## 2. 当前问题 / 背景

现网炮塔的攻击表现以「塔型 + 弹体贴图」为主，攻击方式与塔的视觉符号（字）之间没有必然联系，玩家无法从字形推断行为。拟改造为「字形驱动弹道」，但存在三个不确定点：

1. **可读性**：字身若随朝向旋转会失去辨识度，改用「字身不动 + 出锋方向」是否能被看懂；
2. **形义一致**：字形结构 → 弹道几何的映射是否直观（不用读说明就能猜中七八成）；
3. **笔顺即时序**：把字拆成逐笔动画充当攻击节奏，是否成立、是否会显得拖沓。

## 3. 设计要点（本原型要落实的规则）

- 原则①可读性优先：字身始终正写，只转「出锋方向」；笔画、笔锋、墨迹朝目标展开。
- 原则②形义一致：字形结构直接决定弹道几何。
- 原则③笔顺即时序：起笔蓄力 → 行笔发射 → 收笔后摇 → 回锋冷却，每写完一笔触发该笔对应的弹丸。

## 5. 实施步骤

1. 建工单（本文件）。
2. 定义字形笔画数据：`火`（4 笔，放射）、`川`（3 笔，并列）、`山`（3 笔，三峰）、`弓`（3 笔 + 隐含弦）。
3. 实现水墨渲染基元（笔锋粗细曲线 + 飞白断笔 + 墨晕 + 宣纸底纹）。
4. 实现「字形 → 弹道」的几何推导：
   - 笔画走向 = 弹道方向；
   - 笔画字距 = 平行弹道间距；
   - 峰高 = 抛投弧高。
5. 实现笔顺驱动攻击循环（逐笔书写 → 逐笔发射）。
6. 装配原型界面：主画布 960×432、字形解剖面板、弹道规则卡、三原则说明。
7. 用无头画布渲染截图做视觉校验，修正比例与可读性。
8. 写完成报告。

## 6. 风险与注意事项

- **字体依赖**：不用系统字体渲染字形，全部用预定义笔画折线绘制，避免环境缺字导致字形失真。
- **性能**：笔锋按段描边，单字约 50 段 × 4 塔，需控制在可接受范围内；静态底图预渲染缓存。
- **不污染正式工程**：仅新增 `demo/` 目录，不接入 `index.html`、不改 `CONFIG`、不影响 `npm test`。
- **行数限制**：按 600 行上限拆分文件，避免超限。
- **文件协议**：使用传统 `<script>` 而非 ESM，保证 `file://` 双击可用。

## 7. 验收标准

1. 双击 `demo/glyph-trajectory-demo.html` 可正常运行，无控制台报错。
2. 四座塔能自动索敌开火，且**每写完一笔才出一发**，笔顺与弹丸顺序一一对应。
3. 字身始终正写，改变出锋方向时字不旋转、只有弹道与笔锋转向。
4. `火`呈扇形散射、`川`呈三条平行贯穿、`山`呈三点抛投、`弓`呈蓄力贯穿，四者不看文字说明即可区分。
5. 点击塔可在右侧「字形解剖」看到逐笔拆解与笔顺编号。
6. 无 600 行以上文件。
