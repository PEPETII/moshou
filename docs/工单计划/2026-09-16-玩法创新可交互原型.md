# 工单：玩法创新方案可交互原型（HTML 演示）

## 任务目标
在项目根目录新建独立文件夹，为 `docs/玩法创新方案.md` 中的六个玩法思路各制作一个**可交互的独立 HTML 原型**，并附一个总入口页。目标是让设计思路"能被看见、能被点击"，而不是只停留在文字描述。

## 当前问题/背景
- 纯文字方案难以传达交互体验，评审效率低。
- 六个方案（字格营造 / 句读改径 / 语法羁绊 / 墨为血 / 对句波次 / 错别字入侵）分别改动塔防的不同维度，差异需要可视化对比。
- 现有游戏入口为 `index.html`，Canvas 游戏区 960×432（20 列 × 9 行，`CELL_SIZE = 48`），本项目为纯静态前端、无构建工具。

## 涉及文件
新建（不修改任何现有游戏代码）：
- `prototypes/README.md`
- `prototypes/index.html`（总入口导航）
- `prototypes/01-字格营造.html`
- `prototypes/02-句读改径.html`
- `prototypes/03-语法羁绊.html`
- `prototypes/04-墨为血.html`
- `prototypes/05-对句波次.html`
- `prototypes/06-错别字入侵.html`

文档：
- `docs/完成报告/2026-09-16-玩法创新可交互原型.md`

## 实施步骤
1. 建立 `prototypes/` 目录，六个页面各自独立自包含（CSS/JS 全部内联），双击即可打开，不依赖服务器与任何外部资源。
2. 视觉体系统一：白纸底 + 墨黑字 + 朱砂红点缀 + 水墨笔触（对齐游戏既有美术方向），字体走楷体族。
3. 每个页面固定三段式结构：
   - 顶部：方案名 + 一句话主张 + 该方案攻击的塔防支柱；
   - 中部：Canvas 可交互演示区（核心，鼠标可直接操作）；
   - 底部：机制说明 + 与现有代码的对接点说明。
4. 每个页面的演示必须"可操作"，而非静态截图式画面：至少提供一个鼠标交互动作，并能看到即时反馈。
5. `index.html` 作为导航页，卡片式列出六个方案及其评分，点击进入对应原型。
6. 用 Playwright 截图校验六个页面渲染无 JS 报错、无布局溢出。

## 风险与注意事项
- **不触碰游戏代码**：仅新增 `prototypes/` 目录，`index.html`、`js/`、`css/` 保持零改动，不影响 `npm test` 与现有平衡性基线。
- 单文件行数控制在 600 行以内（遵守 AGENTS.md）；如某原型超出，需拆分逻辑而非压缩代码。
- 禁止引入构建工具、TypeScript、外部 CDN 资源（离线可用）。
- 原型中的数值仅用于演示效果，不代表最终平衡数值。

## 验收标准
- `prototypes/` 下六个 HTML + index 均可独立打开，无控制台报错。
- 每个页面至少有一个有效的鼠标交互，交互后画面有明确变化。
- 页面在 1280px 及以上宽度下无横向溢出、无内容裁切。
- 未修改 `prototypes/` 以外的任何文件（`docs/` 新增文档除外）。
- `npm test` 保持通过。
