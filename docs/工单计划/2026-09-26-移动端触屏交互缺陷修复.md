# 工单：移动端触屏交互缺陷全面修复

- **日期**：2026-09-26
- **类型**：交互/适配缺陷修复（P0 阻断级 + P1 体验级）
- **优先级**：P0
- **适用平台**：移动端浏览器 / TapTap 小游戏（H5 横屏）—— 本项目唯一目标平台

---

## 1. 任务目标

项目定位为移动端游戏（`docs/ui-design-spec.md:6` 明确"适用范围：TapTap 小游戏（H5 横屏）、移动端浏览器"），
但前序 AI 代理按桌面端假设实现交互，导致移动端存在"操作不可用/不可预期"的缺陷。
本工单目标是：**让操作与交互符合移动端触屏预期，且不改变任何游戏数值与玩法规则。**

## 2. 当前问题/背景

### 2.2 缺陷清单（均为实测确认）

**A. 触屏几何不达标（违反自身规范）**
`docs/ui-design-spec.md:49` 规定"所有可交互元素最小触控区域 44 × 44px"。实测渲染后尺寸：

| 元素 | 实测（CSS px） | 规范 |
|---|---|---|
| 塔卡 `.tower-select` | 30.5 × 38.2 | 44 × 44 |
| 顶部"融合图鉴" `#fusion-encyclopedia-btn` | 49.6 × **15.9** | 44 × 44 |
| 顶部"主菜单" `#back-to-menu-btn` | 42 × 28 | 44 × 44 |
| 波次按钮 `#start-wave` | 50.9 × 28 | 80 × 44 |

根因：`css/style/part-02.css:189` 的 `@media (pointer: coarse)` 把目标声明为 44px，
但整棵游戏树在 `#scale-container` 上被 `transform: scale(0.636)` 整体缩小，
**CSS px 声明会连同缩放一起被缩小**，44px 实际渲染为 28px。该"触摸优化"在架构上失效。

**B. 放置预览功能 100% 依赖 hover**
`js/core/rendering.js:211` 的 `drawPlacementPreview` 以 `ui.hoveredCell` 为唯一输入；
`hoveredCell` 只在 `mousemove`（`js/ui/input.js:3-11`）与 `touchmove`（`input.js:60-73`）中赋值。
触屏"轻点放置"（无位移）永远不会经过 `touchmove`，因此：
- 实测：选中塔卡后 `ui.hoveredCell === null`，**手指按住不放也不出现任何预览**；
- `Game.canPlaceTower` 为假时 `placeTower`（`js/core/towers.js:24-40`）静默 `return false`；
- 实测"金币不足点击放置"：塔 0 → 0、金币 50 → 50、通知节点 **0 个** → **完全无反馈**；
- 实测"点已有炮塔的格子"：金币花费 **0**、通知 **0 个** → **完全无反馈**。

即：移动端正反馈与负反馈同时缺失，玩家视角等于"点了没反应"。

**C. 手指自然抖动直接导致放置失败**
`this.dragThreshold = 5`（`js/ui.js:16`）是鼠标参数。实测：手指按住后抖动 **6px** 再抬起 →
`isDragging=true` → `touchend` 走拖拽分支 → **落子失败**（塔数不变）。
触屏常规 slop 应为 ~10–12px。同理 `touchmove` 无条件 `clearTimeout` 长按定时器（`input.js:132-143`）：
实测"长按静置 600ms"能显示炮塔信息，**"长按期间抖动 8px"则完全不显示** → 长按查看信息在真实手指下失效。

**D. 无"滑动取消"逃生，且落点取抬起点**
`js/ui/input.js:78-100` 直接以 `changedTouches[0]` 落塔。
实测：在 A 格(2,6) 按下 → 滑到 B 格(12,2) → 抬起 → **塔落在 B(12,2)**。
玩家按错想滑开取消，反而在别处花了钱。

**E. 取消选中只有右键一条路**
`js/ui/input.js:44-51` 用 `contextmenu` 取消；`js/ui/panels.js:94-102` 硬编码提示文案
**"右键取消选择"**（实测读取到该字符串）。触屏无右键。
实测：已选塔卡后点画布空白处 → `selectedTowerType` 仍为 `water`、卡牌仍高亮 → **无取消路径、无反馈**。

**F. 触屏零按压反馈 + 零 `hover:none` 分支**
全量扫描 8 个 CSS 文件：`:hover` 规则 58 处，`@media (hover: none)` 分支 **0 个**；
`:active` 仅覆盖 `.tower-select / .menu-btn / .menu-level-item`（`part-02.css:216-218`）。
而 `html,body` 已设 `-webkit-tap-highlight-color: transparent`（`part-01.css:35`），
即"系统默认的点击高亮被去掉，替代反馈又没写" → 图鉴卡片、筛选标签、关卡项、主题卡点击后全无确认。

**G. 缩放基准与实际布局不一致**
`js/bootstrap/viewport.js:4-8` 用固定 `TOTAL_GAME_WIDTH=1264 = 280+24+960` / `GAME_HEIGHT=480`：
1. 塔防模式实际内容宽 960（无侧栏），却按 1264 计算 → **无谓缩小 24%**；
2. 实际容器高 ≈562（顶栏 57 + 画布 432 + 底栏 69 + 边框），却按 480 计算 → **高估可用高度，导致上下裁切**；
3. 横屏 CSS 把 `#game-container` 限制为 `max-width: 800px`（`part-02.css:86-89`）而 `#game-area` 固定 960px
   → 画布比顶栏/底栏宽 166.7px（实测），**顶栏底栏与战场错位**；
4. 该缩放只在 `load` 时计算一次，**塔防 ↔ 征服模式切换时不重算**。

**H. 塔信息面板盖在手指下**
`js/ui/panels.js:139-157` 以触点坐标定位面板（实测 `coversFinger: true`），
面板按钮 `padding:8px; font-size:13px`（`part-01.css:464-474`）实际高度 44px（有 coarse 兜底），但面板本身正好被手指压住。

**I. 金币不足的锁定卡点击无解释**
实测点击 `.tower-select.locked` → 不选中、无任何提示、无 `title`、无可见原因文案。

**J. 底栏 38 张卡牌需横向滑动**
静态 markup 只有 8 张，但 `createTowerSelects()`（`js/ui/menu.js:2-49`）按
`getUnlockedTowers()`（返回**全部** 38 座塔）重建 → 实测 `scrollWidth 2062 / clientWidth 696`，
仅 **12 张**完全落在可视区内 → 移动端要滑 3 倍宽度才能找到目标塔，且触屏下无滑动提示。

**K. 缺 `touch-action` 与安全区适配**
实测 canvas 与 `#bottom-bar` 的 `touch-action` 均为 `auto`；全项目 `grep safe-area` **0 命中**
→ 横屏刘海机型左右被裁、canvas 手势与浏览器默认手势可能竞争。

**L. 桌面专属输入残留**
`document` 级键盘快捷键（数字键开波、`S` 召唤）在触屏无意义；`js/ui/notifications.js:95-96` 用
`onmouseover/onmouseout` 做按钮反馈；`page-markup.js:349/352/420` 用 `title` 属性当提示（触屏不显示）。

## 4. 实施步骤

1. 新建 `js/bootstrap/device-profile.js`，在 `viewport.js` 之前加载。
2. 重写 `js/bootstrap/viewport.js`：
   - 可见根元素取 `#conquest-container`（未隐藏时）否则 `#game-container`；
   - 迭代求 scale（渲染后目标尺寸反算会改变实测尺寸，需收敛迭代）；
   - 可用空间扣除安全区；
   - 暴露 `window.applyGameScale`，并在 `startGame` / 征服模式启动 / 返回菜单时重算。
3. 新增 part-05 CSS：
   - 修掉横屏 `#game-container{max-width:800px}` 与固定 960px 画布的冲突；
   - `@media (hover: none) and (pointer: coarse)`：`min-height/width: calc(44px / var(--ui-scale))` 反算触控尺寸；
   - `:active` 按压反馈覆盖所有可点元素；
   - `touch-action`：canvas `none`、底栏 `pan-x`、按钮 `manipulation`；
   - 安全区变量与 `#game-wrapper` 内边距；底栏滑动提示。
4. 新增 `js/ui/toast.js`，节流去重。
5. `js/core/towers.js` 增 `getPlacementBlockReason`。
6. 抽出 `js/ui/input-touch.js` 并实现新触摸流程：
   - `touchstart`：命中格 + 容差选塔；若已选塔类型 → 立即置 `hoveredCell`（**按住即预览**）；
   - `touchmove`：位移 > slop（12px）才判为拖拽/滑动；长按期间允许抖动；
   - `touchend`：拖拽 → 融合；位移 > slop → **滑动取消**；干净轻点 → 命中塔显示信息 / 已选类型则按**按下点**落子（失败给原因）/ 否则取消选中；
   - 放置使用按下格（非抬起格），选塔使用容差（无副作用，宽容）。
7. `js/ui/panels.js`：触屏下取消文案改为"点击空白处取消"，面板定位上移到触点上方并做边界收敛。
8. `js/modes/conquest/misc.js`：slop 与滑动取消同步。
9. 复核行数：新增/修改文件均 < 600 行（`npm run check:line-count`）。
10. 用 Chromium 在 844×390 / 740×360 / 1440×900 三档重测，与 §2.1 基线对比。
11. 运行 `npm test`。

## 5. 风险与注意事项

- **几何硬约束**：20 列 × 9 行 = 960×432 的战场，在 390px 高的手机上单格上限约
  `(390 - 顶栏 - 底栏)/9 ≈ 31px`，**物理上不可能达到 44px**。
  因此移动端放置可靠性不能靠放大格子，必须靠"按住预览 + 按下点落子 + 滑动取消"。
  本工单据此取舍：**触控控件放大到合规，战场格子维持等比**（不做自动吸附，避免误花金币）。
- 缩放迭代必须收敛：`--ui-scale` 会影响反算后的实测尺寸，需多轮迭代并设上下限，防止抖动。
- 只改交互与适配层，**严禁触碰任何平衡数值**；仍跑 `npm test` 兜底。
- 同一文件的多处编辑必须**串行**提交，改完 `Grep` 复核（本项目出现过 Edit 报告成功但未落盘）。
- `js/ui/menu.js`（556 行）、`page-markup.js`（505 行）、`js/modes/conquest/misc.js`（483 行）
  改动后需确认未超 600 行。
- 桌面端为回归基线：1440×900 下 `scale` 必须仍为 1，布局与现状一致。

## 6. 验收标准

1. 844×390 横屏：`#game-area` 不再溢出 `#game-container`（溢出量 0），容器完整落在视口内（不裁切）。
2. 844×390 横屏：`.tower-select` 渲染尺寸 ≥ 44×44；`#fusion-encyclopedia-btn`、`#back-to-menu-btn` 高度 ≥ 44。
3. 选中塔卡后**按住**画布即出现放置预览（绿/红 + 射程圈），松手前可看到落点。
4. 手指抖动 6–8px 的轻点仍能正常放置；位移 > 12px 后抬起**不落子**（滑动取消）。
5. 金币不足 / 格子被占 / 非法位置的放置失败必须有可见提示（toast）。
6. 触屏取消选中：点画布空白处即取消并清除卡牌高亮；面板提示文案不再出现"右键"。
7. 树内 `@media (hover: none)` 分支数 > 0；点击塔卡/图鉴卡片/筛选标签/关卡项均有按压反馈。
8. 长按查看炮塔信息在 8px 抖动下仍生效（或改为"轻点炮塔即显示信息"的等价路径）。
9. 桌面 1440×900：`scale` 仍为 1，塔卡尺寸不变（64×80），无回归。
10. `npm test` 全绿；所有改动文件 ≤ 600 行。
