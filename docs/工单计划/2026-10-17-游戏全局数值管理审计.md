# 工单：游戏全局数值管理审计（阶段一：只审计，不改数值）

日期：2026-10-17

## 任务目标

全面审计《墨守成规》现行数值体系（炮塔、敌人、波次、资源、升级、融合、关卡、征服模式、胜负判定），
判断数值是否合理、一致、相互协调，产出审计完成报告，供用户确认后再进入修改阶段。

## 当前问题/背景

- `tests/test-balance.js` 内手抄了一份 CONFIG，并未加载真实运行时配置，可能与现行代码不一致。
- 伤害结算链路（`Enemy.takeDamage`）包含取整，小数伤害配置可能被截断，需量化验证。
- 数值分散在 `js/config/*`、`js/core/*`、`js/entities/*`、`js/data/levels/*`、`js/modes/conquest/*`，
  需核对重复定义与不一致。
- `docs/full-balance-spec.md` 是历史基线，不能当作当前结果。

## 涉及文件（只读审计）

- `js/config/domain-02.js`（炮塔）、`domain-03.js`（敌人/玩法）、`fusion.js`（融合）
- `js/tower.js`、`js/entities/towers/*`（攻击、升级、投射物）
- `js/enemy.js`、`js/entities/enemy/*`（受伤、状态、死亡、核心）
- `js/core/waves.js`、`flow.js`、`towers.js`、`game.js`（波次、经济、胜负）
- `js/data/levels/*`、`js/levelManager.js`、`js/conquest*`、`js/modes/conquest/*`
- `tests/test-balance.js`、`tests/test-fusion-recipes.js`

## 实施步骤

1. 梳理全部数值定义位置与运行时计算公式。
2. 运行 `npm run test:balance`、`npm run test:fusion` 并核对测试输入是否等于真实配置。
3. 用只读 Node 脚本（放临时目录，不入库）加载真实配置，计算 DPS、性价比、升级曲线、
   波次总 HP/奖励、经济收支、融合收益、边界情况。
4. 分类：确定的程序错误 / 明显的平衡问题 / 设计选择 / 证据不足。
5. 将报告写入 `docs/完成报告/`，随后暂停等待用户确认。

## 风险与注意事项

- 审计阶段禁止修改任何游戏数值或逻辑代码。
- 不把主观偏好当异常；不破坏既有设计意图。
- 模拟结果为近似，需在报告中标明假设。

## 验收标准

- 报告包含：数值体系及位置、问题清单（条件/影响/严重度）、关键公式、建议数值及范围、待验证项。
- 所有结论有代码行或计算结果作依据。
- 仓库中除新增两份文档外，无游戏代码/数值改动。
