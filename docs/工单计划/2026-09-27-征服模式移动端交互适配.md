# 工单：征服模式移动端交互适配

- **日期**：2026-09-27
- **类型**：交互/适配缺陷修复（移动端）
- **优先级**：P0（部分缺陷等于"功能在手机上不可用"）
- **适用平台**：移动端浏览器 / TapTap 小游戏（H5 横屏）—— 本项目唯一目标平台
- **范围**：仅征服模式（`js/conquestGame.js` + `js/modes/conquest/*` + 相关 CSS），不改动游戏数值与玩法规则

---

## 1. 任务目标

前序代理（codex）在实现征服模式时按桌面端假设设计交互，而本项目的唯一目标平台是移动端
（`docs/ui-design-spec.md:6`）。上一次移动端改造（工单 `2026-09-26-移动端触屏交互缺陷修复`）
只覆盖了塔防模式，征服模式仍是桌面端交互范式。

目标：把征服模式的操作链路（拾取塔 / 拖拽移动 / 拖拽融合 / 查看信息 / 失败反馈 / 弹窗）改造为
符合移动端触屏预期，与塔防模式已确定的交互范式（`js/ui/input-touch.js`、`js/bootstrap/device-profile.js`）
保持一致，且不改变任何数值、玩法与桌面端回归行为。

## 2. 当前问题/背景（静态审查结论，逐条定位到代码行）

| 编号 | 缺陷 | 代码位置 | 移动端后果 |
|---|---|---|---|
| C1 | 触摸拖拽**没有落点预览**：`hoveredCell` 只在 `mousemove` 中赋值，触摸链全程不更新 → `drawDragPlacementPreview()` 的 `if (!this.hoveredCell) return` 永远早退 | `js/modes/conquest/misc.js:116-131、200-282`；`js/modes/conquest/rendering.js:150-151` | 手指按住塔拖动时看不到"松手会落在哪格 / 能否融合"，而手指本身还遮住了预览区——移动端唯一的落子前确认通道缺失 |
| C2 | 拾取炮塔**零容差**：`touchstart` 用 `getTowerAt(gx, gy)` 严格格命中 | `misc.js:205-215` | 单格约 36px（1104 宽容器按 844 视口缩放），手指点塔边缘 → `draggingTower=null` → 后续 `touchend` 两个分支都不进 → **完全无反应**（连面板都不关） |
| C3 | 融合目标**严格格命中**：`touchend` 用抬起的那一格 `getTowerAt` 找目标塔，且落点取抬起点 | `misc.js:247-275` | 融合是征服模式核心玩法，手指偏移半格即失败且无提示 |
| C4 | **静默失败**：移动塔到非法格、`attemptFusion` 无可融合配方（`return` 前无任何输出）、召唤失败（仅闪红） | `misc.js:256-259`；`js/modes/conquest/fusion.js:49-53`；`js/modes/conquest/waves.js:2-14` | 触屏无 hover，静默失败 = "点了没反应"，玩家无法归因 |
| C5 | 信息面板**定位算错**：`showTowerInfo` 用 `#game-container` 的 rect 做 clamp，征服模式下该容器不可见 → rect 全 0 → `maxX=-180 / maxY=-150` → `Math.min(x, -180)` → 面板被定位到 `left:-180px` | `misc.js:462-468` | 点塔后面板飞出屏幕外，玩家再次认为"点了没反应"（严重） |
| C6 | 面板内硬编码提示 **"右键取消选择"** | `misc.js:436-444` | 移动端没有右键，文案误导；应改为"点击空白处关闭" |
| C7 | 融合确认弹窗**只有一个按钮**（"确认融合"），取消路径只有 ESC 键 | `fusion.js:65-94` | 误触拖到相邻塔即弹出确认框，移动端用户只能被迫执行融合（不可逆、扣金币） |
| C8 | `#conquest-canvas` **缺 `touch-action: none`**（只有 `#game-canvas` 有） | `css/style/part-05.css:50-52`；`css/style/part-03.css:155` | 长按/双击可能触发系统菜单、文本选择、页面缩放，打断游戏手势 |
| C9 | **容器互斥缺失**：`startLevel/startGame` 只解除 `conquest-container`/`main-container` 的 hidden，从不隐藏 `#game-container`；塔防 `startGame` 也不隐藏 `#conquest-container` | `js/modes/conquest/flow.js:93-104、176-202`；`js/core/flow.js:137-139` | 两个 960px / 1104px 容器同时进入 flex 布局 → 内容宽翻倍 → `viewport.js` 缩放崩塌、战场被挤出屏幕（移动端等于不可用） |
| C10 | 拖拽时**幽灵塔画在手指正下方**（`drawDragPreview` 用 `dragCurrentPos`） | `rendering.js:193-217` | 手指完全遮住被拖的塔与前方的目标格 |
| C11 | 侧栏占宽过大：触屏下侧栏仍为 280px（矮屏媒体查询 180~220px） | `css/style/part-02.css:465` | 战场占比被压缩，格子变小、更难点 |

> 说明：C1~C11 为静态代码审查结论。C5 的算术可由代码直接推出（rect 为 0 时 `maxX = 0-180`）。
> C9 依据：全仓库检索 `game-container` 无任何 `classList.add("hidden")` 调用。

## 4. 实施步骤

1. 新增 `js/modes/conquest/touch.js`
   - `_pickTowerNear(clientX, clientY, {tolerance, exclude})`：严格格命中 + 容差就近（复用塔防范式）。
   - `setupTouchInteraction()`：单指状态机（origin/cell/tower/moved/dragging），
     `touchstart` 起预览（写 `hoveredCell`）、`touchmove` 持续更新落点格并按 `DeviceProfile.slop(12px)` 判拖拽、
     `touchend` 分三支：拖拽（容差找目标塔 → 融合 / 合法格 → 移动 / 否则给原因）、滑动取消、干净轻点（点塔看信息、点空白关闭）。
   - `_notify(message, type)`：复用 `window.gameInstance.ui.showToast`，无实例时降级 `console.warn`。
   - 松手后按 `previewHoldMs(260ms)` 保留落点高亮，便于确认结果。
2. `misc.js`：删除 `touchstart/touchmove/touchend/touchcancel` 四段（约 95 行），改为
   `if (window.DeviceProfile && window.DeviceProfile.hasTouch) this.setupTouchInteraction();`；
   `showTowerInfo` 改用视口 clamp + 触屏时面板置于触点上方（避让手指），提示文案按 `DeviceProfile.isTouch` 切换。
3. `fusion.js`：确认弹窗增加"取消"按钮（复用既有 `#modal-return-btn` 机制），确认/取消均清理监听；
   无配方时 `_notify("这两个炮塔无法融合")`。
4. `waves.js`：`summonTower` 金币不足 / 无空位时给出具体原因提示。
5. `rendering.js`：`drawDragPreview` 在触摸源时把幽灵塔上移约 0.8 格；`drawDragPlacementPreview` 给落点格加金色描边。
6. `flow.js`（征服 + 塔防）：进入某模式时隐藏另一模式的容器，并在切换后调用 `window.applyGameScale()`。
7. CSS：`#conquest-canvas { touch-action: none; }`；触屏下 `#conquest-side-panel` 收窄到 200px。
8. `index.html`：在 `js/modes/conquest/` 脚本块中加入 `touch.js`。

## 5. 风险与注意事项

1. **不改变玩法数值**：本次只改交互与反馈，不动 `CONFIG`、不动融合配方、不动波次参数。
2. **桌面端回归**：鼠标链路（`mousedown/mousemove/mouseup/contextmenu`）保持原样；
   触摸监听改为仅在 `DeviceProfile.hasTouch` 时注册，避免桌面端重复触发。
3. **移动塔的落点语义**：移动仍按"拖到哪放哪"取抬起点（与放置不同——放置不可自动吸附是防误花金币，
   移动不消耗资源，取抬起点更符合直觉）；失败时给原因提示而非静默。
4. **文件行数**：所有代码文件 ≤600 行（AGENTS.md 强制），新增 `touch.js` 独立成文件以确保 `misc.js` 不超限。
5. **弹窗取消按钮**：`#modal-return-btn` 已被胜利弹窗复用，需保证两种弹窗互不残留（显示时创建/显示，关闭时隐藏）。
6. 修改后需重跑 `npm run check:line-count`；本次不涉及数值，不重跑平衡性测试。

## 6. 验收标准

1. 手指按住炮塔拖动时，画布上实时显示落点格（可放置=绿 / 不可放置=红 / 可融合=朱砂底+融合字），松手后短暂保留。
2. 手指点击炮塔边缘（偏移 ≤0.75 格）仍能打开信息面板；面板完整出现在视口内，且触屏时位于触点上方。
3. 把塔拖到另一座塔上（偏移 ≤0.5 格）能触发融合确认；确认弹窗有"取消"，取消后不扣金币、塔不变。
4. 拖到非法格 / 拖融合塔 / 金币不足召唤 / 无可融合配方，均有文字提示，不再静默失败。
5. 面板提示文案在触屏设备为"点击空白处关闭"，桌面端仍为"右键取消选择"。
6. 进入征服模式时塔防容器不可见，进入塔防时征服容器不可见；缩放基准只按当前可见容器计算。
7. 征服画布上长按不触发系统菜单/选择，双击不缩放页面。
8. `npm run check:line-count` 通过；桌面端鼠标操作路径无回归。
