# 工单：P4 战斗界面横屏布局（塔防 · 征服）

- 日期：2026-10-19
- 上级方案：[全界面横屏适配与水墨视觉统一](2026-10-19-横屏适配与水墨视觉统一.md) 第 3.2 节「战斗 · 塔防」「战斗 · 征服」；问题编号 A1、A2、A3、B7
- 依赖：P1 令牌与组件；P3 设置组件 `InkSettings`（战斗设置弹层）

## 1. 任务目标

1. **塔防**：画布占满高度；顶栏改为叠在画布上方的 HUD（左侧数值组、右侧核心印），不再单独占一行；塔栏改为**叠在画布右缘的竖排卡槽**，暂停按钮放在卡槽顶部。在 740×360 下缩放率从约 0.60 提到 **≥ 0.74**（A1、A3）。
2. **征服**：侧栏改为**叠在画布左缘的竖条**（召唤、墨、坚守、危险、菜单），缩放率从约 0.62 提到 **≥ 0.74**（A2）。
3. **镜头余量**：被卡槽或侧栏遮住的格子，都能通过镜头滚动露出来并放置炮塔；拖卡时的边缘自动滚动区和边缘提示都改为以「可见区」边缘为准。
4. **弹层尺寸**：暂停和设置弹层移出缩放容器，按真实屏幕尺寸显示，可点元素不小于 44px（解决 P3 遗留的问题）。
5. **清理**：去掉顶栏和征服侧栏里的音效、音乐按钮（已在设置中），去掉征服规则说明；画布上的 14px 关卡名（B7）改由 HUD 显示；征服召唤费用改为实时显示。

## 2. 当前问题 / 背景（已核对代码）

- 布局：`#game-container` 由 `#top-bar`（约 56px）、`#game-area`（960×432 画布）、`#bottom-bar`（约 82px）纵向叠放，内容高约 570px，高度先触顶，所以缩放约 0.60。征服是 `#conquest-side-panel`（约 199px）加画布横排，宽度先触顶，所以缩放约 0.62。
- 缩放：`js/bootstrap/viewport.js` 测量可见根元素的尺寸，迭代计算 `--ui-scale`；触控尺寸用 `calc(44px / var(--ui-scale))` 反算（`style/part-05.css`、`mobile.css`）。
- 镜头：`js/core/camera.js` 的 `minX = 0`、`maxX = worldW - viewW`；`_edgeDirection` 按画布左右各 48px 判定边缘自动滚动；`drawHints` 在画布边缘画墨晕和位置条。
- 塔卡手势：`js/ui/input-card-gesture.js` 按「横滑滚动底栏、其余方向放置」判定，并操作 `scrollLeft`。改成竖排后，滚动方向要随卡槽排布方向切换。
- 暂停和设置弹层（`.battle-layer`）在 `#game-container` 内，跟随缩放。
- 征服召唤费用 `.summon-cost` 写死为「80墨」，实际费用为 50 起并逐次递增，没有任何代码更新它（原有缺陷）。
- 旧样式：`style/part-01/02/03/05`、`inline/part-02/05`、`mobile.css`、`battle.css` 中有约 200 条相关规则。

## 4. 实施步骤

1. 改结构：HUD（`#top-bar` 改为叠放，保留 `#ink`、`#hold-time`、`#enemies`、`#core-hp`、`.core-stat` 这些 ID 和类名）、卡槽（`#pause-btn` 加上 `#bottom-bar`）、征服竖条（保留所有 ID）；弹层移出。
2. 编写 `battle-layout.css`，然后剪除旧的布局规则。
3. 镜头加遮挡余量，接入塔防（右侧）和征服（左侧）。
4. 卡牌手势改为按轴滚动；召唤费用实时更新；HUD 显示关卡名。
5. 编写巡检脚本，覆盖 6 台设备：缩放率、HUD 和卡槽不越界、按钮 ≥ 44px、真实触摸拖卡出塔、镜头能滚到最右（塔防）和最左（征服）；运行 `npm test`。

## 5. 风险与注意事项

- **命中盒变化**：方案总纲的 C2 要求「命中盒不变」，那是针对上一批纯视觉工单的约束。本批是布局改版，卡片尺寸保持 62×70 不变，但位置会变；按钮按反算后的 44px 渲染。
- **拖放**：卡片从右缘卡槽向左拖到地图。起手时指针位于卡槽上，不能误触发边缘自动滚动；卡槽内的竖向滑动用于滚动卡槽（只有 2 张卡时不会滚动）。
- **HUD 遮挡第 0 行**：HUD 半透明、`pointer-events: none`，只遮住第 0 行上部约三分之一；第 0 行的敌人和塔仍然可见，也可以点击。
- **画布逻辑尺寸**（960×432）、网格、`RenderScale` 都不变；世界坐标换算不变（镜头的 x 可以为负，坐标换算本来就是 `sx + x`）。
- `test-camera.js` 的现有断言（`maxX = 912` 等）在默认无遮挡时保持成立。

## 6. 验收标准

1. 在 740×360 下：塔防和征服的缩放率都 ≥ 0.74；左右或上下空边 ≤ 24px（实际约等于安全区宽度加 8px 边距）。
2. 在 6 台设备矩阵中：HUD、卡槽、竖条都在视口内；按钮渲染尺寸 ≥ 44px；没有页面溢出。
3. 真实触摸从卡槽拖出火塔，可以放在路径旁；镜头拖到最右时，核心所在列完整露出在卡槽左侧（塔防）；征服开局时第 0 列在竖条右侧。
4. 暂停 → 设置弹层按真实屏幕尺寸显示，开关 ≥ 44px；继续游戏、返回主菜单正常。
5. 征服召唤费用随召唤次数实时变化。
6. `npm test` 全部通过。
