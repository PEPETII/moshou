# 工单：P1 水墨设计令牌与组件

- 日期：2026-10-19
- 上级方案：[全界面横屏适配与水墨视觉统一](2026-10-19-横屏适配与水墨视觉统一.md) 第 3.3 节、第 5 节 P1
- 性质：**只新增基础设施**，不替换任何现有页面的布局和外观（唯一例外是 C6 的字形修复，它是缺陷修复）。

## 1. 任务目标

1. 建立唯一的设计令牌来源：纸色、五墨、点缀色、字号 6 档、间距、字体栈、触控尺寸、动效时长。
2. 提供横屏页面骨架 `.ink-page` 和一组水墨组件（按钮、返回、面板、分隔、选中、开关、数值行），供 P2 到 P6 直接使用。
3. 新增 `npm run check:tokens`，统计令牌文件之外裸写的色值和像素字号（本批只报告，不阻断）。
4. 修复 C6：设置页「返回墨卷」等处的「回」字显示成实心方块。

## 2. 当前问题 / 背景（已核对）

- 令牌只有 `css/ink-ui/foundation.css:1-16` 中的一小组，`inline/`、`style/` 两套历史样式大量绕开令牌：21 种字号、26 种裸写的十六进制色值。
- **C6 根因（已实测）**：不是墨点粒子，而是外链字体 **ZCOOL XiaoWei 的「回」(U+56DE) 字形本身是实心方块**，在 13px、16px、24px 下都一样。用画布逐字测量页面和 `CONFIG` 中出现的 425 个汉字的墨量占比：只有「回」异常（0.31，第二名只有 0.24）；Ma Shan Zheng 没有异常字。在浏览器中注入一个只覆盖 U+56DE、指向本机宋体或黑体的 `@font-face` 后，「回」恢复正常（占比 0.12）。
- 受影响的文案：「返回墨卷」「返回」「返回主菜单」，以及以后所有用正文字体显示的「回」。

## 4. 实施步骤

1. 新建 `tokens.css`：迁入现有 `:root`，新增令牌，旧名（`--ink-paper`、`--ink-strong` 等）改为指向新令牌的别名，保证现有样式不变。
2. 新建 `layout.css`、`components.css`，类名统一用 `ink-` 前缀，不使用 ID 选择器，避免和现有规则冲突。
3. 在 `ink-ui.css` 中 @import。
4. C6：在 `tokens.css` 中声明 `@font-face "Ink Glyph Fix"`（`unicode-range: U+56DE`，`src` 为多平台本机字体的 `local()` 列表）；把 CSS 中的 `"ZCOOL XiaoWei", serif` 替换为 `var(--font-text)`，把 `"Ma Shan Zheng", cursive` 替换为 `var(--font-brush)`；JS 中的字体栈同步补上。
5. 编写 `check-tokens.js`：默认只报告，`--strict` 时有违规则返回退出码 1。
6. 编写组件样张页，在浏览器中按 740×360 和桌面两种尺寸验证。
7. 运行 `npm test`，并检查各文件行数。

## 5. 风险与注意事项

- **级联顺序**：新组件只用类选择器，优先级低于现有的 ID 规则，本批不会影响任何现有页面；后续批次启用组件时，需要同步删除对应的旧规则。
- **`font` 简写和 `var()`**：`font: 13px var(--font-text)` 是合法写法；机械替换后要用 grep 确认没有残留和语法错误。
- **本机字体缺失**：如果设备上没有列表中的任何字体，`Ink Glyph Fix` 会被跳过，回退到 ZCOOL 的方块，效果等同于现状，不会更差。列表要覆盖 Windows（SimSun / Microsoft YaHei）、Apple（Songti SC / PingFang SC）、Android（Noto CJK / Droid Sans Fallback）。
- 画布 `ctx.font` 首次绘制时 local 字体可能还没就绪；只影响首帧，可以接受。
- 行数：所有新文件都要少于 600 行。

## 6. 验收标准

1. 现有界面的外观除「回」字外无变化：主菜单、图鉴、设置、战斗截图与改动前对比一致。
2. 「回」在设置、择潮、暂停各处都显示为正常笔画。
3. 组件样张页在 740×360 下：骨架的顶栏固定，返回按钮在左上，只有内容区可以滚动；所有可点组件不小于 44px。
4. `npm run check:tokens` 能输出按文件统计的违规清单，并且退出码为 0。
5. `npm test` 全部通过。
