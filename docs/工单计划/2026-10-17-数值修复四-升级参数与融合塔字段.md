# 工单：数值修复四 —— A6 升级参数生效 + A7 融合塔字段补全

日期：2026-10-17　来源：审计报告 A6、A7（用户已确认继续）

## 任务目标
1. A6：投射物命中时的状态参数（毒伤/毒时长/溃烂时长、冰冻时长、符的标记加成/时长、暗的影印时长、寄生时长/爆炸伤害/范围、风的击退冷却）改读**塔自身字段**（含升级后的值），不再读 `CONFIG.TOWERS[this.type]` 基础值。
2. A7：`FusionTower` 构造时，从其动作所含的基础塔配置补全缺失的状态/链式/范围字段，使雷系融合能出手、水/冰/毒/暗/寄生/符融合带上对应状态。

## 当前问题/背景
- 毒 3 级面板 0.55，实际施加 0.35；冰 3 级冻结 1800，实际 1200；符 3 级标记 0.55/7500，实际 0.35/5500。
- 融合塔 `type` 为融合键，不在 `CONFIG.TOWERS` 中，所有状态分支被跳过；`chainCount` 等继承自 `fusion` 基类为 0，雷系融合实测 DPS=0。
- `ulcerDuration`、`parasite` 爆炸伤害/范围、`knockbackCooldown` 是死配置（代码写死 5000、3.0/2、3000）。

## 涉及文件
- `js/entities/towers/projectiles.js`（命中分支）
- `js/entities/towers/fusion.js`（构造时补全字段）
- `js/entities/enemy/combat.js`（`applyPoison` 溃烂时长参数、`takeDamage` 寄生爆炸读取敌人字段）、`js/entities/enemy/misc.js`/`enemy.js`（reset 初始化新字段）
- 测试 `tests/test-upgrade-and-fusion-effects.js`

## 实施步骤
1. 投射物命中改读 `this.*`；`applyPoison/applyParasite` 增加可选参数，默认值保持原硬编码值。
2. `FusionTower` 在构造末尾对白名单字段：若融合塔值为空/0，则取其 `skillParams.actions` 中第一个提供该字段的基础塔配置值。伤害/射程/冷却/HP/花费仍用融合配方值。
3. 测试：升级后参数被施加；融合塔六类状态及雷系出手。
4. 重跑融合塔实测表，记录变化。

## 风险与注意事项
- 融合塔获得状态/链式后实际强度上升，与 B2 的融合 DPS 溢出叠加；本工单不调数值，仅记录，后续统一调融合公式。
- 土系 `aoeAttack` 使用 `range` 作为半径、`aoeRange` 未被使用（新发现，A12），本工单不改，仅记录。
- `knockbackCooldown` 改读配置会把风塔击退冷却从 3000ms 变为配置值 2800ms（配置意图）。

- 毒/冰/符 3 级塔命中后敌人状态等于塔自身升级后的值。
- 融合 霆/淼/凌/蛊/冥/蛊毒 等出现对应状态或伤害 >0。
