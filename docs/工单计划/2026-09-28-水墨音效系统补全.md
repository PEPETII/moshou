# 水墨主题音效系统补全

## 任务目标

补齐游戏实际可用的音效系统，以 Web Audio API 程序化生成水墨风格短音效，覆盖放塔、攻击、击杀、融合、波次开始和核心受击，并提供普通模式与征服模式均可操作的音效开关。

## 当前问题 / 背景

当前没有 `AudioContext` 或播放逻辑。`#sound-toggle` 只有样式，敌人死亡和核心受击处留有待实现注释，界面实际没有声音控制。游戏无需传统音效素材，适合用毛笔、宣纸、墨滴、印章和鼓点构成短音效。

## 实施步骤

1. 在页面装配后加载独立的 `js/audio.js`，用惰性创建的 `AudioContext` 合成音效，不引入外部资源；持久化开关状态并处理浏览器不支持或本地存储不可用的情况。
2. 在普通模式和征服模式的操作区加入可访问的音效开关，并沿用现有触屏尺寸规则。
3. 在成功事件处接入六类音效：放置/召唤、攻击、击杀、融合、波次开始和核心受击；对高频攻击、击杀和核心受击做节流。
4. 更新 README，只描述实现后确认存在的音效行为和控制方式。
5. 做语法、行数和差异检查，并记录实际验证范围与限制。

## 风险与注意事项

- 浏览器需在用户交互后创建或恢复音频上下文；不得在页面载入时自动播放。
- 战斗中的攻击和击杀可能高频触发，需要节流，避免音量堆叠。
- 两种模式的控件应共用状态，但页面中不能重复使用同一个 HTML `id`。
- 保持普通脚本加载方式，不引入构建工具、第三方音频文件或网络依赖。
- 工作区已存在与本任务无关的文档改动，必须保留。

## 验收标准

- Web Audio 能程序化生成六类短音效；没有可用音频上下文时游戏流程仍正常。
- 普通模式和征服模式都能开关声音，状态通过 `aria-pressed` 显示并跨刷新保存。
- 六类音效只在对应成功事件发生时触发；攻击、击杀和核心受击不会无节制重复。
- 新增或修改的代码文件不超过 600 行；不引入外部音频依赖。
- README 与实际实现一致；语法、行数与差异检查结果写入完成报告。
