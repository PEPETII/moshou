# 工单：战场画布高清渲染（修复画面模糊）

- 日期：2026-10-19
- 背景来源：用户反馈「demo 画面清晰，正式游戏字、塔身、敌人、背景全部模糊」

## 任务目标

让塔防、征服两种模式的战场画布按「屏幕实际像素」渲染，清晰度和 `demo/字形弹道原型-火与水` 一致，并且不改变游戏逻辑坐标、镜头、命中判定和视觉构图。

## 当前问题/背景

- `js/game.js:6-7`、`js/conquestGame.js:21-22` 把画布位图固定为 960×432（`CONFIG.VIEW_W/VIEW_H`）。
- `js/bootstrap/viewport.js` 用 `container.style.transform = scale(s)` 把整个战场放大到窗口宽度；再叠加系统缩放（`devicePixelRatio`，Windows 常见 1.25～1.5），一个画布像素会被拉伸成 2～3 个屏幕像素，位图插值后整体发糊。
- 全仓库 `js/` 里没有任何 `devicePixelRatio` 处理。demo 用 `canvas.width = STAGE.W × dpr` 加 `ctx.setTransform(dpr, …)`，所以清晰。
- 离屏层也是 1 倍分辨率：`StaticCanvasLayer`（`js/runtime.js`，承载地形、墨廊、核心）、`MapBackground` 的地形和墨廊缓存（`js/mapBackground.js`）、墨渍层（`js/glyph/fx.js`）。只改主画布的话，背景仍然会糊。

## 涉及文件

- `js/utils.js`：新增 `RenderScale`（测量倍率、设置位图尺寸、读取逻辑尺寸），`clientToCanvas` / `clientToWorld` / `isInsideCanvas` 改用逻辑尺寸
- `js/game.js`、`js/conquestGame.js`：画布初始化走 `RenderScale.setup`
- `js/core/rendering.js`、`js/modes/conquest/rendering.js`：每帧绘制前 `RenderScale.begin`；所有「逻辑尺寸」的 `canvas.width/height` 改读逻辑尺寸
- `js/runtime.js`：静态层位图按倍率生成，按逻辑尺寸绘制
- `js/mapBackground.js`：地形、墨廊缓存支持 `scale`；模糊滤镜按倍率换算
- `js/glyph/fx.js`、`js/glyph/system.js`：墨渍层按倍率生成；HUD 宽度取逻辑尺寸
- `js/glyph/brush.js`：`shadowBlur` 按倍率换算，保持光晕的逻辑尺寸不变
- `js/ui/input.js`、`js/inkTrailAnimation.js`、`js/core/camera.js`：读取逻辑尺寸

## 实施步骤

1. 倍率 `k = clamp(dpr × 画布 CSS 显示宽度 / 960, 1, 3)`，按 0.25 取整，避免窗口拖动时频繁重建位图；画布不可见时保留上次的值。
2. 主画布：位图 = 逻辑尺寸 × k；每帧 `setTransform(k, 0, 0, k, 0, 0)` 后再按原逻辑坐标绘制。倍率每 250ms 最多重新测量一次。
3. 离屏层：位图 × k，绘制时 `drawImage(cv, 0, 0, 逻辑宽, 逻辑高)`；缓存键包含 k；倍率变化后，静态层标脏重建，墨渍层按比例拷贝迁移。
4. 不受变换影响的像素量（`ctx.filter` 的 blur、`shadowBlur`）乘 k。
5. 坐标换算统一用逻辑尺寸，镜头和命中判定保持不变。

## 风险与注意事项

- 漏改任何一处「把 `canvas.width` 当逻辑宽度」的代码，都会造成 HUD 错位或命中偏移，需要全仓库搜索确认。
- 倍率最高为 3：塔防世界宽 1872 时，静态层位图为 5616×1296，约 29MB，可以接受；不要再提高上限。
- Node 测试环境里没有 `getBoundingClientRect` 或 `devicePixelRatio`，`RenderScale` 必须退化为 k = 1。

## 验收标准

- 在 DPR ≥ 1.25 的显示器上，两种模式的字、塔身、敌人和背景都和 demo 一样清晰（截图对比）。
- 镜头在左、中、右时，放置和选中都精确命中；HUD 位置和修改前一致。
- 改变窗口大小后，画面仍然清晰，不出现错位。
- `npm test` 通过。
