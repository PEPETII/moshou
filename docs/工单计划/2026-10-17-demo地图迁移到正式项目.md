# 工单：迁移 demo 地图系统到正式项目

- 日期：2026-10-17
- 类型：视觉资产迁移 + 渲染层接入
- 状态：进行中

## 1. 任务目标

把 demo（`demo/glyph-trajectory-demo.html`）中的水墨地图系统迁入正式项目：

1. 塔防棋盘改用 demo 的地图底纹与墨廊路径样式；
2. 主界面及其它全屏界面的背景统一换成同一套地图（**只显示地貌，不绘制路径**）；
3. 路径按 demo 的样式重绘，但**敌人实际行走的坐标不变**。

## 2. 尺寸口径（先校事实）

| 区域 | 现状尺寸 | 结论 |
| --- | --- | --- |
| 塔防棋盘 | `CELL_SIZE 48` × `GRID_COLS 20` × `GRID_ROWS 9` = **960×432** | 与 demo 画布完全一致，**棋盘不需要缩放** |
| 征服棋盘 | 16×9 @48 = 768×432 | 本次不迁移（见第 6 节） |
| 主界面/全屏界面 | 随视口，典型 1920×1080 | **真正「尺寸不足」的是这里** |

因此「适度调整地图尺寸」的落点是：地图生成器改为**按目标尺寸自适应**——
纸纹密度、远山数量、苔点数量按面积等比缩放，构图基准按高度比例锚定；
棋盘按 960×432 生成（尺寸不变、结构与路径连贯性天然保持），
全屏界面按视口尺寸生成（同一套规则、更大画幅），而不是把 960×432 位图拉伸。

## 4. 实施步骤

1. 建工单（本文件）。
2. 写 `mapBackground.js`：从 demo 移植纸纹、远山、苔点、墨廊、飞白边、方向箭标；全部按尺寸参数化并缓存为离屏画布。
3. 接入塔防静态层：纸底 → 远山 → 苔点 → 网格 → 墨廊 → 核心。
4. 接入主菜单：新增底图画布，`load` 后与 `resize` 时渲染，不画路径。
5. 视觉校验：截图棋盘与主菜单，确认路径与「入口」标注位置未变、文字仍可读。
6. 回归：`npm test` 与行数检查。

## 5. 风险与注意事项

- **路径坐标一行不改**：只替换绘制方式，`path` 数据、`core`、放置校验全部保持原样。
- **性能**：墨廊含数百个飞白点，必须缓存离屏画布，禁止每帧重绘（征服模式是每帧重绘的，若接入必须走缓存）。
- **文字可读性**：底纹不能压过顶栏文字与菜单文字，纸纹对比需克制。
- **行数**：新文件控制在 600 行内。
- **不引入构建工具**，纯 `<script>` 引入。

## 6. 明确不做

- 征服模式棋盘本次不迁移：其 `drawPlacementArea()` 每帧用纯色填充所有空格，会覆盖任何底纹，需要先重构该逻辑，超出本次范围。
- 不改动关卡路径、波次、数值、塔位规则。

## 7. 验收标准

1. 塔防棋盘显示 demo 同款纸纹与墨廊，路径走向与原关卡数据逐格一致，「入口」标注位置不变。
2. 主菜单及关卡选择/图鉴/设置界面显示同一套地图底纹，**看不到路径**。
3. 敌人行走、放置格、核心位置、胜负判定全部不变。
4. `npm test` 通过；无控制台报错；新文件 < 600 行。
