## 1. 任务目标

1. **横屏首屏可用**：每个界面在 640×360 到 932×430 的横屏视口内，主要内容和返回入口都在首屏，不需要滚动就能操作。
2. **导航统一**：每个二级以上界面都有位置固定、文案统一的返回入口。
3. **主从结构合理**：图鉴类的「列表 + 详情」做成横屏常驻双栏，列表项要有信息量，空状态要给出明确引导。
4. **战斗画面利用率**：塔防和征服的战斗界面缩放率从约 0.60 提到 0.80 以上，去掉两侧各约 80px 的空边。
5. **水墨视觉一体化**：菜单、图鉴、选关、战斗、弹窗共用一套「宣纸 · 墨阶 · 朱印」设计令牌和组件，UI 和地图之间、各界面之间都不再割裂。

## 3. 设计方案

### 3.1 横屏布局框架（所有界面共用）

把全屏菜单页统一成**三段式横屏骨架**，取代现在各页各自写死的高度：

```
┌ safe-left ─────────────────────────────────────── safe-right ┐
│ [‹ 返回]      页面标题（毛笔）              [辅助操作/进度]   │ ← 顶栏 44px（触控高度），固定
│──────────────────────── 淡墨分隔（晕染，非实线） ─────────────│
│                                                              │
│                 内容区：flex:1，min-height:0                  │ ← 只有这里可以滚动
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

- 新增 `.ink-page` / `.ink-page__bar` / `.ink-page__body` 三个类，放进 `css/ink-ui/layout.css`（新文件，少于 200 行）。
- 所有页面高度改用 `100dvh` 扣掉安全区；内容区 `overflow:auto`，**返回入口永远在顶栏左上角**，不再放进可滚动区。
- 竖向留白按视口高度分档：`max-height:400px` 时统一用 `--space-*` 的最小档。
- 版本号只在主菜单显示，其他页面不显示，避免压住底部内容（05 号图里版本号透过详情面板显示出来）。

### 3.2 逐界面方案

**主菜单（A8）**
- 横屏左右构图：左侧 40% 放竖排题名「墨守成规」，配朱印；右侧 60% 放四个入口，竖排纵列，每项为「大字 + 小字说明」，做成墨块按钮。
- 底部山水条（`landscape.svg`）保留，作为全游戏共用的「卷底」。

**图鉴主界面（K1）**
- 套用三段骨架：顶栏左侧放「‹ 主菜单」，中间放标题「图鉴」。
- 两张入口卡占满内容区高度（`flex:1`），卡内大字、名称、说明三行居中；卡上显示收录进度，例如「已录 2 / 2」。
- 验收：在 360px 高的视口里，两张卡和返回按钮全部在首屏。

**炮塔志 / 妖异录（K2、K3、A4、B1、B2、B4）**
- **常驻双栏**，比例 **40 : 60**（最小 260px : 剩余宽度），取消抽屉覆盖层。
- 左栏列表项改为富信息行：`[大字印块] 名称 · 一句定位 / 造价或血量标签 / 状态点`，行高 56px；选中态是左侧朱砂竖印加淡墨底。
- **默认选中第一项**，右栏不再出现空状态。只有列表为空时才显示引导：「轻点左侧一字，观其笔意」，配一个指向左侧的毛笔箭头。
- 右栏详情分三段：① 字形区：用 `glyph` 笔画数据做书写动画预览，这是本作最独特的内容；② 数值区：两列表格，带单位和等级（如「移速 · 迅」）；③ 招式区：普攻和大招各一张小卡。
- 删除过时页签；只有两三个条目时不显示筛选（列表超过 6 项时才出现「全部 / 火系 / 水系」）。
- 标题统一为入口名「炮塔志」「妖异录」；顶栏左侧「‹ 图鉴」，右侧放一个「⌂」直接回主菜单。

**设置（A9、B5、C6）**
- 两栏网格：左列「画面」（墨迹动效、打击反馈、伤害数字、震动），右列「声音」（音效、音乐滑块）。
- 开关统一为「墨点开关」组件：状态用印章亮或暗表示，文字只写名称。
- **主菜单设置和暂停设置共用同一份组件和数据源**，暂停里打开的是同一面板，只是叠在战斗上层。

**主题选择 / 选关（A5、A6、A7）**
- 塔防和征服**统一成一个「山河长卷」选关组件**：横向卷轴，节点沿一条墨线均匀分布，节点用「印章 + 关名」，线稿山石只放在节点之间。
- 主题少于 3 个时，主题卡居中放大（卡高约等于内容区的 70%），展示主题题字、进度条和关卡数。
- 底部固定一条「关卡信息条」：关名、星级印、敌种小字（尸 / 鬼 / 巨），右侧放「入境」主按钮。征服模式也用这一条，取代现在直接点节点就进入的做法。

**战斗 · 塔防（A1、A3、B7）**
- **改成横屏专用布局**：画布占满高度，HUD 浮在画布上方的淡墨半透明带里（高 36px），塔栏改为**右侧竖排卡槽**（宽 72px），**叠放**在画布右缘的墨晕上，不额外占宽度。
  - 估算（740×360，扣掉触控边距 8px 后可用 724×344）：内容 960×432，缩放 = min(724/960, 344/432) ≈ **0.75**，比现在的 0.60 提升约 25%。如果把卡槽并排放在画布外，宽度变成 1032，缩放只有 0.70，所以必须叠放。
  - 叠放后画布右侧一列格子会被卡槽遮住：用镜头右边界多留 72px 的滚动余量来解决（`camera.js`），不改地图数据。
- 音效、音乐开关从顶栏移进暂停菜单；顶栏只保留「墨 · 守时 · 击杀 · 核心 · 暂停」。
- 画布关卡名改由 DOM 上的 HUD 显示，并统一为毛笔字体。
- 镜头位置条保持在底部中间（现有），与卡槽不冲突。

**战斗 · 征服（A2、C3）**
- 侧栏改成**叠放在地图左缘的可收起竖条**：常态宽 72px（召唤大按钮、墨数、坚守计时、危险值竖条、菜单），点开后展开详情；和塔防一样不额外占宽度，缩放同样约 0.75，镜头左边界多留 72px 余量。
- 地图去掉硬方格网，统一使用塔防的宣纸地形缓存（`MapBackground`），格子只在拖拽放置时淡出提示。

**弹窗：择潮 / 暂停 / 胜负（B6、C4）**
- 统一使用「卷轴弹窗」组件：一层纸面、上下两根卷轴墨线、四角飞白，不再叠多层错位纸张。
- 胜负弹窗：大字「胜 / 败」加印章动画；星级做成三枚朱印（亮或暗）；按钮组为 `[重来] [选关] [下一关▸]`，主按钮朱红。
- 择潮三档保留现有信息，按钮区和卷轴组件对齐。

### 3.3 水墨视觉系统（解决割裂与精致度）

**① 设计令牌（`foundation.css` 扩展，作为唯一来源）**

| 类别 | 令牌 |
|---|---|
| 纸 | `--paper-0 #f4efe4`（底）、`--paper-1 #ece5d6`（面板）、`--paper-2 #e2d9c6`（凹陷/选中） |
| 墨阶（五墨） | `--ink-焦 #1c1a17`、`--ink-浓 #3a352e`、`--ink-重 #6a6459`、`--ink-淡 #9b9386`、`--ink-清 rgba(28,26,23,.08)` |
| 点缀 | `--seal #b4473a`（朱印，只用于主行动/选中/火）、`--tint-water #5f7884`、`--tint-ochre #a88a62` |
| 字号 | 只保留 6 档：`--fs-xs 12`、`--fs-s 14`、`--fs-m 16`、`--fs-l 22`、`--fs-xl 32`、`--fs-hero 48`（px，未乘 ui-scale） |
| 间距 | `--sp-1 4`、`--sp-2 8`、`--sp-3 12`、`--sp-4 16`、`--sp-6 24`、`--sp-8 32` |
| 字体 | 标题、大字用 `Ma Shan Zheng`；正文、数值用 `ZCOOL XiaoWei`；不再出现 `Microsoft YaHei` |

规则：组件内不允许出现裸写的十六进制色值和像素字号；新增 `npm run check:tokens`（`scripts/` 下的 Node 脚本），统计 `css/` 中裸写的色值和字号，只允许在 `foundation.css` 中出现。

**② 组件统一（`css/ink-ui/components.css`，新文件）**

| 组件 | 统一形态 |
|---|---|
| 主按钮 | 朱红墨块，边缘带飞白（`mask-image` 噪点），按下时墨色加深并下沉 1px |
| 次按钮 | 淡墨底加浓墨字；按下时墨晕从按点扩散（复用 `ink-interactions.js`） |
| 返回 | 「‹」毛笔折线加文字，固定在顶栏左侧，全游戏统一文案为「‹ 上一级名称」 |
| 面板 | `--paper-1` 底，四边用同一张飞白描边 SVG（`border-image`），不用实线 |
| 分隔 | 一律用淡墨晕染横线（渐隐两端），不用 1px 实线 |
| 选中 | 朱砂竖印（左侧 4px）加 `--paper-2` 底 |
| 开关 | 印章亮或暗 |
| 数值 | 「标签（淡墨）· 数值（焦墨）· 单位（淡墨小字）」三段式 |

**③ UI 和地图融合**
- 页面、HUD、面板与地图共用同一张宣纸纹理：把 `MapBackground.paintPaper` 生成的纸纹导出为 dataURL（生成一次并缓存），作为 `body` 和面板的背景，DOM 和 Canvas 用的是同一张纸。
- 战斗 HUD 和卡槽不再是独立色块，而是带 `mask-image` 渐隐边的淡墨带，直接浮在地图上，像墨迹写在同一张纸上。
- 共用卷底山水：主菜单、选关、图鉴底部和战斗地图最下缘都使用同一条山水剪影（`landscape.svg`），形成连续的长卷意象。

**④ 界面之间的连续性**
- 统一的页面转场「墨晕转场」：旧页从点击位置晕开、淡出到纸色，新页淡入；时长 280ms，开启减少动效时改为直接切换。
- 所有页面的标题位置、返回位置、内容起始线对齐同一网格（左右边距 `max(24px, safe-area + 12px)`）。

## 6. 风险与注意事项

- **玩法不变**：不改关卡数据、数值、火和水的弹道与交互；P4 只改布局，画布逻辑尺寸 960×432、镜头和 `RenderScale` 行为保持不变。
- **触控命中**：所有可点元素不小于 44×44 CSS 像素（按 `calc(44px / var(--ui-scale))` 反算的现有约定）；P4 之后要重测拖放出塔和边缘滚动。
- **性能**：不对大面积元素用动画式的 `filter: blur`；飞白、纸纹只生成一次并缓存；转场只用 `opacity` 和 `transform`。
- **字体**：不新增外部字体；字体加载失败时回退到系统 serif，布局不能因此错位（用固定行高）。
- **行数**：`page-markup.js`、`menu.js`、`pages.css` 都接近或可能超过 600 行，修改时要同步拆分。
- **历史文档**：`moshou-UI重构设计方案.md` 中仍提到融合系统，本方案以现行代码为准，不恢复已删除的系统。

## 7. 验收标准

**横屏尺寸矩阵**：640×360、740×360、844×390、932×430，以及带左侧刘海安全区（`--sal: 44px`）的模拟。

1. 每个界面在矩阵中的每个尺寸下，主要内容和返回入口都在首屏，无需滚动；没有文字溢出、截断或元素互相遮挡。
2. 图鉴主界面在 360px 高度下，两张入口卡和返回按钮完整可见。
3. 炮塔志、妖异录为常驻双栏，进入时默认选中第一项；任何状态下右栏都不会只显示一句装饰文案。
4. 所有二级以上页面的返回入口都在顶栏左上，文案格式统一为「‹ 上一级」。
5. 在 740×360 下，塔防和征服战斗的缩放率都不低于 0.74；左右或上下空边不超过 24px；卡槽、侧栏遮住的格子都能通过镜头滚动露出来，并且可以放塔。
6. `npm run check:tokens` 通过：`foundation.css` 之外没有裸写的色值和像素字号。
7. 主菜单设置和暂停设置是同一个组件，修改任意一处后两边状态一致。
8. 回归：`npm test` 全部通过；手动验证塔防 1-1、征服 1 两关都能完成出塔、拖放、镜头滚动和暂停流程。
9. 每批都附上矩阵尺寸下的前后对比截图。
