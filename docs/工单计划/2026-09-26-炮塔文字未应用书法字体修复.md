# 工单：网格炮塔文字未应用书法字体修复

- **日期**：2026-09-26
- **类型**：Bug 修复（渲染层）
- **优先级**：P1（视觉一致性问题，不影响玩法逻辑）

---

## 1. 任务目标

让网格地图上所有炮塔的汉字（火/水/木/金/土/山及融合塔多字名）使用与底部卡牌栏同款的书法字体
`Ma Shan Zheng`，消除"卡牌是书法体、炮塔是系统黑体"的视觉割裂。

## 2. 当前问题/背景

底部卡牌栏（`#bottom-bar` 的 `.tower-select > .tower-char`）是 DOM 元素，字体由
`css/style/part-01.css:204` 的 `font-family: "Ma Shan Zheng", cursive` 控制，渲染正确。

炮塔是 Canvas 绘制（`ctx.fillText(this.char, ...)`），**完全不受 CSS 影响**，字体只能由
`ctx.font` 声明。经全量排查：

- 项目内**不存在任何 `@font-face`**，书法字体唯一来源是 `index.html:15` 的 Google Fonts 外链；
- `js/bootstrap/init.js:10` 通过 `ResourceLoader.add('', 'font')` → `document.fonts.load('1em "Ma Shan Zheng"')`
  在 `initGame()` 之前完成预加载，**字体本身已就绪，不存在加载时序问题**；
- 根因是**五行基础塔 + 山塔 + 基础兜底塔的 `ctx.font` 被硬编码为 `Microsoft YaHei`（系统黑体）**；
- 后期加入的塔（雷/冰/毒/风/霜/鼓/旗…）统一写的是 `"Ma Shan Zheng", cursive`，属早期代码漏改造成的历史遗留不一致。

## 4. 实施步骤

1. 新建工单（本文件）。
2. 在 `js/config/domain-01.js` 增加 `FONTS.BRUSH`，字体栈补齐 CJK 兜底：
   `'Ma Shan Zheng', 'ZCOOL XiaoWei', 'KaiTi', 'STKaiti', serif`
   （原 `cursive` 为拉丁通用族名，无 CJK 字形，一旦 Web Font 失败会直接退到默认中文字体，等于没有兜底）。
3. 逐个修改上述 11 处 `ctx.font`，改用 `CONFIG.FONTS.BRUSH`，保留原有 `scale` / `pulse` 变量与字号算式，
   **不改变任何字号、颜色、坐标、动画参数**。
4. `Grep` 复核每处改动均已落盘（本项目历史出现过 Edit 报告成功但未落盘的静默丢失）。
5. 运行 `npm test`，确认行数检查与平衡性/融合测试未回归。

## 5. 风险与注意事项

- **仅改字体声明，不改任何数值**，对平衡性零影响；但仍跑 `npm test` 兜底。
- 同一文件的多处编辑必须**串行**提交，改完用 Grep 复核，不能凭 "Successfully edited" 判定完成。
- Canvas 的坑：`ctx.font` 字符串若语法非法，浏览器**静默保留上一次的值且不报错**，
  因此改后必须肉眼比对字形，脚本断言测不出。
- `rendering-basic.js` 改后 481 行、`rendering-advanced.js` 445 行，均未超 600 行上限，无需拆分。
- 残留的 ~40 处字面量 `"Ma Shan Zheng", cursive`（雷/冰/毒/风等塔）**本次不动**：
  与 `CONFIG.FONTS.BRUSH` 渲染结果一致，迁移属无关重构，列入后续建议。

## 6. 验收标准

1. 火/水/木/金/土/山六种塔落到网格后，笔画呈现书法飞白，与底部卡牌字形一致。
2. 拖拽放置时的半透明预览与落地后**字形一致**。
3. 融合塔（如「心中炎」「如风似真」）两行文字同为书法体。
4. 地图上的"入口"、`Lv2`、HP 数值、`入口`/`融合` 标签仍为原黑体可读样式，未被误改。
5. `npm test` 全绿。
