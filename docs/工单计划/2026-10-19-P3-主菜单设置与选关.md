# 工单：P3 主菜单、设置与选关横屏改版

- 日期：2026-10-19
- 上级方案：[全界面横屏适配与水墨视觉统一](2026-10-19-横屏适配与水墨视觉统一.md) 第 3.2 节「主菜单」「设置」「主题选择 / 选关」；问题编号 A5、A6、A7、A8、A9、B2、B3、B5
- 依赖：P1 令牌与组件、P2 的 `.ink-page` 用法与 `probe-codex.js` 巡检写法

## 1. 任务目标

1. **主菜单**：横屏左右构图。左侧放竖排题名「墨守成规」和朱印，右侧放四个入口竖列（大字、名称、一句说明），带墨块按下反馈；修复题名「墨」与「成」叠压（A8）。
2. **设置合并**：主菜单设置和战斗暂停设置**共用一个组件、一份状态**。分「画面」「声音」两组，开关统一用印章开关（`.ink-switch`），音量用滑块；在任一处修改，另一处即时同步（A9、B5）。
3. **统一长卷选关**：塔防和征服共用同一个「择卷 → 长卷」组件（A5、A6、A7）。
   - 择卷页：主题卡居中放大，显示题字、名称、简介、进度。
   - 长卷页：关卡节点沿一条墨线均匀分布，节点为「印章序号 + 关名」，完成的关卡盖朱印；底部固定「关卡信息条」：境序、关名、要点、「入境」主按钮。征服模式也改为「先选再入境」。
4. **导航文案统一**为「‹ 上一级」，放在顶栏左上（B3）；征服标题去掉开发者式的连字符（B2）。

## 2. 当前问题 / 背景（已核对代码）

- 结构：`js/bootstrap/page-markup.js` 中的主菜单、`#settings-container`、`#theme-select-container`、`#level-list-container`、`#conquest-theme-select-container`、`#conquest-level-select-container`（征服部分是写死的 5 个主题 × 5 关占位，由 JS 覆盖）。
- 逻辑分散：
  - `menu.js`（486 行）：`showThemeSelect`、`renderThemeSelect`、`showLevelSelect`
  - `menu-2.js`：兼容旧方法
  - `menu-scroll.js`：`renderLevelSelect`
  - `conquest.js`：征服的择卷和选关，点击关卡直接开局
  - 共用的悬浮按钮 `#back-to-menu` 和 `#back-to-themes`
- 设置分散在四处，并且两边的条目不一致：
  - `ink-interactions.js`：墨迹动效
  - `settings-feedback.js`：打击反馈
  - `battle-pause.js`：伤害数字、震动
  - `audio.js`：音效和音乐的开关、音量；`syncButtons` 会直接改写按钮的 `textContent`
- 旧样式分布在 `foundation.css`、`pages.css`、`audio.css`、`mobile.css`、`inline/part-01/03/04/05`、`style/part-02/04/05`，这些文件中有约 340 条相关规则。
- 优先级冲突：`pause.css` 中的 `.battle-layer button` 优先级是 (0,1,1)，会盖过 `.ink-switch`。

## 4. 实施步骤

1. 编写设置组件：条目包括画面组（墨迹动效、打击反馈、伤害数字、震动）和声音组（音效、音乐，各带音量滑块）。存储键沿用现有键（`moshou-ink-motion`、`CONFIG.GLYPH_FEEDBACK.storageKey`、`moshou_damage_numbers`、`moshou_screen_shake`），保证玩家原有设置不丢失。
2. 主菜单设置页改为 `.ink-page`；战斗设置弹层改为同一组件渲染；`audio.js` 兼容印章开关。
3. 主菜单改为左右构图。
4. 编写长卷组件，接入塔防和征服；删除共用悬浮按钮。
5. 清理旧规则（用脚本按选择器删除失效规则，保留选择器列表中仍然有效的部分），并排除 `ink-` 组件的优先级冲突。
6. 在横屏矩阵中巡检，回归设置持久化、进入关卡、战后返回选关；运行 `npm test`。

## 5. 风险与注意事项

- **玩家设置兼容**：存储键和取值（`'on'`/`'off'`、`'full'`/`'reduced'`）保持不变。
- **战后返回**：`Game.returnToLevelSelect` 和 `ConquestGame.returnToLevelSelect` 调用 `showLevelSelect` / `showConquestLevelSelect`，这两个函数名和参数保持不变。
- **战斗设置弹层**位于缩放容器内（当前缩放约 0.6），印章开关在手机上会显得偏小，等 P4 调整战斗布局时一并解决，本批不处理缩放。
- **音效点击**：`audio-director.js` 的 `TAP_TARGETS` 需要加入新的可点类名。
- **行数**：`menu.js` 迁出函数后会变短；新文件都要少于 600 行。

## 6. 验收标准

1. 在 640×360 到 932×430 的横屏矩阵中（含刘海安全区）：主菜单、设置、择卷、长卷的所有元素都在首屏，没有叠压和溢出，可点元素不小于 44px。
2. 主菜单题名不再叠压；四个入口都有按下反馈。
3. 设置：主菜单和暂停中显示相同的条目；在一处修改，另一处同步；刷新页面后保持；关闭打击反馈、伤害数字、震动时，`GlyphFX` 的对应字段同步变化。
4. 塔防和征服的选关外观一致：默认选中第一关，底部信息条显示关卡信息，点「入境」才开局；战后能回到对应的长卷。
5. 所有返回入口都在顶栏左上，文案为上一级名称。
6. `npm test` 全部通过；`check:tokens` 中新文件零违规。
