# 水墨 UI 全界面重构实施工单

## 任务目标

执行《moshou-UI重构设计方案》，在保留 960 × 432 Canvas 战场、纯静态架构、现有玩法和宣纸基色的前提下，让主菜单、关卡、图鉴、战斗 HUD、炮塔详情、融合、胜负及征服/自定义入口使用一致的「纸、墨、字、朱印」视觉语言。

## 当前问题与背景

- 方案指出正式界面仍有矩形卡片、网页按钮、Emoji 图标和普通弹窗。
- `js/bootstrap/page-markup.js` 中存在图鉴、自定义、征服主题的 Emoji 与卡片结构；真实样式分布在 `css/style/`、`css/inline/`，交互分布在 `js/ui/`。
- `docs/ui-design-spec.md` 仍包含 800 × 480 等旧尺寸描述；实际入口 Canvas 为 960 × 432。
- 修改前 `npm test` 退出码为 0；其中 `test:balance` 文本报告已有数值目标未达标，本任务不调整数值。

## 涉及文件

- 页面装配：`js/bootstrap/page-markup.js`，必要时 `index.html`。
- 样式：`css/style/`、`css/inline/` 中相关模块；按职责新增不超过 600 行的样式模块。
- 界面逻辑：`js/ui/` 中主菜单、关卡、图鉴、面板、融合与 HUD 相关文件；必要时游戏现有胜负/融合反馈调用点。
- 规范与交付：`docs/ui-design-spec.md`、本工单、`docs/完成报告/` 中对应报告。

## 实施步骤

1. 核对 UI 实现、事件调用链、缩放机制、主要场景和现有测试，记录基线。
2. 建立统一纸墨朱印的颜色、题字按钮、选择/锁定、古籍版式与短动效；移除正式入口 Emoji。
3. 重构主菜单与入口仪式感；将关卡变为可横向浏览的山河长卷，将图鉴变为字谱列表加详情。
4. 调整战斗 HUD、炮塔栏和详情墨签，保持数值与操作可读、触控区域充分。
5. 为融合成功与胜负增加合字、落印、书写反馈；让征服和自定义入口沿用同一风格。
6. 修正 UI 规范中的实际尺寸与交互描述；运行测试并在浏览器检查桌面和移动横屏关键流程。
7. 在 `docs/完成报告/` 记录实际改动、验证、未解决项及工作区状态。

## 范围与风险

- 不改平衡数值、关卡数据、存档格式、核心塔防规则；不引入构建工具、框架或 TypeScript。
- 保留用户未跟踪的原方案文档，不创建/切换分支，不提交或推送。
- 动效必须短且可在减少动态效果偏好下停用；不能延迟融合结算或阻塞胜负操作。
- 移动端保持现有 `--ui-scale`、Canvas 坐标补偿与横屏路径；改动不得改变山字塔特殊放置规则。
- 若现有文件接近 600 行，优先按样式/界面职责拆分，不为行数压缩代码。

## 验收标准

- 主菜单、关卡、图鉴、战斗、融合、胜负、征服与自定义入口显示一致的纸墨字印样式；正式图标以汉字呈现，不再以 Emoji 识别功能。
- 关卡可浏览/选择、图鉴可筛选/查看、炮塔可选择/升级/出售、融合与胜负流程仍可操作；状态不依赖 Hover 才可辨识。
- 960 × 432 Canvas 保持完整，桌面与移动横屏的主要可见按钮可触控；减少动态效果下仍能理解反馈。
- `npm test`、行数检查和浏览器关键路径检查有真实结果；与修改前基线区分。
- 完成报告记录验证证据和未验证范围。
