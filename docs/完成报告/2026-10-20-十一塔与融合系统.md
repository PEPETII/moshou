## 三、关键实现

- **结构与火、水一致**：每座塔都由三部分组成：
  - `CONFIG.TOWERS[type]` 条目（字段为 char / cost / size / desc）；
  - `CONFIG.GLYPHS[type]` 笔画数据；
  - 招式参数。

  招式参数统一经 `applyGlyphMoves(raw, pxKeys)` 注入 `TOWERS[type].glyph`，像素量乘 `GLYPH_SCALE`，射程同步成格数。原先只服务火水土木的注入函数改成了通用函数，三份配置文件共用。
- **注册表**：`GlyphTower.impl` 改为查 `GlyphSystem.IMPLS`，查不到时退回水塔（与旧行为一致）。新增一座塔只需在注册表里登记一行。
- **合字字形由组合生成**：`glyphs-fusion.js` 把素材字的笔画按部件位置缩放、平移后拼起来（炎为上下两火，林为左右两木，焚为上林下火），不手写坐标。合字塔的招式参数单独配置。
- **路径相关的招式**：`kit.js` 提供 `wrapS`、`pathDelta`、`alongTrack`，在征服的环形路径上也能正确工作。旋风、藤蔓、燎原、飞剑、山的震荡都按沿路距离结算。
- **山的挡路**：复用敌人一侧已有的阻挡链（`checkBlocking` → `blockingTowerByCell` → `takeDamage` → `removeTower`），只需给山配置 `onPath` 和 `hp`。征服模式召唤出的山不放在路上，只用它的招式。
- **爆燃不递归**：燃烧中被击杀的敌人只在 `blaze.pending` 里登记，下一帧再结算爆炸，避免连锁击杀时递归调用。
- **敌人状态**：湿身、减速、寒三者叠乘，总减速上限 80%（`slowCap`）。冻结记在新字段 `iceTime`，不复用旧冻结链的 `frozen` 布尔值，因为旧代码会把它重置。破甲倍率在 `Enemy.hit` 里统一乘上，灼烧的伤害数字也会同步体现。
- **火塔大招改名**：火塔大招原名「焚」，与合字塔「焚」重名，说明与图鉴里改称「燎」，招式本身不变。

## 五、未解决问题

1. **潮档会漏怪**：第一次手测把塔只摆在第一段路，潮档（每秒 6.5 只）下核心被打穿。原因是我的布局只覆盖了第一段路，不是代码缺陷，但说明默认潮档对新塔组合没有调过。按 D12，本阶段未做数值平衡。
2. **右侧塔卡需要滚动**：12 张卡在两列网格里，桌面 1280×720 下只能看到前 8 张，其余要在卡栏内纵向滚动，没有滚动提示。
3. **炮的盲区很小**：塔紧贴路边时，离路最近的距离是 72px，盲区只有 81px，只有正前方一小段打不到。
4. **合字塔售价**：按自身造价的 70% 退墨，低于两份素材加合成费的总和，未单独设计。
5. **工作区未提交**：工作区里还有此前「删除下架炮塔残留」那批未提交的改动。本次在它的基础上开发，没有提交或推送。

## 六、后续建议

- 做一轮数值平衡：以潮档、两关为基准，用 `test-glyph-towers` 的驱动跑各塔的 DPS 与控制时长，再定 D12 之后的目标区间。
- 卡栏：给 12 张卡加滚动提示（底部渐隐或页码点），或在宽屏下改成三列。
- 融合可视化：选中素材塔时，在相邻的可合素材上画一圈提示，减少玩家找素材的成本。
- 已有的 `onKill` 回调与新状态（减速、寒、破甲）可直接用于后续合字（例如冰＋水）与塔之间的联动设计。
