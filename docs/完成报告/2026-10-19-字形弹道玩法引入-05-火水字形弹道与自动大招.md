## 实际完成内容

1. **配置**（`js/config/glyphs.js`，新建，在 `glyph-battle.js` 之后加载）：`CONFIG.GLYPHS`（火、水笔画数据，照搬原型）、`CONFIG.GLYPH_COLORS`、`CONFIG.GLYPH_TOWER`（初始蓄力 0.35、写出整字动画、圆相环尺寸）。原型 `TOWER_CFG` 的全部招式参数以原值保存在 `GLYPH_MOVES_RAW`（带 `[px]` 标记的是像素量），加载时乘 `GLYPH_SCALE` 后写入 `CONFIG.TOWERS.fire/water.glyph`；`chargePerSec`、`chargePerHit` 与时间、伤害、概率照搬。同时把 `Tower.range`（格）同步为招式射程 / `CELL_SIZE`，射程圈、信息面板、拖拽预览自动复用。`domain-02.js` 里火、水加 `size: 68`，说明改为新的招式描述（普攻、大招各一句）。
2. **笔刷与特效**：`js/glyph/brush.js` 照搬原型（仅配色改读配置）；`js/glyph/fx.js`（`GlyphFX`）只含世界层的粒子、冲击环，发射参数按原型像素给出、内部统一乘 `GLYPH_SCALE`，粒子封顶 700。打击反馈相关接口（`addShake`、`addHitstop`、`number`、`stain`、`stampGlyph`、`shatter`、`kill`）**预留为空函数**，招式代码已在原型对应位置调用，06 填实现即可。
3. **适配层** `js/glyph/adapter.js`（`GlyphWorld`）：`enemiesInRange`（塔防走 04 的空间分桶，征服没有索引则退化为全量扫描）、`nearestEnemy`、`tracks`、`bounds`、`damage`（统一走 `Enemy.hit` → `takeDamage`）。没有新建任何与原型同名的全局变量。
4. **字形塔组件** `js/glyph/glyph-tower.js`（`GlyphTower`）：每座 `Tower` 实例持有 `tower.gl`（`strokes[]`、`charge`、`timer`、`nextDot`、`recoil`、`readyPulse`）。新塔放下时 `charge = 0.35`，所有笔画 `prog` 从 0 起按笔顺写出。每帧推进笔画写回、蓄力、自动大招、普攻。射程虚线圈只在选中塔时显示。塔身用 `Brush.drawGlyph`（68px），写回中的笔画用元素色，满蓄时整字元素色并发光，`shadowBlur` 只用于满蓄塔；圆相蓄力环在塔身外圈。
5. **全局调度** `js/glyph/system.js`（`GlyphSystem`）：弹道列表 `game.glyphShots`、全局大招间隔 `ULT_GLOBAL_GAP = 0.6`（`game.glyphUltCd` 倒计时）、统一推进与绘制。弹道与塔实例解耦，塔被出售后已发出的弹道继续完成。
6. **火** `js/glyph/fire.js`：火星（左右点轮流、追踪、灼烧、暴击、命中加蓄力）；焚（落点沿 `track.sample(16×S)` 在**本塔**射程 1.15 倍内、离入口 150×S 之后的路段里挑，巨权重 4；征服环形路径不限入口距离；落地爆炸、火字焦土、周期灼烧）。
7. **水** `js/glyph/water.js`：水箭（竖钩拉长，贯穿、击退、打湿，单发最多按 3 个命中充能）；潮（浪头为里程值，从射程内最靠前敌人前方 `40×S` 处涌起，向来路倒卷）。塔防倒卷下限为 `80×S`；征服（环形）为 `max(0, s0 − 推回距离)`，不绕过 0 点；`carried` 不为空的敌人不再被卷入；浪太靠近起点、没有倒卷空间时 `cast` 返回 `false`（新增配置 `waveMinTravel`），不浪费蓄力。
8. **自动大招**：射程内有敌人、`charge ≥ 1`、全局间隔已过时自动 `cast`，返回 `false` 则下一帧重试。**没有任何手动入口**（原型的点塔释放、`Q`/`W`、「点塔 · 焚/潮」提示均未移植）。
9. **接入**：
   - 实际生效的 `Tower.reset` / `Tower.update` 在 `js/entities/towers/misc.js`（它覆盖了 `js/tower.js` 里的同名类方法），两处都已加上字形塔分支：`type` 为火、水时 `update` 委托 `GlyphTower`，**不再走旧攻击与投射物管线**；`js/entities/towers/rendering-basic.js` 的 `Tower.draw` 委托 `GlyphTower.draw`。旧管线的共用部分未动。
   - 两种模式的 `update` 开头 `GlyphSystem.tick`、敌人移动后 `GlyphSystem.update`；`draw` 顺序改为：地面效果（焚后火字）→ 敌人 → 塔 → 弹道与大招 → 粒子 → 字形特效，全部在世界层内（镜头平移内）。
   - `resetBattleState`（塔防、征服各一份）里 `GlyphSystem.reset`，换关、重开时清空弹道与特效。
   - `Enemy.hit` 击杀后调用 `GlyphFX.kill(enemy, kind)`（空函数，供 06）。
   - 放置预览：塔防拖卡片时目标格画半透明的火字或水字（不可放置时偏红）并保留射程圈；塔防拖动已放置的塔、征服拖塔也改画字形幽灵。
   - 信息面板与图鉴：字形塔的旧伤害、攻速、减速清零不再显示，范围显示为一位小数；图鉴详情只列射程、造价与招式描述。

## 关键实现 / 与工单的差异

- **`Tower.range` 改为招式射程换算值**（火 2.42 格，水 2.21 格，原为 4.2 / 3.2），旧塔管线本就不再用于火、水；平衡护栏测试照常通过。
- **字形特效半径按原型像素传入**：`GlyphFX.emit/ring` 内部乘 `GLYPH_SCALE`，招式里直接写原型数值，避免重复乘。
- **焦痕 / 墨渍层未做**：焚落地后的「焦痕印在墨渍层」依赖 06 的墨渍层，本工单只调用 `GlyphFX.stain/stampGlyph` 空函数，焦土本身（火字、灼烧、火苗）已完整实现。
- **范围查询**：塔防复用 04 的 `runtimeIndexes.enemiesInRange`；征服没有该索引，退化为全量扫描（敌人数 ≤ 260，实测无压力，但若征服里同时有很多塔，可考虑给征服也建索引）。
- **水箭判定**用线段中点为圆心的圆做一次空间查询，再逐个精确判定，不再全量扫描。
- **旧的双份类方法**：`js/tower.js` 里的 `reset/update` 被 `entities/towers/misc.js` 覆盖，实际生效的是后者；本次两处同步改动，避免误导。

## 未解决问题

1. **DPR = 2 的清晰度**：主画布固定 960×432 逻辑像素（03 已说明「未按 DPR 渲染」），字形塔和其他元素一样在高分屏上由 CSS 放大，不是 DPR 原生分辨率；笔画是矢量绘制，放大后仍平滑，但没有做真正的 DPR 画布。若要彻底解决，需要改画布与镜头/坐标换算（超出本工单），建议单独立项。
2. **手机横屏帧率仍未实测**（04 已留此项）：本工单只在桌面浏览器验证；满蓄塔的 `shadowBlur` 与飞行火字的发光是主要开销，真机不达标时可下调 `glowBlur` 或粒子上限 `GlyphFX.MAX_PARTICLES`。
3. **打击反馈、墨渍、焦痕、碎字、连斩**均属 06，目前是空函数；击杀时没有视觉反馈（只有粒子与奖励墨）。
4. **火塔密集时的火星追踪**：原型的追踪搜索半径 260px 乘 0.74 后为 192px；征服内圈密集摆塔时火星偶有在同一目标上扎堆，不影响正确性，未处理。
5. 信息面板仍是旧版样式（只显示射程、说明与出售）；出售价、旧版「升级」入口相关均已在 02 移除。
