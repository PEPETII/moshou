# 完成报告：P4 战斗界面横屏布局（塔防 · 征服）

- 日期：2026-10-19
- 对应工单：[2026-10-19-P4-战斗横屏布局](../工单计划/2026-10-19-P4-战斗横屏布局.md)
- 解决的问题编号：A1、A2、A3、B7（见[总方案](../工单计划/2026-10-19-横屏适配与水墨视觉统一.md)），以及 P3 遗留的「战斗设置偏小」；另外修复了两个原有缺陷（见第 5、6 条）

## 实际完成内容

1. **塔防**：画布 960×432 占满容器。
   - 顶栏改为叠在画布上的 HUD：左侧是「墨 · 守时 · 尸 · 关卡名」，右侧是核心朱印。HUD 半透明、边缘渐隐，`pointer-events: none`，点击会穿透到地图。
   - 塔栏改为**画布右缘的竖排卡槽**，暂停按钮（「停」）放在卡槽顶部。
   - 顶栏里的音效、音乐按钮已移除（设置里已有）。
2. **征服**：侧栏改为**画布左缘的竖条**，自上而下是朱红「召」按钮（带实时费用）、墨、守时、危，最下方是「退」（返回选关）。规则说明、标题、分隔线和音效、音乐按钮已移除。
3. **镜头余量**：`Camera` 新增 `insetLeft` / `insetRight`。
   - 塔防最右可以多滚 84px，核心列能完整露在卡槽左侧。
   - 征服的最小 x 为 -84，开局时世界第 0 列紧贴竖条右缘。
   - 拖卡时的边缘自动滚动区改为以可见区为准；指针在卡槽上不会触发滚动，避免拿卡一起手镜头就跑。
   - 边缘墨晕和位置条也改为以可见区为准。
   - 遮挡宽度统一由 `CONFIG.BATTLE_DOCK_W` 定义，并同步为 CSS 变量 `--battle-dock-w`，布局与镜头同源。
4. **弹层**：暂停和设置弹层移出缩放容器，改为 `position: fixed`，按真实屏幕尺寸显示，并让开刘海安全区。设置弹层的「‹ 暂停」和标题排在同一行。
5. **原有缺陷修复 · 触摸拖卡偶发失败**：触摸按下时，浏览器会把指针隐式捕获在被按的子元素（`.tower-char`）上；开始拖拽时代码把捕获转给塔卡，子元素因此收到一次 `lostpointercapture`，而 document 级的监听不分来源，直接取消了放置。现在只有「我们主动捕获的那张塔卡」丢失捕获时才取消（`js/ui/input.js`）。
   - 说明：同一段处理逻辑在 HEAD 上就存在，机制与布局无关；但我没有在 HEAD 上端到端复现（HEAD 的脚本环境里没找到可放的格子，没有继续深挖）。在新布局上，修复前真实触摸拖卡 0 次成功，修复后 6 台设备全部成功。
6. **原有缺陷修复 · 征服召唤费用写死**：费用原来写死为「80墨」，实际是 50 墨起、每召唤一次涨 4%。现在每帧随 `getSummonCost()` 更新。
7. **其他**：塔卡手势的滚动轴随塔栏排布方向切换（竖排时竖滑滚动、横向拖出放置）；画布左上角 14px 的关卡名改由 HUD 显示；战场字号新增一组「画布逻辑 px」令牌（`--bfs-*`）。
