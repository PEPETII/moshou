## 已确认结论、限制与后续事项

- **已确认**：入口脚本、CSS 加载路径、真实关卡选取、放塔/升级/融合与移动触摸关键路径可运行；证据为上述浏览器操作、状态变化和截图。
- **已确认**：移动战场中央的深灰横带来自原有 `js/core/rendering.js` 的 `drawPath()`，即关卡道路，不是残留加载条；加载层计算透明度为 0。
- **推断**：其余关卡与设备会沿用同一界面结构。依据是共用渲染与缩放路径；尚缺所有关卡、真机和不同浏览器的逐项运行证据。若推断不成立，个别屏幕或关卡可能出现遮挡；后续应在目标设备上跑一遍完整关卡与胜负操作。
- **未验证**：真实移动设备、所有关卡的完整通关/失败流程、长期运行性能、网络字体不可用时的最终视觉。浏览器中胜负弹层进行了渲染检查，未以完整对局打到结局。
- **后续建议**：若另开平衡性工单，应先修正 `test:balance` 返回码与文本结论不一致的问题，再针对已有未达标数值进行调整；该问题不属于本次 UI 范围。
