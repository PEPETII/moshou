## 1. 实际完成内容

### 1.1 根因

底部卡牌栏是 **DOM 元素**，字体由 CSS 控制，正常生效；炮塔是 **Canvas `fillText`**，
字体只能由 `ctx.font` 决定，**CSS 完全不参与**。项目内不存在任何 `@font-face`，
书法字体唯一来源是 `index.html:15` 的 Google Fonts 外链，且 `js/bootstrap/init.js:11`
已在 `initGame()` 前通过 `document.fonts.load('1em "Ma Shan Zheng"')` 完成预加载——
**字体本身早已就绪，不存在加载时序问题**。

真正的根因是：**五行基础塔（火/水/木/金/土）、山塔、基础兜底塔的 `ctx.font` 被硬编码为
`Microsoft YaHei`**。后期加入的塔（雷/冰/毒/风/霜/鼓/旗…）统一写的是
`"Ma Shan Zheng", cursive`，属早期代码漏改造成的新旧两代写法并存。

## 2. 关键实现

### 2.1 字体栈集中化

`js/config/domain-01.js`：

```js
FONTS: {
  BRUSH: "'Ma Shan Zheng', 'ZCOOL XiaoWei', 'KaiTi', 'STKaiti', serif",
  TEXT:  "'ZCOOL XiaoWei', 'Microsoft YaHei', serif",
},
```

符合 `AGENTS.md`「数值/常量必须集中配置，禁止在散落模块中写死」的约定。
`js/config/domain-01.js` 在 `index.html:24` 加载，全部消费方（41/43/58/78 行）均在其后，
`CONFIG` 为全局绑定，运行时无作用域风险。

### 2.2 修复 CJK 兜底失效

原写法末尾的 `cursive` 是**拉丁通用族名，不含 CJK 字形**，一旦 Web Font 失败，
中文会直接掉到系统默认中文字体（Windows 下即微软雅黑）——等于**根本没有兜底**。
新栈显式追加 `KaiTi`（Windows 楷体）/`STKaiti`（macOS 楷体），
最坏情况退化为楷体这种笔锋字体，而不是无衬线黑体。

### 2.3 未改动任何数值

所有改动仅替换字体族声明，**字号算式（`${28 * scale}px`）、颜色、坐标、动画参数全部保持原样**。
`rendering-basic.js` 改后 481 行、`rendering-advanced.js` 445 行，均未超 600 行上限。

### 3.2 无浏览器渲染验证（新增）

用本机已有的 `@napi-rs/canvas`（复用托管 node 工作区依赖，零安装）搭了一个最小渲染夹具，
**直接求值项目源码里的 `CONFIG.FONTS.BRUSH`**（而非抄副本），注册本机 `simkai.ttf`(楷体)、
`msyh.ttc`(微软雅黑) 后做三组断言：

```
[1] 从 domain-01.js 读到的 CONFIG.FONTS.BRUSH = "'Ma Shan Zheng', 'ZCOOL XiaoWei', 'KaiTi', 'STKaiti', serif"
[2] ctx.font 设置后回读 = "bold 28px 'Ma Shan Zheng', 'ZCOOL XiaoWei', 'KaiTi', 'STKaiti', serif"
    => 字符串被引擎接受(未静默回退) : PASS
[3] 字形位图哈希（值不同 = 解析到了不同字面）
    旧:bold 28px Microsoft YaHei    1f7e3379
    新:CONFIG.FONTS.BRUSH           2bd339a4
    参照:KaiTi                       2bd339a4
    => 新字体栈已脱离微软雅黑        : PASS
    => 缺字时兜底到楷体(KaiTi)而非黑体: PASS
```

**为什么这个验证是必要的**：`ctx.font` 语法非法时浏览器**不报错、静默保留上一次的值**，
纯代码审查查不出这类失败。断言里特意加了 `KaiTi` 参照栈做负控制——
只证明"新旧不同"是不够的，因为那也有可能意味着两者都退化成了默认字体；
"新栈哈希 == 参照 KaiTi 哈希"才证明兜底确实落到了预期字面。

对照图已归档：`docs/test-results/2026-09-26-tower-font-stack-compare.png`
（第 1 行为旧行为微软雅黑，第 2、3 行为新字体栈与楷体参照，三者肉眼可辨，且 2/3 完全同形）。

> 说明：本机未安装 `Ma Shan Zheng`，所以本地渲染落到栈内下一个能命中的 CJK 字体（楷体）。
> 用户在浏览器里 `Ma Shan Zheng` 是已加载的（卡牌栏能正常显示），因此炮塔会直接显示真正的书法体，
> 而非楷体。该验证覆盖的是"字体栈能正确命中并逐级兜底"这一机制本身。

## 5. 后续建议

1. **自托管字体（优先级最高）**：下载 `Ma Shan Zheng` / `ZCOOL XiaoWei` 的 woff2 到
   `assets/fonts/`，用 `@font-face` + `font-display: swap` 声明，去掉 Google Fonts 外链。
   收益：消除外网依赖、`document.fonts.load()` 等待时间从数百毫秒降到接近 0。
2. **收敛字体栈用法**：把残留的 ~40 处字面量统一迁移到 `CONFIG.FONTS.BRUSH`，
   并让 `js/ui/notifications.js` 的 DOM 内联样式也引用同一配置（目前它写死 `Microsoft YaHei`）。
3. **补一条 lint 规则**：禁止在 `ctx.font` 中出现未走 `CONFIG.FONTS` 的写死字体族名，
   从机制上防止同类问题再次出现。
4. **平衡性问题单独立项**：辅助塔达标率 20%、战斗节奏 42.9%、融合价值 0% 需要单独工单处理。
