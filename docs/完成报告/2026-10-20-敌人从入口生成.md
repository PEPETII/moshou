# 敌人从入口生成（修复开战瞬间铺满路径）

## 实际完成内容

1. **删除开局预铺**：`BattleDirector.begin()` 不再调用 `prefill()`，`prefill()` 方法与
   `SPAWN.prefillCount / prefillStart / prefillSpacing` 三项配置一并移除。
   开战后敌人一律走正常刷怪：`Enemy.reset` 里 `s = random × startSpread`（0~20px），
   `PathTrack` 的入口已向画外延伸一格（`extendEntry`），因此是从画外走进来的。
2. **开战即收掉开场演出**：`Game.prototype.beginBattle` 先 `inkTrailAnimation.stop()` 再开战。
   修掉一个实测问题——玩家快速点「开战」时，未盖章的塔卡仍是 `opacity: 0` + `pointer-events: none`，
   12 张里只有 1 张可点，持续数秒。
3. **测试**：`tests/test-path-track.js` 的预铺断言改为"开战当帧为空、随后从入口生成"；
   新增 `tests/test-spawn-entry.js`（`npm run test:spawn`），覆盖生成时机、生成位置、开战收演出三条契约。

## 关键实现

```js
// js/core/spawner.js —— begin 不再预铺
game.battleActive = true;   // 计时、计数归零，敌人由 update() 按密度从入口刷出
```

```js
// js/core/waves.js
Game.prototype.beginBattle = function(densityKey) {
    // 开场演出只属于开战前：开战即收尾，否则还在飞行途中的塔卡会继续隐藏且不可点
    if (this.inkTrailAnimation && this.inkTrailAnimation.active) this.inkTrailAnimation.stop();
    BattleDirector.begin(this, densityKey);
    ...
};
```

入口位置无需额外处理：`PathTrack.fromCells` 在 `extendEntry` 时把首点向画外退一格，
`s = 0` 对应世界坐标 `x = -36`（1-1 关），敌人生成即从画外进入。

## 未解决问题

- **入口处敌人会叠成一团**：潮档 6.5 只/秒、尸速 34px/s，理论间距约 5px，小于敌人 26px 的身形。
  这是密度与速度的既有关系（连续刷怪一直如此），不是本次改动引入；只是过去开局的 12 只被预铺拉开，
  现在全部从入口排队，视觉上更明显。
- **开局前几秒中段塔位没有目标**：预铺删除的必然结果。首只敌人在 `1/rate` 秒出现
  （潮 0.15s、常 0.29s、稀 0.63s），走到中段需要数秒。
- 开战前的开场演出仍保留尸/鬼/巨飞入（原有设计，属于演出，不是真实敌人），本次未改。

## 后续建议

1. 若希望"开战即有压力"又保持从入口进入，可在入口外做**排队区**（支持负里程或延迟出场队列），
   让一批敌人依次从画外走入，而不是把敌人摆到路径中段。
2. 观察稀档开局是否偏空；如需保留开局强度，优先调 `DENSITY.sparse.rate`，不要恢复中段预铺。
3. 入口叠团若影响可读性，可给同帧生成的敌人加大 `laneRange` 抖动，或按体型给最小生成间距。
