## 关键实现：网络通道问题与解法

首次推送连续失败，三种错误形态逐一排查：

1. `schannel: server closed abruptly (missing close_notify)` —— 沙箱代理中断 TLS
2. `CONNECT tunnel failed, response 502` —— 沙箱代理 `127.0.0.1:7570` 拒绝 `github.com:443`
3. `Failed to connect to github.com:443 after 21077 ms` —— 绕过代理直连时，443 端口被网络层阻断

诊断结论：

- `github.com:443` 直连不通；`api.github.com` 经沙箱代理可达（200）
- `github.com:22` 与 `ssh.github.com:443` 的 TCP 层可连通（返回 `Permission denied (publickey)`，即网络通、仅缺密钥授权）
- 本机存在代理 `127.0.0.1:7897`，可正常访问 `https://github.com/`（200）
- Git 凭据已存在于 Windows 凭据管理器（`git:https://github.com`、`gh:github.com:PEPETII`），无需重新认证

最终可用命令（清除环境代理变量后显式指定 7897）：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy \
  git -c http.proxy=http://127.0.0.1:7897 push origin main
```
