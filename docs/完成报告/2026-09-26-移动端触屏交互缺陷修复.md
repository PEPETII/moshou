## 一、实际完成内容

把交互层从"桌面鼠标假设"整体改造为"按输入能力分流"，共 13 项修正。

### 1. 设备判定改为按输入能力（新增 `js/bootstrap/device-profile.js`）

旧代码用 `window.innerWidth` 判断设备类型（`<768` 手机 / `769-1024` 平板 / `>1024` 桌面）。
手机横屏时 `innerWidth` 达 844~1024px，会被判成"平板/桌面"，从而切到依赖 hover 与鼠标的分支——
这是移动端交互失效的根源。现改为 `matchMedia('(pointer: coarse)')` + `(hover: none)` + 触摸硬件探测，
并集中输出三档触摸参数：滑点 12px、选塔容差 0.75 格、长按阈值 420ms。

### 2. 缩放算法改为实测迭代

`js/bootstrap/viewport.js` 重写：
- 不再用硬编码的 `1264 × 480` 估算，改为实测当前可见根元素（塔防 `#game-container` / 征服 `#conquest-container`）的自然尺寸；
- 迭代逼近（最多 4 轮，收敛阈值 0.002）——因为触控尺寸用 `calc(44px / var(--ui-scale))` 反算，改变 scale 会影响实测尺寸，需要反复逼近；
- 扣除 `env(safe-area-inset-*)`（刘海/圆角安全区）；
- 暴露 `window.applyGameScale`，并在 `Game.startGame` / 征服 `startLevel` / `startGame` 后调用。

### 3. 触屏尺寸反算（新增 `css/style/part-05.css`、`css/inline/part-05.css`）

**关键认知**：整棵游戏树挂在 `#scale-container` 的 `transform: scale(s)` 之下，
CSS 里写的 `44px` 会连同缩放一起被缩小（实测 `s=0.636` 时 44px 只渲染出 28px）。
所以既有的 `@media (pointer: coarse) { min-height: 44px }` 在架构上必然失效。
现改为 `clamp(44px, calc(44px / var(--ui-scale)), 88px)` 反向补偿，
渲染后稳定在 44px（上限防止极端小屏把栏撑爆）。

### 4. 触摸交互重写（新增 `js/ui/input-touch.js`，从 `input.js` 剥离）

新增的触摸状态机，五个设计取舍：

| 取舍 | 理由 |
|---|---|
| **按住即预览**：`touchstart` 立即置 `hoveredCell` | 触摸端没有 hover，旧代码只在 `touchmove` 里更新，导致"轻点放置"永远看不到绿/红预览 |
| **落点取按下格**（非抬起格）+ 滑动取消 | 手指滑过再抬起不应改变目标；实测旧逻辑"按下 A 滑到 B 抬起"会在 B 落塔 |
| **选塔带 0.75 格容差，放置零容差** | 选塔是无副作用的读取，可宽容；放置会花金币，必须严格，不做自动吸附 |
| **点已有炮塔优先显示信息** | 该格本来就放不下，不会与放置冲突；消除了对 500ms 长按的依赖 |
| **点空白处 = 取消选中** | 旧代码只有 `contextmenu`（右键）一条取消路径，触摸端等于没有 |

### 5. 失败反馈（新增 `js/ui/toast.js`）

旧代码放置失败时 `placeTower` 静默 `return false`；`showFusionFailed` 只 `console.log`。
现在新增轻提示组件（同消息 900ms 去重、最多 3 条），并新增
`Game.getPlacementBlockReason(type, gx, gy)`（`js/core/towers.js`）把原因暴露给 UI：
"金币不足（需 220 金）" / "该位置已有炮塔" / "这里不能建造" / "「山」只能放在路径上" / "开场准备中…"。

### 6. 横屏布局修复

旧 CSS 把 `#game-container` 限制为 `max-width: 800px`（矮屏 700px），而 `#game-area` 是固定 960px
→ 画布比顶栏/底栏宽出 165.3px，顶栏底栏只覆盖战场左侧 83%。
现固定为 `width: 960px; max-width: none`。

> 期间踩过一次坑并已修正：一度写成 `width: auto`，底栏 38 张炮塔卡在 `overflow-x: auto` 下的
> 最大内容宽度把容器撑到 1415px，缩放基准随之崩掉（scale 从 0.65 跌到 0.386）。

### 7. 炮塔信息面板避让手指

旧实现按触点坐标定位面板，实测面板左上角正好等于触点坐标（被手指完全压住）。
现触摸端改为**停靠在离手指较远的一侧**（左半屏点按 → 面板靠右），
并在触摸端压缩面板行高（`line-height` 2 → 1.6）与内边距，避免 250px 高的面板在 390px 屏幕上顶格。

### 8. 塔卡锁定状态改为实时同步

旧实现只在关卡加载时按金币给卡打一次 `.locked`，之后金币变化完全不更新，
点击又被 `if (el.classList.contains('locked')) return;` 直接吞掉
→ 玩家攒够钱后卡仍是灰的，点它毫无反应。现改为每次 `updateUI` 同步
（新增 `UI.refreshTowerSelectAffordability`），点击时按**当前金币**判断并给出提示。

### 9. 手势归属与安全区

`#game-canvas: touch-action: none`、`#bottom-bar: pan-x`、可点元素 `manipulation`；
`#game-wrapper` 横屏时按 `env(safe-area-inset-*)` 留出安全区。

### 10. 按压反馈全覆盖

新增 5 个 `@media (hover: none) and (pointer: coarse)` 分支（此前全项目 **0 个**），
`html[data-input="touch"]` 下为 40+ 个可点元素补 `:active` 反馈——
此前 `-webkit-tap-highlight-color: transparent` 把系统默认高亮去掉了，替代反馈又只覆盖 3 个类。

### 11. 底栏滑动提示

38 张炮塔卡一屏放不下，用右缘渐隐 + `scroll-snap` 表达"还有内容"，并开启惯性滚动。

### 12. 征服模式滑点同步

`js/conquestGame.js` 新增 `dragThresholdTouch`，`js/modes/conquest/misc.js` 触摸分支改用它
（旧代码与鼠标共用 5px，手指抖动 6px 就会被判成"拖拽移动炮塔"）。

### 13. 征服模式入口空白修复（工单外发现）

`#conquest-container` 位于 `#main-container` 之内，但征服模式只解除自身的 `hidden`，
父级 `#main-container` 仍是 `hidden` → 从主菜单直接进征服模式是**整屏空白**。
实测复现，已修复（`startLevel` / `startGame` 两处补上父级解除隐藏）。

## 五、未解决问题

1. **单格尺寸无法达到 44px（几何硬约束）**：20 列 × 9 行的战场，在 390px 高的手机上单格上限约
   `(390 - 顶栏 - 底栏) / 9 ≈ 31px`。要达 44px 需至少 880×396 的无边框屏幕。
   因此本次没有用"放大格子"解决放置精度，而是用"按住预览 + 按下点落子 + 滑动取消"。
   这是权衡后的结论，不是遗漏。
2. **底栏仍是 38 张塔卡**：`Game.getUnlockedTowers()` 无视关卡数据里的 `unlocks` 字段，
   返回全部炮塔，导致底栏 `scrollWidth 2918 / clientWidth 956`，手机上一屏只能看到约 12 张。
   修正它属于**玩法/平衡变更**（会明显改变可用塔池），未获授权，故未动。
3. **平衡性测试的 3 项不达标**：如上，既有问题，需要数值设计决策。
4. **`page-markup.js` 里 4 处按钮内联样式**：会压过所有 CSS 规则，
   是"改不动样式"的隐患（本次靠 ID 选择器 + 未冲突属性绕过）。
5. **`test-balance.js` 已 598 行**：接近 600 行上限，下次修改需先拆分。

## 六、后续建议

1. **优先决策第 2 项**：`getUnlockedTowers` 是否应改为读取关卡 `unlocks`。
   若确认是漏接，底栏会从 38 张缩到数张，移动端滑动问题随之消失，
   同时这也是原始设计意图（关卡数据里已有 `unlocks` 字段）。
2. 把 `page-markup.js` 的内联样式收敛到 CSS（新增 `#back-to-menu-btn` 基样式规则后再移除）。
3. 建议在 `AGENTS.md` 中固化一条规则：**项目的目标平台是移动端**，
   任何新增交互都必须同时提供触屏路径，且禁止用 `innerWidth` 判断设备类型。
   （现状：`docs/ui-design-spec.md:6` 已写明适用移动端，但代码里仍有 3 处按宽度判设备。）
4. `docs/ui-design-spec.md` §12.1 的基准尺寸（800×480 / 总宽 1104px）与代码（960×432 / 顶栏+画布+底栏）
   已不一致，建议同步，避免后续再次误用。
5. 键盘快捷键（数字键开波、`S` 召唤）在触屏设备上是死代码，可加 `DeviceProfile.isTouch` 守卫。
6. 建议把本次新增的 `E:/news-game/_moshou_verify/` 实测脚本作为工具固化进 `scripts/`，
   供后续移动端改动回归（当前放在项目外，避免污染仓库与行数检查）。
