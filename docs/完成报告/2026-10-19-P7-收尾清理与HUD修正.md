- 对应工单：[2026-10-19-P7-收尾清理与HUD修正](../工单计划/2026-10-19-P7-收尾清理与HUD修正.md)

## 实际完成内容

### A. 塔防 HUD 修正（用户反馈）

1. **地图零遮挡**：「守（核心）/ 墨 / 守时 / 尸」从画布上方移进右侧卡槽，竖排在塔卡下方，与征服的左侧竖条同构。画布上方不再有任何 DOM 叠层；卡槽宽度和镜头余量不变，所以缩放率不变。
2. **数字字体**：数值改用伤害数字同款字体 `var(--font-brush)`（`CONFIG.FONTS.BRUSH`，Ma Shan Zheng）。数值留了 4.2ch 的最小宽度，数字增减时卡槽不跳动。征服竖条的数值同步改用此字体。
3. **关卡名**移到暂停面板，作为标题下方的副标题（「第 1-1 境 · 初阵」）。
4. 原有的 ID（`#ink`、`#hold-time`、`#enemies`、`#core-hp`、`#top-bar .core-stat`、`#hud-level`）全部保留，`rendering.js` 的更新逻辑不用改。

### B. 收尾清理

1. 删除下架玩法的遗留：`js/ui/notifications.js`（`showEventNotification`、`showMerchantEvent`，全仓无调用）、`#event-container` 结构，以及 `.event-notification`、`.merchant-inscription`、孤立的 `#sound-toggle`、`#bgm-toggle` 规则（删除 14 块，修剪 1 处）。
2. 编写失效选择器扫描脚本：找出「选择器里所有 ID 和类在 `index.html` 与全部 JS 中都不存在」的规则，共 19 个失效标记，都属于已删除的融合、升级、波次系统（`comparison-*`、`material-*`、`wave-btn`、`level-panel` 等），并确认没有动态拼接类名的代码。删除 24 块规则；扫描结果从 19 降为 0。
3. `toast.js` 不再写内联样式和色值，外观移到 `components.css` 的 `.ui-toast`，全部使用令牌（纸面、纤维纹理、朱印竖条）。
4. **检查接入 `npm test`**：
   - `check:syntax`（新）：对 `js/`、`scripts/`、`tests/` 下 136 个 JS 执行 `node --check`；
   - `check-tokens.js --ratchet`（新模式）：以 `scripts/tokens-baseline.json` 为上限，任何文件违规数增加或新文件出现违规都会失败。已实测：往 `codex.css` 加一个裸色值，退出码为 1；移除后退出码为 0。`--write-baseline` 用于清理后收紧基线。
5. `npm run check:landscape`（新）：一条命令依次运行四个横屏巡检脚本，自动汇总越界、过小按钮、溢出、页面错误以及关键流程断言。

## 测试 / 验证结果

- **画布零遮挡**：在卡槽之外的画布可见区内打 13×7 个点，用 `elementFromPoint` 检查最上层元素，6 台设备全部是 `game-canvas`（结果为 `clear`）。
- **数值字体**：`#ink` 的计算字体为 `"Ma Shan Zheng"`，与伤害数字一致。
- **卡槽溢出**：第一轮在 640×360（缩放 0.65）下，暂停按钮被压到 43px。改为卡槽按钮不可压缩、数值区间距收紧、核心印 26px 后，6 台设备都没有过小按钮。
- **`npm run check:landscape`**：`probe-codex`、`probe-menu-p3`、`probe-battle-p4`、`probe-overlay-p5` 在 6 台设备上全部通过（✓），包括拖卡出塔、核心可见、征服镜头、设置同步、胜负按钮流程、转场开关。
- `npm test` 全部通过（已包含语法检查和令牌棘轮）；最大文件 553 行。
- **令牌检查**：裸色值 128 → 99 处，像素字号 75 → 62 处，全部集中在 11 个旧样式文件，已写入棘轮基线。
