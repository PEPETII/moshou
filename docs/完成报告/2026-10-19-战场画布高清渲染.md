# 完成报告：战场画布高清渲染（修复画面模糊）

- 日期：2026-10-19
- 对应工单：[2026-10-19-战场画布高清渲染](../工单计划/2026-10-19-战场画布高清渲染.md)

## 实际完成内容

**根因**：战场画布的位图固定为 960×432，但浏览器按 `devicePixelRatio`（Windows 常见 1.25～1.5）以及页面缩放显示它，每个画布像素被插值拉伸，所以字、塔身、敌人和背景全部发糊。原型 demo 用 `canvas.width = 960 × dpr` 加 `setTransform(dpr)` 渲染，所以清晰。静态背景层、地图底纹和墨廊缓存、墨渍层同样是 1 倍分辨率，也一起修复。

**修复**：新增高清倍率 `RenderScale`，所有战场画布及其离屏层统一按「屏幕实际像素」生成位图；游戏逻辑坐标仍是 960×432 和世界坐标，镜头、命中判定、构图都不变。

## 关键实现

- 倍率 `k = clamp(dpr × 画布显示宽度 / 960, 1, 3)`，按 0.25 向上取整；每 250ms 最多重新测量一次，窗口缩放、切换显示器后自动跟随。
- `RenderScale.setup` 会把画布的 CSS 显示尺寸固定为逻辑尺寸。原因：`#conquest-canvas` 没有 CSS 尺寸，默认按位图尺寸显示；位图一放大，显示尺寸跟着变大，倍率又按显示宽度测量，形成自激放大，一直涨到上限 3。验证中发现了这个问题，已修复。
- Node 测试环境里没有 `getBoundingClientRect`，倍率自动退化为 1。

## 测试/验证结果

- `npm test` 全部通过（包含行数检查）。
- 浏览器（DPR 1.5）：
  - 塔防：位图 1440×648（k = 1.5），墨渍层同步为 1.5 倍；同一区域截图对比，修复后笔画边缘、圆相环、火星轮廓明显更锐利。
  - 征服：显示宽 747、k = 1.25，位图 1200×540，倍率稳定，不再自激放大；画面比例正确。
  - 镜头滚动到 x = 300～400 时，`getGridFromEvent` 的命中格子和目标格子完全一致（塔防、征服都已验证）；视口外返回 `null`。
- 没有在用户的实际显示器上肉眼确认，请在原设备上复查。

## 未解决问题

- 验证时浏览器面板处于隐藏状态，`requestAnimationFrame` 暂停，所以帧率没有实测。倍率为 3 时，静态层位图约 5616×1296，高倍屏下的帧率需要在真机上观察。

## 后续建议

- 如果低端手机帧率吃紧，可以把 `RenderScale.MAX` 降到 2，这是清晰度和性能之间的折中。
