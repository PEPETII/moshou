## 1. 实际完成内容

1. **塔防棋盘**：纯色底 + 硬边路径线 → 宣纸底纹 + 远山 + 苔石 + 淡墨廊道（含飞白边与行进箭标）。
2. **主界面及其它全屏界面**（关卡选择、图鉴、设置、征服选关）：共用同一套地图底纹，**不绘制路径**。

## 2. 尺寸口径（先校事实，再谈「适配」）

工单里先把尺寸这条事实核清了，因为它决定了实现方式：

| 区域 | 尺寸 | 结论 |
| --- | --- | --- |
| 塔防棋盘 | `20 × 9` 格 @ `CELL_SIZE 48` = **960×432** | 与 demo 画布**完全一致** |
| 全屏界面 | 随视口（实测 1440×900 / 1180×760 / 1024×680） | 比 demo 的 960×432 大得多 |

所以「地图尺寸小于项目所需」真正成立的是**全屏界面**，棋盘并不缺尺寸。
据此把地图生成器做成**按目标尺寸参数化**，而不是把 960×432 位图拉伸：

- 纸纹纤维、茶渍、苔点数量按**面积比**换算（`area / (960×432)`）；
- 远山数量按**宽度**换算（每 230px 一座），峰高按**高度比例**锚定；
- 廊道宽度按 `CELL_SIZE` 的比例计算（1.24 / 1.02 / 0.88 倍格宽），因此在任何格宽下都不失真。

棋盘按 960×432 生成，路径与网格逐格对齐；界面按视口尺寸生成，构图规则相同、画幅更大。

## 4. 关键实现

### 4.1 墨廊不是一条粗线，是「外晕 + 墨心 + 积墨 + 飞白」

初版直接照搬 demo 的三层色带，在棋盘上读成一条硬边灰条（实测路径中心只比纸底深 7%，但边界太齐，观感像刷漆）。改成：

1. **外晕**：1.24 倍格宽，`filter: blur(9px)`，4% 墨 —— 消掉硬边；
2. **墨心**：1.02 / 0.88 倍两遍叠加，中路略微更浅，像被水洗过；
3. **积墨**：沿路每 1.9 格随机压一团 6px 模糊的墨，破掉平涂感；
4. **飞白**：边缘按 5px 采样、62% 概率落点，间距随机，不再是整齐的点线；
5. **箭标**：每 112px 一个 `>`，颜色随路段自动旋转（1-3 蛇行关里能看到箭头折返）。

全部烘焙到离屏画布并按 `尺寸|格宽|路径哈希` 缓存，绘制时只做一次 `drawImage`。

### 4.2 路径数据一处未改

`drawPathCorridor(ctx, this.path, CONFIG.CELL_SIZE)` 只是把同一份 `path` 换了个画法。像素换算仍走原有的 `gridToPixel()`，因此敌人行走、核心位置、放置格、`_pathCellSet` 全部不受影响。

### 4.3 界面的「无路径」底图

`MapBackground.drawScreen()` 只画纸、山、苔，再叠一团极淡的墨晕补左上角的空白。主菜单画布与原有泼墨层同层、置其下（DOM 顺序控制），所以「地图在下、泼墨在上、文字最上」，无需改动任何 z-index 体系。

## 6. 未解决问题

1. **征服模式未迁移**。它的 `drawPlacementArea()` 每帧用纯色填充所有空格，会把任何底纹覆盖掉；要接入必须先重构该逻辑。已在工单中标注为不做，日志留档。
2. **高清屏偏软**。棋盘底图按 960×432 的 backing store 生成，`devicePixelRatio > 1` 时由 CSS 放大，边缘略软。若要更锐，需要按 dpr 生成底图并同步 `drawImage` 缩放，改动面比这次大。
3. **泼墨层不透明度是拍脑袋调的**（.25 → .12）。它有 `prefers-reduced-motion` 与模式切换逻辑，我没有动那部分，只调了视觉权重。

## 7. 后续建议

1. 若征服模式也要统一，建议先把 `drawPlacementArea` 改成「只画边框/角标」而不是填色，再挂 `drawTerrain`。
2. `CONFIG.COLORS.pathLine` 目前在塔防模式已不再使用（仅征服与降级分支引用），后续可以考虑统一到 `MapBackground` 的配色常量，避免两套路径色。
3. 棋盘底图可考虑按 `dpr` 生成一份高清缓存，代价是 2 倍显存（960×432 → 1920×864，约 6.6MB）。
