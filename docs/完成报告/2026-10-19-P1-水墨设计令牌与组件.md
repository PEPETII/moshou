## 实际完成内容

1. **设计令牌唯一来源** `css/ink-ui/tokens.css`：纸三档、五墨（焦、浓、重、淡、清）加按下态、朱印与青灰淡赭、两条字体栈、字号六档、间距六档、触控尺寸、页面边距（含安全区）、动效时长。旧令牌名（`--ink-paper` 等）保留为别名，现有样式不受影响。
2. **横屏页面骨架** `css/ink-ui/layout.css`：`.ink-page`（顶栏固定，三列网格，标题居中）、`.ink-page__body`（唯一可滚动区域）、`.ink-split`（40 : 60 主从双栏）；矮横屏和竖屏各有一档适配。
3. **水墨组件** `css/ink-ui/components.css`：`.ink-btn`（基础、`--primary` 朱红墨块、`--ghost`、`--glyph` 大字入口）、`.ink-back`（毛笔折线「‹」）、`.ink-panel`、`.ink-divider`、`.ink-item`（朱砂竖印选中态）、`.ink-chip`、`.ink-switch`（印章亮暗）、`.ink-stat`（标签 · 数值 · 单位）、`.ink-empty`（空状态引导）；都支持减少动效。
4. **`npm run check:tokens`**：统计令牌文件之外的裸色值和像素字号；默认只报告（退出码 0），`--strict` 时有违规返回 1，`--verbose` 逐行列出。
5. **C6 修复**（「回」字显示为实心方块）：根因是外链字体 ZCOOL XiaoWei 的 U+56DE 字形本身有缺陷，**不是**审查时推测的墨点粒子。新增只覆盖 U+56DE 的 `@font-face "Ink Glyph Fix"`（本机宋体、黑体的 `local()` 列表，覆盖 Windows、Apple、Android），CSS 中 103 处字体栈统一换成 `var(--font-text)` / `var(--font-brush)`，JS 中 7 个文件的字体栈（`CONFIG.FONTS`、画布 `ctx.font`、toast、提示文案）都补上了这个兜底字体。
6. **组件样张页** `demo/水墨组件样张/index.html`：只加载令牌、纹理、骨架和组件，作为后续批次的参考。

## 测试 / 验证结果

- `npm test` 全部通过，包括行数检查；新文件行数分别为 tokens 81、layout 119、components 267、check-tokens 96。
- **回归对比**：改动前后对主菜单所有元素（366 个）采集颜色、背景、字号、字重、行高、边框、阴影、透明度、字距等计算样式。改动后颜色、字号、背景类属性**零差异**；只有宽高和边框宽度有亚像素差，原因是两次采样时浏览器面板的设备像素比不同（1.5 对 1）。
- **C6**：画布逐字测量「回」的墨量占比，修复前 0.31（实心），修复后 0.12（正常笔画，与本机 serif 一致）。设置、暂停、择潮的返回按钮计算字体都已包含兜底字体。另外实测确认 425 个在用汉字中只有「回」有问题，Ma Shan Zheng 没有坏字。
- **样张页**（740×360）：顶栏 52px 固定，返回按钮在左上（24, 4，尺寸 70×44），标题居中；只有内容区可以滚动，左栏内容超出时在栏内滚动；页面没有横向或纵向溢出；所有按钮不小于 44px；模拟左侧刘海 `--sal: 44px` 时返回按钮右移到 x=56；选中态的朱砂竖印能正确切换。
- `npm run check:tokens`：新增的三个 CSS 文件零违规；全仓现存裸色值 348 处、像素字号 237 处，集中在 `inline/`、`style/` 两套历史样式。

## 未解决问题

- 验证时浏览器面板处于隐藏状态，截图工具返回的是裁切或过期的画面，所以本批**没有附视觉截图**，验证都依靠计算样式和画布测量。组件的最终观感（飞白描边的浓淡、朱红墨块质感）需要在 P2 首次启用时随页面截图确认。
- 如果设备上没有 `Ink Glyph Fix` 列表中的任何字体，「回」仍会显示为方块（与修复前相同）。最彻底的办法是自托管一个只含若干字的子集字体，但这违反 P1 的约束「不引入新外部字体」，如有需要请另行决定。
- `css/inline/part-01.css:515` 的 `.event-notification` 仍是旧的黑底金边和微软雅黑，属于 P5 / P7 的范围。
- `--touch-min` 在 `css/style/part-05.css:18` 中还有一份同值定义，P7 清理时删除。
