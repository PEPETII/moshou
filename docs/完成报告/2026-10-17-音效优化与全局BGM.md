# 音效优化与全局 BGM：完成报告

对应工单：[2026-10-17-音效优化与全局BGM](../工单计划/2026-10-17-音效优化与全局BGM.md)

## 实际完成内容

**P1 音效**

- 拆分音频模块：`audio.js`（核心、总线、设置）、`audio-cues.js`（音效定义）、`audio-bgm.js`（BGM 引擎）、`audio-director.js`（场景导演）。
- 新总线结构：`音效总线 / 音乐总线 → 总输出 → 压限器 → 输出`，多声叠加时压住峰值。
- 攻击音按炮塔系别分 6 类（火、水冰、风木毒、金属、雷光、土暗），每类独立节流，另有全局间隔；融合塔取第一个组成塔的系别。所有短音效加入 ±3~6% 音高随机。
- 击杀音分小、大、首领三档（首领带钟鸣泛音）。
- 新增音效 7 个：界面点击、升级、出售、拒绝（所有 `warning` 提示框触发）、波次结束、胜利、失败。
- 同时发声数上限 26，超过后低优先级（攻击、击杀）被丢弃，高优先级（波次、核心受击、胜负）不受限。
- 音效与音乐可分别开关并调节音量；设置页新增两行控件，战斗 HUD 与征服面板新增"音乐"按钮。

**P2 BGM**

- Web Audio 预调度节拍器（前瞻 0.28s），不依赖 `setTimeout` 精度。
- 声部：古筝（Karplus-Strong 缓冲，按音高缓存，用 `playbackRate` 精调音准）、竹笛（正弦加泛音、气声、缓起颤音）、波鼓（大/中/轻敲/细点四种）、低频长音，合成混响作为发送总线。
- 旋律在五声音阶内随机游走，40% 概率复用上一小节的动机并微调，每四小节收束到主音。
- 四个场景：菜单、战斗准备、波次进行、结算。胜利、失败短旋律播放时 BGM 自动压低再恢复。
- 首次点击、触摸或按键后解锁；页面切后台自动挂起，回前台恢复；关闭音乐后调度器停止。

**P3 打磨**

- 五个主题（初墨、风林、火山、玄冰、终焉；征服模式按关卡 ID 前缀对应）各有根音、调式、速度偏移、笛与鼓的倾向、混响量。
- 战斗强度由"场上敌人数 × 60% + 波次进度 × 40%"决定，影响速度（最多加 16 BPM）、鼓点密度、旋律密度和强拍回音。

## 关键实现

- 场景由导演器每 250ms 读取现有界面状态（`#main-menu` 是否显示、`gameInstance`/`conquestGame` 的 `gameEnded`、`waveInProgress`）推断，没有在各处场景切换里逐一埋点，对原有流程代码侵入很小。
- 胜利、失败音效挂在 `InkUI.setModalScene`，普通模式与征服模式共用；拒绝音挂在提示框的 `warning` 分支，天然带 900ms 去重。
- 总线增益在 `applyGains` 统一计算，音效基准 0.6、音乐基准 0.5，再乘各自音量。

## 测试 / 验证结果

- `npm test` 全部通过，包含新增的 `test:audio` 与 600 行检查。新增文件最大 543 行。
- `tests/test-audio.js` 用假 `AudioContext` 在 Node 中验证：13 个音效已注册、系别与体型映射、冷却与发声上限、设置持久化与重新加载、不支持 Web Audio 时静默、BGM 调度出古筝/竹笛/鼓、场景与主题切换、长时间挂起后不补播、音乐开关启停、导演器对菜单、塔防、征服、结算的判断。
- 在应用内浏览器实际加载（`localhost`）：无控制台报错；用 `AnalyserNode` 测得菜单 BGM 平均 RMS 约 0.019、峰值约 0.10，战斗 BGM 平均 RMS 约 0.023，所有 13 个短音效均有输出且峰值小于 0.15，没有削波。据此把鼓点音量下调约 40%，攻击音和界面点击音上调，使攻击音不被鼓点淹没。
- 五个主题在真实时钟下逐一切换，速度和鼓点各不相同，无异常。
- 812×375 横屏手机尺寸下，设置页的返回按钮仍在屏内，战斗 HUD 的"音效 · 开""音乐 · 开"并排放得下。

## 未解决问题

- **没有听过实际声音。** 以上只能证明技术上出声、不削波、逻辑正确。古筝、竹笛的音色，旋律是否顺耳，BGM 与音效的音量配比，都需要你试听后调整。可调的位置：`audio-bgm.js` 的 `THEMES`、`SCENES`（速度、密度、笛与鼓的概率），`audio.js` 顶部的 `SFX_BASE`、`BGM_BASE`。
- 未在真实 iOS、Android 设备上验证：自动播放解锁、省电模式、蓝牙耳机延迟、长时间运行的发热与耗电。
- 验证环境把页面判为"后台"（`document.hidden`），`requestAnimationFrame` 不运行，所以没有端到端观察到真实战斗中的攻击音密度，只是单独触发各音效测量。
- `npm run test:balance` 仍输出"需要进一步调整"，但退出码为 0，因此 `npm test` 看起来是通过的。这是本任务之前就存在的情况，本次未改动。

## 后续建议

1. 先在手机上完整玩一关，重点听：BGM 是否太响或太单调、战斗中攻击音是否刺耳、鼓点是否过密，把感受告诉我，再微调参数。
2. 若觉得合成音色不够好，可补入少量免版权的古筝或竹笛采样（几十 KB 的 ogg），与现有合成混用。
3. 战斗强度目前只看敌人数和波次进度，可加入"核心受伤"作为紧张度来源。
4. 把 `test:balance` 改为在不达标时返回非 0 退出码，避免测试假通过。
