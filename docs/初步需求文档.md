# 《墨守成规》初步需求文档

版本：V0.1
日期：2026-04-21
定位：项目级初稿

## 1. 目标

本需求文档用于描述《墨守成规》整个项目的下一阶段规划，重点围绕以下方向展开：

- 融合系统
- 关卡内容
- 数值平衡

文档目标不是一次性定稿，而是作为后续持续补充和细化的起点。

## 2. 面向对象

这份文档主要给项目开发者自己使用，也可作为后续 AI 代理继续执行任务时的基础输入。

## 3. 当前优先级

当前优先级为“正式版规划”，但实施时按阶段推进，先保证核心体验清晰，再逐步扩展内容。

### 3.1 优先事项

1. 融合系统体验更完整，规则更清晰。
2. 关卡内容更合理，整体流程更顺。
3. 数值平衡更稳定，避免前后期体验断层。

## 4. 需求范围

### 4.1 需要做的内容

- 完善融合相关规则与体验。
- 继续补充或调整关卡设计。
- 调整炮塔、敌人、奖励和节奏等平衡项。
- 让玩家能够完整通关并感知到成长曲线。

### 4.2 暂不考虑的内容

- 美术重做。
- 底层逻辑大改。
- 引入构建工具或复杂工程化流程。

## 5. 约束条件

- 保持当前纯 HTML5 Canvas + JavaScript 的实现方式。
- 不引入构建工具，除非后续明确提出。
- 保持项目可直接通过静态服务器运行。
- 需求修改应尽量服务于“能通关、好理解、好平衡”的目标。

## 6. 核心需求

### 6.1 融合系统

- 融合规则需要足够清晰，玩家能理解如何组合。
- 融合结果应有明确收益，避免“看起来厉害但实际无价值”。
- 融合与路径占位、放置条件之间的关系要一致。

### 6.2 关卡设计

- 关卡之间要有递进感。
- 关卡应配合新炮塔或新机制逐步开放。
- 关卡难度需要和资源获取、敌人强度保持一致。

### 6.3 数值平衡

- 保证战斗节奏稳定，不出现明显前期过难或后期失衡。
- 炮塔、敌人、融合收益之间要形成合理闭环。
- 允许通过测试脚本或实际试玩验证平衡变化。

## 7. 验收标准

以下条件可视为本阶段初步达成：

- 玩家可以完成一局完整流程并通关。
- 融合系统的规则和收益能被正常理解和使用。
- 关卡推进与敌人强度有明确层次。
- 数值调整后不会明显破坏原有节奏。
- 文档可以继续作为后续细化需求的基础。

## 8. 排除项

当前阶段不优先处理以下内容：

- 美术风格重构。
- 大规模底层重写。
- 构建链、打包流程、复杂工程化改造。

## 9. 待确认问题

以下内容后续可以继续补充：

- 是否要新增炮塔或敌人类型。
- 是否要调整当前关卡数量或顺序。
- 融合系统是否需要更明确的教学或提示。
- 数值平衡的优先级是“更简单”还是“更有策略深度”。
