## 1. 游戏概述 (Game Overview)

### 1.1 游戏名称 (Game Title)

**正式名称：《墨守成规》**

**名称寓意：**

- **墨守**：以"墨"（黑）代表游戏的纯黑白文字风格，同时谐音"墨守"意为坚守
- **成规**：谐音"城归"，寓意守护城池、让敌人归去
- 整体传达：在黑白文字世界中，坚守阵地，守护核心

**备选名称：**
| 名称 | 寓意 |
|------|------|
| 《字守》 | 简洁明了，强调"文字守护"的核心玩法 |
| 《文字塔防》 | 直接描述游戏类型，易于理解传播 |
| 《墨战》 | 强调黑白风格与战斗主题 |

### 1.2 游戏类型 (Game Genre)

**固定路径、关卡式塔防游戏**

- 玩家无法改变敌人的移动路径
- 关卡逐级解锁，难度递进
- 炮塔放置在路径两侧的固定网格区域

### 1.3 核心玩法循环 (Core Gameplay Loop)

```
┌─────────────────────────────────────────────────────────────┐
│                      核心玩法循环                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    ┌──────────┐    ┌──────────┐    ┌──────────┐            │
│    │  观察波次  │───▶│  布置炮塔  │───▶│  战斗阶段  │            │
│    └──────────┘    └──────────┘    └──────────┘            │
│         ▲                               │                  │
│         │                               ▼                  │
│    ┌──────────┐                   ┌──────────┐            │
│    │  升级/调整 │◀─────────────────│  获得资源  │            │
│    └──────────┘                   └──────────┘            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**详细流程：**

1. **开局准备**：玩家获得初始资源（金币），查看当前波次敌人预览
2. **策略布置**：在路径旁网格区域放置文字炮塔
3. **战斗执行**：敌人沿固定路径移动，炮塔自动攻击范围内敌人
4. **波次结算**：击败敌人获得金币，波次间可调整/升级炮塔
5. **关卡判定**：击败所有波次则胜利，核心被摧毁则失败

### 1.5 独特卖点 (Unique Selling Points)

| 卖点               | 描述                                                           |
| ------------------ | -------------------------------------------------------------- |
| **纯文字美术风格** | 所有游戏元素（炮塔、敌人、特效）均由汉字构成，极具辨识度       |
| **黑白画面**       | 极简视觉风格，突出文字的艺术性，降低美术资源成本               |
| **网格化放置**     | 虽路径非网格，但炮塔放置区域为网格化，简化操作同时保留策略深度 |
| **五行主题炮塔**   | 火/水/山/木/金/土六种炮塔，各具特色，形成完整策略体系          |
| **文字动态效果**   | 炮塔攻击、敌人死亡等通过文字的旋转、缩放、闪烁表现             |

## 3. 核心玩法与机制 (Core Gameplay & Mechanics)

### 3.1 关卡设计 (Level Design)

#### 3.1.1 路径布局原则

**固定路径特征：**

```
示例关卡布局：

┌─────────────────────────────────────┐
│  [G] [G] [G] [G] [G] [G] [G] [G]    │
│  [G]      入口                      │
│  [G]        ↓                       │
│  [G]  ┌─────────┐                   │
│  [G]  │         │                   │
│  [G]  │    ┌────┴───┐               │
│  [G]  │    │        │               │
│  [G]  │    │   ┌────┴───┐          │
│  [G]  │    │   │   ★    │          │
│  [G]  │    │   │ 核心   │          │
│  [G]  └────┴───┴────────┘          │
│  [G] [G] [G] [G] [G] [G] [G] [G]    │
└─────────────────────────────────────┘

[G] = 可放置炮塔的网格区域
★  = 核心目标
```

**路径设计规则：**

| 规则       | 说明                                        |
| ---------- | ------------------------------------------- |
| **连续性** | 路径必须从入口连续到核心，无断裂            |
| **转弯点** | 每个关卡至少2-3个转弯，增加策略性           |
| **长度**   | 路径格子数 = 关卡编号 × 10 + 20（基础长度） |
| **宽度**   | 路径宽度固定为1格                           |

**路径形状类型：**

| 类型   | 描述             | 适用关卡 |
| ------ | ---------------- | -------- |
| 直线型 | 最简单，少量转弯 | 第1关    |
| S型    | 蛇形弯曲         | 第2-3关  |
| 螺旋型 | 向内盘旋         | 第4关    |
| 分支型 | 多条路径汇合     | 第5关+   |

#### 3.1.2 中心核心设定

**核心属性：**

| 属性   | 数值     | 说明                 |
| ------ | -------- | -------------------- |
| 生命值 | 20       | 默认值，可随关卡调整 |
| 位置   | 关卡中心 | 敌人终点             |
| 防御   | 无       | 无法攻击，纯防守目标 |

**失败条件：**

- 核心生命值 ≤ 0

**视觉表现：**

```
    ★
   核心
  ═════
```

#### 3.1.3 怪物波次机制

**波次结构：**

```
波次 = {
  预警时间: 5秒,      // 波次开始前的准备时间
  敌人队列: [...],    // 敌人生成序列
  间隔: 1-3秒         // 敌人间隔生成时间
}
```

**波次数量规则：**

| 关卡  | 波次数量 | 每波敌人数量 |
| ----- | -------- | ------------ |
| 第1关 | 3波      | 3-5          |
| 第2关 | 4波      | 4-6          |
| 第3关 | 4波      | 5-7          |
| 第4关 | 5波      | 6-8          |
| 第5关 | 5波      | 8-10         |

### 3.2 防御塔放置机制 (Tower Placement Mechanics)

#### 3.2.1 网格布局

**放置区域规则：**

```
横截面示意：

[G][G][G][G]   <- 上方放置区（4行）
════════════   <- 敌人路径
[G][G][G][G]   <- 下方放置区（4行）
```

**网格属性：**

| 属性       | 值                 | 说明         |
| ---------- | ------------------ | ------------ |
| 网格大小   | 40×40像素          | 单位格子     |
| 放置区宽度 | 路径两侧各4格      | 保证攻击覆盖 |
| 状态标识   | 空闲/已占用/不可用 | 视觉区分     |

#### 3.2.2 放置限制

| 限制条件   | 说明                           |
| ---------- | ------------------------------ |
| **费用**   | 放置炮塔需消耗对应金币         |
| **位置**   | 只能放置在路径旁的网格区域     |
| **唯一性** | 每个格子只能放置一个炮塔       |
| **地形**   | 山字炮塔可放置在路径上（特殊） |

### 3.3 核心防御目标 (Core Defense Objective)

**核心机制：**

```
┌─────────────────────────────────────┐
│              核心状态面板             │
├─────────────────────────────────────┤
│                                     │
│         ★ 核心                       │
│        ═════                         │
│   生命值: ████████░░ 16/20          │
│                                     │
└─────────────────────────────────────┘
```

**被攻击逻辑：**

1. 敌人到达核心位置
2. 敌人对核心造成伤害 = 敌人伤害值
3. 核心生命值减少
4. 敌人消失（已造成伤害）

### 3.4 胜利/失败条件 (Win/Loss Conditions)

#### 胜利条件

```
胜利判定:
  IF 所有波次敌人已消灭 AND 核心生命值 > 0:
    触发胜利
    显示胜利结算界面
    解锁下一关卡
    发放通关奖励
```

#### 失败条件

| 失败类型 | 触发条件                    | 结果             |
| -------- | --------------------------- | ---------------- |
| 核心摧毁 | 核心生命值 ≤ 0              | 立即失败         |
| 资源耗尽 | 金币为0 且 无法消灭剩余敌人 | 等待敌人攻击核心 |

## 4. 游戏视觉与风格 (Game Visuals & Style)

### 4.1 美术风格 (Art Style)

#### 4.1.1 纯文字表现原则

**核心原则：所有游戏元素均由汉字构成，无图像资源**

| 元素类型 | 表现方式                      |
| -------- | ----------------------------- |
| 炮塔     | 单个汉字（火/水/山/木/金/土） |
| 敌人     | 单个汉字（尸/鬼/甲/分）       |
| 核心     | 星号+汉字"核心"               |
| 路径     | 连续的下划线或点号            |
| 特效     | 动态文字（旋转/缩放/闪烁）    |

#### 4.1.2 黑白画面风格

**配色方案：**

| 元素      | 颜色    | 用途            |
| --------- | ------- | --------------- |
| 背景      | #0a0a0a | 深黑，营造氛围  |
| 主要文字  | #ffffff | 白色，主要元素  |
| 次要文字  | #888888 | 灰色，辅助信息  |
| 高亮/选中 | #ffff00 | 黄色，交互反馈  |
| 危险/伤害 | #ff0000 | 红色，敌人/警告 |
| 治愈/正面 | #00ff00 | 绿色，恢复/增益 |

**视觉层次：**

```
亮度层次：
255 (白色) ─── 主要元素（炮塔、核心）
200 (浅灰) ─── 次要元素（路径、网格）
128 (中灰) ─── 背景元素
 64 (深灰) ─── 阴影效果
 10 (黑色) ─── 背景底色
```

#### 4.1.3 文字动态效果

**攻击效果：**

| 炮塔类型 | 攻击动画           |
| -------- | ------------------ |
| 火       | "火"字旋转飞向敌人 |
| 水       | "水"字波纹扩散     |
| 山       | "山"字震动         |
| 木       | "木"字快速连射     |
| 金       | "金"字直线穿透     |
| 土       | "土"字范围震动     |

**状态效果：**

| 状态       | 动画效果          |
| ---------- | ----------------- |
| 炮塔攻击中 | 文字轻微缩放脉动  |
| 敌人受伤   | 文字闪烁红色      |
| 敌人死亡   | 文字缩小消失      |
| 敌人减速   | 文字颜色变浅      |
| 核心受伤   | 文字震动+红色闪烁 |

#### 5.1.2 放置规则 (Placement Rules)

**通用规则：**

| 规则     | 说明                       |
| -------- | -------------------------- |
| 放置区域 | 只能放置在路径旁的网格区域 |
| 山字炮塔 | 例外：可放置在路径上       |
| 唯一性   | 每格只能放置一个炮塔       |
| 费用消耗 | 放置时扣除对应金币         |

**放置流程：**

```
1. 点击底部炮塔栏选择炮塔类型
2. 鼠标移动到网格区域预览放置效果
3. 点击确认放置
4. 扣除费用，炮塔出现
```

**出售机制：**

| 规则     | 数值           |
| -------- | -------------- |
| 出售价格 | 原价 × 70%     |
| 升级投入 | 不计入出售价格 |

#### 5.1.3 升级机制 (Upgrade Mechanics)

**升级界面：**

```
┌─────────────────────┐
│        火 Lv.1       │
│    ─────────────     │
```

#### 5.2.2 移动路径 (Movement Paths)

**移动规则：**

```
1. 敌人生成于入口位置
2. 沿预设路径移动（路径为格子序列）
3. 每秒移动速度格数 = 基础速度 × (1 - 减速效果)
4. 到达路径终点 → 攻击核心
```

**阻挡逻辑（山字炮塔）：**

```
IF 敌人.类型 != 鬼:  // 鬼可以飞行绕过
  IF 路径上存在山字炮塔:
    敌人停止移动
    山字炮塔.生命值 -= 敌人.伤害
    等待1秒
    IF 山字炮塔.生命值 <= 0:
      山字炮塔.销毁()
      敌人继续移动
    ELSE:
      敌人继续等待
```
