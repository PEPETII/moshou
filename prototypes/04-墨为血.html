墨为血

方案四 攻击「建塔防守 · 波次进攻」

金币换成「墨」。墨量同时是货币与生命：写字耗墨，敌人不扣核心血，而是擦掉你的笔画——字缺了笔画，就不再是那个字。

点击空白处落字（耗墨 20）；点击受损的字可「蘸墨」修复笔画（耗墨 8）

字的退化链（血条变成了字形完整性）

火三笔俱全→火缺一笔·伤害减半→火缺两笔·近乎失效→人不再是「火」

已放置的字会随时间干涸（浓度下降），浓墨写的字更强、但会向邻格晕染污染相邻字的浓度——写多必枯，这是主动的风险权衡，而不是数值升级。

为什么它差异化最深

这是六个方案里唯一把美术语言直接变成规则语言的方案：水墨的「浓淡干湿」从装饰变成玩法。别的水墨游戏在画墨，这个游戏在用墨。

实现上需要新增墨资源层替换 js/game.js 的金币逻辑，并让 js/inkRenderer.js 增加"扩散 / 干涸 / 残留"三种字状态渲染（现有墨晕、飞白、拖影可复用）。

最大风险是平衡：两个资源耦合会让数值难度指数上升。项目已有 npm run test:balance 基线，本方案的重调必须一次性完成，反复改会拖垮基线。
