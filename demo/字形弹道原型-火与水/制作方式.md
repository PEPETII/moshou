# 制作方式：字形弹道原型（火与水）

本文记录这个原型是怎么设计、怎么实现、怎么调出手感的，以及如何按同一套方法做新的字塔。读完应该能独立做出第三座塔。

---

## 1. 设计目标

要验证两件事：

1. **可读**：只看画面，能不能一眼认出每一招来自字的哪一笔；
2. **爽**：这种表现，加上足够的敌人规模和打击反馈，能不能带来爽感。

旧版 demo（见 `screenshots/00-旧版demo对照.png`）失败在三处：字只有约 40px，弹丸几乎看不见；映射太抽象（火的四笔各射一粒火星，看不出是"火"）；没有命中和击杀反馈。新版针对性地定了三条原则。

### 原则一：飞出去的就是那一笔

弹道不是"看起来像"笔画，而是**直接用那一笔的笔画数据去画**。

- 火星 = 「火」的左点或右点本身，旋转到飞行方向；
- 水箭 = 「水」的竖钩本身，沿瞄准方向拉长；
- 焚 = 整个「火」字；潮 = 「水」的横撇、撇、捺三笔。

### 原则二：用掉的笔画就是冷却

笔画飞出去后从塔身消失，再按笔顺一笔一笔写回来。玩家看塔身缺了哪几笔，就知道哪一招还没好，不需要额外的冷却条。

### 原则三：普攻克制，张扬留给大招

普攻小而快（点、竖），大招大而慢（整字、三笔），中间用一个**圆相墨圈**作蓄力条。这样画面有节奏：平时细碎地打，蓄满后一声巨响。

### 一招的拆解模板

每座字塔都按这个模板设计：

| 项 | 火 | 水 |
| --- | --- | --- |
| 普攻用哪几笔 | 左点、右点（轮流） | 竖钩 |
| 普攻的形与义 | 点 → 火星，追踪、灼烧 | 竖 → 水柱，贯穿；钩 → 水花 |
| 大招用哪几笔 | 整字 | 横撇、撇、捺 |
| 大招的形与义 | 整字掷出 → 落地成火字焦土 | 三笔张开 → 浪头倒卷 |
| 用掉后塔身的样子 | 缺一点 / 整字消失后重写 | 缺竖 / 只剩一竖 |
| 这一招在战术上的职责 | 输出、收割 | 控场、把敌人送回输出区 |

## 2. 文件结构与运行方式

纯静态页面，没有构建步骤，脚本按顺序加载、共享全局对象：

| 加载顺序 | 文件 | 全局对象 | 职责 |
| --- | --- | --- | --- |
| 1 | `js/data.js` | `STAGE`、`GLYPHS`、`TOWER_CFG`、`ENEMY_TYPES`、`DENSITY`、`PATH_POINTS`、`COLORS` | 笔画数据与全部参数 |
| 2 | `js/brush.js` | `Brush` | 毛笔渲染与笔画几何查询 |
| 3 | `js/fx.js` | `FX`、`rnd` | 粒子、数字、震屏、顿帧、墨渍、连斩 |
| 4 | `js/world.js` | `World` | 路径、敌人、伤害结算 |
| 5 | `js/towers.js` | `Towers` | 塔的通用逻辑与绘制 |
| 6 | `js/fire.js` | `FireTower` | 火星、焚 |
| 7 | `js/water.js` | `WaterTower` | 水箭、潮 |
| 8 | `js/app.js` | （立即执行函数） | 纸面、主循环、输入、控件、拆解图 |

舞台逻辑尺寸固定为 960×540，画布按 `devicePixelRatio`（最高 2）放大，CSS 等比缩放到容器宽度。所有坐标、速度、半径都用舞台像素。

每帧的绘制顺序：

```
宣纸底（离屏，含路径） → 墨渍层（离屏，会慢慢褪色） → 地面效果（焚后火字）
→ 敌人 → 塔 → 弹道与大招 → 粒子、碎字 → 伤害数字 → 连斩与朱印（不随震屏晃动）
```

## 3. 核心技术

### 3.1 笔画数据格式

每个字由 3～4 条折线组成，坐标在 0..100 的字身方格内（y 向下），`w` 是三段笔宽 `[起笔, 行笔, 收笔]`：

```js
fire: {
  char: '火',
  strokes: [
    { id: 'dotL', name: '左点', pts: [[21, 35], [26, 42], [31, 52]], w: [7, 10, 5] },
    { id: 'dotR', name: '右点', pts: [[81, 29], [75, 39], [67, 50]], w: [6, 9, 4] },
    { id: 'pie',  name: '撇',   pts: [[51, 8], [52, 28], [50, 50], [39, 71], [15, 92]], w: [10, 9, 2] },
    { id: 'na',   name: '捺',   pts: [[50, 48], [59, 62], [73, 79], [92, 93]], w: [4, 8, 12] },
  ],
},
```

- 数组顺序就是笔顺，重写时按这个顺序写；
- 撇的收笔宽度给小值（2）让它出锋，捺的收笔给大值（12）做出捺脚；
- 不用字体渲染塔身：一是不受用户机器字体影响，二是笔画自带几何信息（起点、走向、长度），弹道直接从这里取。

**手绘笔画的方法**：在 100×100 的方格纸上（或把楷体字截图放大后描）定出每笔的 3～6 个关键点。转折处多放一个点，平滑后才不会圆得太厉害。一个字调到满意大约需要半天。

### 3.2 毛笔渲染（`brush.js`）

1. **平滑**：折线经 Catmull-Rom 插值，每段细分 12 个点，计算每点的累计长度 `t`（0..1）、切线和法线。结果按笔画缓存，只算一次。
2. **笔压曲线**：前半段从起笔宽过渡到行笔宽，后半段过渡到收笔宽，用 smoothstep 插值；再在 `t≈0.05` 处叠加一个高斯形的"顿笔"：

   ```js
   const base = t < 0.5 ? w0 + (w1 - w0) * smooth(t / 0.5) : w1 + (w2 - w1) * smooth((t - 0.5) / 0.5);
   const press = w0 * 0.28 * Math.exp(-(((t - 0.05) / 0.06) ** 2)); // 起笔顿笔
   ```

3. **轮廓**：每个采样点沿法线向两侧各偏移半个笔宽，左边正序、右边逆序连成多边形填充，起笔处再补一个圆头。
4. **墨晕**：填充前先用同色、14% 透明度、3.2 单位线宽描一圈轮廓，模拟墨在纸上的晕开。
5. **飞白**：在笔画后半段用纸色画 3 条细线。线的位置由笔画 `id` 算出的种子决定，所以不会逐帧闪烁。
6. **书写中**：`progress < 1` 时只画到 `progress` 处，并在笔尖加一团略大的湿墨，看起来像正在被写。

接口：

| 函数 | 作用 |
| --- | --- |
| `Brush.drawStroke(ctx, stroke, { x, y, size, rot, progress, color, alpha, glow })` | 画一笔，`(x, y)` 是字身中心 |
| `Brush.drawGlyph(ctx, glyph, opts, styleFn)` | 画整字，`styleFn(i)` 可逐笔覆盖参数或隐藏 |
| `Brush.pointAt(stroke, t)` | 取笔画上某处的字身坐标与切线 |
| `Brush.toWorld(p, { x, y, size, rot })` | 字身坐标转舞台坐标 |
| `Brush.drawRing(...)` | 圆相蓄力环 |
| `Brush.drawTrail(...)` | 从细到粗的拖尾 |

### 3.3 "飞出去的就是那一笔"怎么实现

**火星**：把「点」的笔画中点移到原点，再旋转到速度方向。旋转量是"速度角减去这一笔自身的走向角"，保证点的笔锋始终朝前：

```js
const strokeAng = Math.atan2(tail.y - head.y, tail.x - head.x);   // 这一点本来的走向
ctx.translate(s.x, s.y);
ctx.rotate(Math.atan2(s.vy, s.vx) - strokeAng);                    // 转到飞行方向
Brush.drawStroke(ctx, stroke, { x: (50 - mid.x) * k, y: (50 - mid.y) * k, size, color: COLORS.fire, glow: COLORS.fireGlow });
```

火星初速沿"点离开塔心的方向、略偏上"，然后每帧把速度向目标方向插值（转向系数 `dt * 7`），速度从 280 加到 520，形成先弹出、再拐弯追踪的弧线。

**水箭**：对竖钩做**非均匀缩放**：宽度保持塔身比例，长度拉到目标距离。竖钩在字身里从 y=5 到 y=90，约 85 个单位：

```js
ctx.translate(s.x, s.y);
ctx.rotate(s.aim - Math.PI / 2);                 // 让字身的"向下"对准目标
ctx.scale(widthK * layer.w, s.len / 85);         // 横向保持笔宽，纵向拉到目标距离
ctx.translate(-51, -5);                           // 竖钩的起笔对齐塔心
Brush.drawStroke(ctx, shu, { x: 50, y: 50, size: 100, progress: prog, ... });
```

前 0.09 秒 `progress` 从 0 到 1，看起来是竖从塔身里"写"出去；写满时结算命中，之后 0.29 秒变细淡出。底下再垫一层 2.2 倍宽的浅蓝作为水汽。钩被拉长后正好落在末端，配合一簇向后上方甩出的水滴，就成了水花。

**焚**：整字沿抛物线飞向敌群最密处，缩放系数 `1 + 0.75·sin(πk) + 0.55k`，所以飞到最高点时最大，落地时仍比塔身大 1.55 倍，带着光晕和火星尾迹。落点选取方式：沿路径每 16px 取一个点，统计半径内的敌人权重（巨尸算 4），只在塔射程 1.15 倍以内、且离入口足够远的路段里选。

**潮**：只画「水」的第 2～4 笔，字顶朝向浪的前进方向（`rot = 前进角 + π/2`），三笔就张成一个破浪的形状；身后沿路径画一串逐渐变淡的水痕圆，前沿持续喷出水滴。

### 3.4 笔画消耗与重写

每座塔为每一笔维护 `{ prog, delay, rate }`：

```js
consume(t, i, delay, dur) {        // 用掉第 i 笔：delay 秒后，用 dur 秒写回
  const s = t.strokes[i];
  s.prog = 0; s.delay = delay; s.rate = 1 / dur;
}
```

| 招式 | 消耗 | 写回节奏 |
| --- | --- | --- |
| 火星 | 当前那一点 | 0.05 秒后，0.32 秒写回 |
| 焚 | 全部 4 笔 | 落地后按笔顺依次写回，共 1.4 秒 |
| 水箭 | 竖钩 | 0.3 秒后，0.5 秒写回 |
| 潮 | 横撇、撇、捺 | 浪走到 70% 时开始，依次写回，共 1.2 秒 |

普攻只在对应笔画写满时才能发射，所以"缺笔"既是表现也是真实的冷却。正在书写的笔画用元素色画，写完恢复墨色；蓄满时整字变成元素色并发光。

### 3.5 路径里程系统（击退与倒卷的关键）

敌人位置不存坐标，而是存**路径里程 `s`**（从入口沿路走了多少像素），每帧用 `World.pointAt(s)` 换算坐标，再加一个垂直于路径的随机偏移 `lane`，避免排成一条线。

好处是：

- **击退**就是 `e.s -= 距离`，无论在直道还是拐角，都会沿路后退；
- **潮**的浪头也是一个里程值 `wave.s`，每帧减小。被卷入的敌人把自己的 `s` 锁在浪头后面 `carryOff`（8～48px 随机）处，所以浪能带着一群敌人自然转弯：

```js
s.s = Math.max(80, s.s - cfg.waveSpeed * dt);   // 浪头倒卷，不推出画面
for (const e of World.enemies) {
  if (e.dead || e.carried) continue;
  if (e.s >= s.s - 4 && e.s <= prev + 50 && e.s <= s.s0 + 40) {   // 浪扫过的区间
    e.carried = s; e.carryOff = rnd(8, 48); s.caught.push(e);
  }
}
for (const e of s.caught) if (!e.dead) e.s = s.s + e.carryOff;
```

### 3.6 打击反馈清单

| 反馈 | 实现 | 数值 |
| --- | --- | --- |
| 伤害数字 | 书法字体、纸色描边、上飘减速淡出；暴击放大并加「!」 | 普通 19px，暴击 34px，灼烧 15px |
| 灼烧数字合并 | 灼烧伤害每 0.45 秒合并显示一次，避免数字刷屏 | — |
| 顿帧 | `FX.hitstop` 期间主循环时间 × 0.06 | 焚落地 90ms、潮落下 70ms、巨尸死 60ms、潮起 50ms、暴击 25ms |
| 震屏 | 随机平移，按 40/秒衰减，上限 22 | 焚 15、潮落下 9、巨尸死 7、暴击 2.5 |
| 碎字 | 敌字沿随机斜线裁成两半，各自旋转飞散、受重力下落 | 0.7 秒 |
| 墨渍 | 击杀处在离屏墨渍层点出不规则墨团与飞溅点；墨渍层每 0.5 秒整体褪 3.5% | 火杀偏焦褐，水杀偏靛青 |
| 焦痕 | 焚的火字熄灭后，以 22% 透明度印在墨渍层上 | — |
| 冲击环 | 扩张并变细的圆环 | 焚 1.25 倍爆炸半径 |
| 连斩 | 1.6 秒内连续击杀累计，数字弹跳；25 以上转朱色 | — |
| 朱印 | 连斩 25 / 60 / 120 时盖「一气呵成 / 势如破竹 / 所向披靡」，四字两列，按印章习惯从右列读起 | 1.4 秒 |

「打击反馈」开关关掉的是数字、顿帧、震屏、碎字、墨渍和连斩。系统开启「减少动态效果」时，自动关闭震屏。

### 3.7 圆相蓄力

蓄力条画成禅画里的"圆相"：一笔写成、起收笔细、中段粗，并留一个缺口。蓄力值 0..1 对应写出的弧长（最多 93% 圈）。射程内有敌人时按秒蓄力，命中再额外加：

- 火：每秒 0.12，每发火星命中 +0.012；
- 水：每秒 0.08，每发水箭每命中一个 +0.02，**单发最多按 3 个算**（原因见 4.2 第 3 条）。

满蓄后圆相变元素色并脉动，塔右侧出现「点塔 · 焚 / 潮」提示。

### 3.8 对照模式

`Towers.mode = 'plain'` 时，机制和数值完全不变，只把表现换成常见塔防的样子：方块里印字、灰色圆点子弹、细线水箭、灰色圆形爆炸、灰色圆圈代替浪头，命中只有几个灰点。这样对比时只改变一个变量，能看清字形表现本身贡献了多少。

### 4.2 调参中踩过的坑

这几条比具体数值更重要，做正式游戏时同样适用：

1. **单塔太强，另一座塔就没活干。** 火最初放在第一段路，敌人全死在第一段路，水一直闲着。爽感要求每座塔都有事做，所以敌人总血量要明显超过任一座塔单独的输出。
2. **控场推到空地上只会拖节奏。** 水放在入口段时，潮把敌人推回入口，那里没有火，结果只是拖时间。改成火守上游、水守下游后，潮把敌人卷回火的射程，"卷回去烧"才是爽点。**控场塔的价值取决于它把敌人送到哪里**，这本身可以做成摆位玩法。
3. **按命中数充能，敌人扎堆时会失控。** 水箭穿透整排，每命中一个就加充能。敌人被潮压成一团后，一发水箭命中 20 个，潮几乎连放，敌人被永远卡在入口。解决办法是单发充能按最多 3 个命中计算。
4. **持续推退加减速，会把敌人卡死。** 水箭最初推退 20px、减速 38%：敌人每秒前进约 28px，却被推回约 24px，几乎原地不动。降到推退 8px、减速 30% 后，水才回到"拖慢"而不是"冻结"的角色。
5. **大招落点要限制在塔附近。** 最初按全图找最密处，焚常常砸进画面边缘的出生口，炸开一半在画外。改为只在塔射程 1.15 倍内、离入口 150px 以后的路段里选。

## 5. 如何新增一个字塔（以「山」为例）

### 第一步：拆字定招

| 项 | 山 |
| --- | --- |
| 笔画 | 竖（中峰）、竖折（左峰与底）、竖（右峰） |
| 普攻 | 中峰竖 → 从天而降砸在路上（单体、眩晕） |
| 大招 | 三峰拔地而起，在路上立起一座山形墙挡住敌人，撞上反伤；墙消失前塔身只剩底 |
| 职责 | 阻挡，和火配合：把敌人挡在火字焦土上 |

判断标准：**不看说明，能不能从画面认出是哪一笔**。认不出就换一笔或换一种形态。

### 第二步：写笔画数据

在 `GLYPHS` 里加 `mountain`，在 `TOWER_CFG` 里加参数（位置、射程、普攻间隔与伤害、蓄力速度、大招参数、重写时长）。

### 第三步：写招式文件

新建 `js/mountain.js`，导出与 `FireTower` 相同的五个方法：

```js
const MountainTower = {
  update(t, dt) {},        // 普攻：检查笔画是否写满 → 找目标 → Towers.consume → 推入 Towers.shots
  cast(t) {},              // 大招：无合适目标返回 false；否则消耗笔画、推入大招对象，返回 true
  updateShot(s, dt) {},    // 推进自己的弹道/大招对象，结束时设 s.done = true
  drawShot(ctx, s) {},     // 画自己的弹道；Towers.mode === 'plain' 时画普通版本
};
```

画弹道时继续遵守原则一：用 `Brush.drawStroke` 画对应那一笔，借助 `rot`、`ctx.scale` 改变朝向和长度，不要另外画一个"像"的形状。

### 第四步：接入调度

`towers.js` 里目前按 `type === 'fire' ? FireTower : WaterTower` 分派。新增第三座塔时，改成一张表：

```js
const TOWER_IMPL = { fire: FireTower, water: WaterTower, mountain: MountainTower };
```

再在 `index.html` 的脚本列表里、`towers.js` 之后加上 `js/mountain.js`，在「出场」控件里加选项。

### 第五步：调参与验收

1. 关掉说明看 30 秒，能否说出普攻和大招；
2. 切「普通弹道」对比，确认字形表现确实加分；
3. 看自动模式下各塔蓄力是否都在循环，有没有哪座塔长期闲着（参照 4.2）；
4. 跑 `tools/smoke-test.js` 确认零报错。

## 6. 接入正式游戏的建议

- **塔身尺寸**：正式游戏格子是 48px，而笔画至少要 72px 才清楚（本原型用 92px）。可以放大塔身让它溢出格子，或让核心字塔占 2×2 格。
- **范围**：只给 6～8 个单字核心塔做，统一规则：一笔做普攻，其余笔画做大招。「心中炎」「如风似真」这类多字塔不逐笔拆，改成几个字依次出手的连招。
- **复用**：`brush.js`、`fx.js` 基本可以直接搬，敌人移动需要改成同样的路径里程方式，击退和"卷回"才自然。
- **画面密度**：七八座塔同时开火会乱。普攻继续保持小而快，大招之间可以加全局间隔，避免同时爆。
- **性能**：本原型最多 140 个敌人加数百个粒子，光晕阴影只用在火字和蓄满的塔上。正式接入时也建议控制阴影模糊的使用范围。

## 7. 验证方式

- 用 Playwright 无头打开页面，强制满蓄，分别截取火星、焚飞行、焚爆炸、焚后火字、潮、普通弹道、整页、手机竖屏（见 `screenshots/`）；
- 自动大招各跑 40 秒统计：「常」档火放焚 4 次、水放潮 3 次，击杀 139；「潮」档火 5 次、水 3 次，击杀 248；漏过均为 0，控制台零报错；
- 已知现象：「常」档下火有时会独自清空上游，水塔会闲十几秒。想让水更忙，可以调高「常」档敌潮密度或尸的血量（见 4.2 第 1 条）；
- 手机 390px 宽度下无横向滚动；
- 所有代码文件不超过 250 行，符合项目 600 行上限。

**尚未验证**：真人手感（顿帧长短、震屏强度、伤害数字密度）需要试玩后再调；断网时的字体回退只确认了能显示，没有做美观调整。
