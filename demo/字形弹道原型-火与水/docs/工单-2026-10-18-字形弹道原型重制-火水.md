# 工单：字形弹道原型重制（火、水）

- 日期：2026-10-18
- 类型：独立玩法原型（不改动正式游戏代码）

## 任务目标

从零重做「字形即弹道」原型，只做「火」「水」两座塔，验证两件事：

1. 只看画面，能否一眼认出每一招来自字的哪一笔；
2. 这种表现，加上足够的敌人密度与打击反馈，能否带来爽感。

## 当前问题 / 背景

`demo/glyph-trajectory-demo.html`（2026-10-17）被判定为效果很差：

- 塔身字只有约 40px，弹丸是几个像素的小点，招式看不清；
- 字形到弹道的映射偏抽象（火的四笔各射一粒火星），看不出"这是火"；
- 敌人是墨团，没有命中、击杀反馈，没有爽感；
- 暗色界面与正式游戏的宣纸浅色风格不一致，说明文字多于画面。

## 涉及文件

全部新增，位于 `prototypes/glyph-v2/`：

- `index.html`：页面、样式、控制条、概念评估
- `js/data.js`：火、水笔画数据，招式与敌人参数，路径
- `js/brush.js`：毛笔笔画渲染（笔压、起笔、飞白、按笔顺书写、圆相蓄力环）
- `js/fx.js`：粒子、伤害数字、震屏、顿帧、墨渍、连斩
- `js/world.js`：路径、敌人、伤害结算
- `js/towers.js`：火塔与水塔的普攻、大招
- `js/app.js`：主循环、输入、控件、HUD、字形拆解图

## 实施步骤

1. 手绘火、水笔画数据，写毛笔渲染器，保证大尺寸下观感；
2. 火：左右两点化作追踪火星（普攻）；整字被掷出、落地炸开、留下火字焦痕（大招「焚」）；
3. 水：竖钩化作贯穿水箭（普攻）；横撇、撇、捺化浪，沿路径倒卷，裹挟敌人后退（大招「潮」）；
4. 塔身被"用掉"的笔画按笔顺重写，重写过程即冷却；
5. 圆相墨圈作蓄力环，蓄满后点塔释放（也可切自动）；
6. 敌潮密度三档、倍速、伤害数字、顿帧、震屏、击杀碎字、墨渍、连斩；
7. 对照开关：字形弹道 ↔ 普通弹道、打击反馈开 ↔ 关，便于分别判断两个因素；
8. 页面下方给出概念评估。

## 风险与注意事项

- 粒子与敌人数量多时的帧率：敌人上限 140，阴影模糊只用于火字；
- 手机宽度下画布等比缩放，触屏点击塔需换算坐标；
- 单个代码文件不超过 600 行；不引入构建工具；
- 不实现火水反应（按需求确认，先做好单塔）。

## 验收标准

- `file://` 直接打开可运行，控制台零报错；
- 关闭说明观察 30 秒，能说出火、水各自的普攻和大招；
- 切换到「普通弹道 + 反馈关」时，观感明显变平淡；
- `npm run check:line-count` 通过。
