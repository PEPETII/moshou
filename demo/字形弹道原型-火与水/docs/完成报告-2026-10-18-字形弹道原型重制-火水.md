## 1. 实际完成内容

从零重做了「字形即弹道」原型，没有沿用 `demo/` 的代码。只做火、水两座塔，每座塔一个普攻、一个大招，招式全部从笔画数据推导：

| 塔 | 笔画 | 招式 | 表现 |
| --- | --- | --- | --- |
| 火 | 左点 · 右点 | 火星（普攻） | 点本身脱离塔身，按速度方向旋转飞出，带火尾追踪；命中叠灼烧；点立刻补写 |
| 火 | 整字 | 焚（大招） | 整个火字被掷出，抛物线上越飞越大，砸进敌群最密处，顿帧、震屏、火星四溅；地上留下烧 3 秒的火字，持续灼烧，熄灭后在纸上留焦痕 |
| 水 | 竖钩 | 水箭（普攻） | 竖钩笔画沿瞄准方向拉长成水柱，贯穿整排敌人，推退、打湿；钩在末端甩成水花 |
| 水 | 横撇 · 撇 · 捺 | 潮（大招） | 三笔离开塔身化作浪头，沿路径倒卷，把卷入的敌人一路推回并眩晕；浪在外面时塔身只剩一竖 |

共通机制：

- **笔画即冷却**：用掉的笔画从塔身消失，再按笔顺写回；
- **圆相蓄力环**：一笔写成的墨圈作蓄力条，满后变色、脉动，点塔或按 Q / W 释放，也可切自动；
- **打击反馈**：书法体伤害数字（暴击放大带「!」）、顿帧、震屏、敌字被斜劈成两半飞散、墨渍逐渐褪去、连斩计数，连斩 25 / 60 / 120 盖朱印「一气呵成 / 势如破竹 / 所向披靡」；
- **对照开关**：「字形弹道 ↔ 普通弹道」只换表现、不换机制与数值；「打击反馈 开 ↔ 关」单独控制反馈，两个因素可以分开感受；
- 敌潮稀 / 常 / 潮三档、1× / 2× 速度、出场火 / 水 / 双塔切换；
- 页面下方有「字 → 招」笔顺拆解图（循环演示笔顺，普攻笔画着色）和概念评估。

## 3. 关键实现

- **笔画轮廓**：折线经 Catmull-Rom 平滑后按笔压曲线向两侧偏移生成多边形填充，起笔处加一个高斯顿笔，收笔逐渐出锋；飞白丝位置按笔画 id 固定，不会逐帧闪烁。
- **飞出去的就是那一笔**：火星直接绘制「点」的笔画数据，并旋转到速度方向；水箭对竖钩做非均匀缩放（宽度不变、长度拉到目标），所以玩家看到的是同一笔从塔身伸出去。
- **潮沿路径倒卷**：敌人位置用路径里程 `s` 表示，浪头的 `s` 逐帧减小，被卷入的敌人 `s` 锁定在浪头之后，因此浪能自然转弯。
- **顿帧**：`FX.hitstop` 期间主循环时间缩放到 0.06，大招落地 90ms、暴击 25ms。

## 4. 测试 / 验证结果

用 Playwright（Chromium）加载 `file://` 页面，截图逐帧核对并抽样统计：

- 控制台零报错（`pageerror` / `console.error` 均为空）；
- 截图确认：火星是飞行中的点画，焚是放大的整字，落地火字、焦痕、水箭竖钩、潮的三笔浪头、塔身缺笔与重写、圆相蓄力环、朱印均按设计呈现；
- 「常」档自动大招运行 30 秒：两塔蓄力都在循环（火、水交替释放），击杀约 126、漏过 0；
- 普通弹道 + 反馈关：塔变成方块字，弹道是灰点和细线，无数字、无震屏，观感明显变平淡；
- 手机宽度 390px：页面无横向滚动，画布等比缩放，控件换行正常；
- `npm run check:line-count` 通过（最大文件仍是既有的 585 行）。

调参中发现并修正的问题：

1. 火塔放在第一段路时，敌人全在第一段路被清空，水塔无事可做；
2. 水在第一段路时，潮把敌人推回入口，火够不着，自动模式下水把火"饿死"；水箭每命中一个敌人都加充能，敌人扎堆时潮几乎连放，把敌人永久卡在入口。最终改为火守上游、水守下游，潮把敌人卷回火的射程；单发水箭的充能封顶 3 个命中。

## 5. 未解决问题

- 只在无头浏览器里验证，手感（顿帧长度、震屏强度、伤害数字密度）需要真人试玩调整；
- 环境中没有 Ma Shan Zheng 字体时，敌人字与数字会退回楷体或系统衬线体；塔身笔画不依赖字体；
- 笔画数据是手绘近似，「水」的横撇转折处偏圆，可再精修；
- 未实现火水反应（按需求，先做好单塔）。

## 6. 后续建议

1. 先找没看过说明的人试玩 30 秒，看能否说出两塔的普攻与大招；再切到「普通弹道」，问哪个更想玩；
2. 若成立，再选 2～3 个单字核心塔（建议山、金、木）按同一规则（一笔普攻、其余笔画大招）扩展；
3. 正式游戏格子为 48px，接入前需决定塔身放大或核心塔占 2×2 格；
4. 「控场把敌人送进输出区」值得做成摆位玩法的核心，而不只是数值配合。
